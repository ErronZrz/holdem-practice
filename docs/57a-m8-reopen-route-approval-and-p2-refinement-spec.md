## 4. 三处反例的代码层根因（**静态阅读所得，不是读数**）

### 4.1 读数（已落盘，直接引用）

| 项 | 读数 | 来源 |
|---|---|---|
| 域二（翻牌面对下注）三档主动率 | `0.363%` / `0.985%` / `0.615%`（tight / aggressive / calling），**在 `16` 个种子块上 `min == max`** | `docs/56i` §7 |

### 4.2 根因 A：主动分支与被动分支**尺度不匹配**

按 `build_distribution`（`backend/app/strategy/mixed_policy.py`）的口径逐项比对：

| 分支 | 权重口径 | 量级上界（按源码取值代入） |
|---|---|---|
| 弃牌 | `max(0, call_threshold − passive_score + 160) × fold_percent`（`130` / `85` / `70`） | `(1000 + 160) × 130 = 150,800` |
| 跟注 | `max(0, passive_score − call_threshold + 160) × call_percent`（`90` / `110` / `150`） | `(1000 + 160) × 150 = 174,000` |
| 主动 | `share × aggression_scale × quality`（`aggression_scale = aggression_percent × 模式百分 / 100`，`aggression_percent` 为 `90` / `140` / `60`） | `1 × 1.61 × 520 ≈ 837` |

`value_quality = max(0, score − value_threshold + 120)`，而 `value_threshold` 按街固定（`600` / `650` / `700` / `740`），故 `quality` 的上界约为 `520`（翻前）。

⇒ **主动项比被动项低约两个数量级**；当 `Δ = call_threshold − passive_score + 160` 接近其上界（面对下注时价格项常把 `call_threshold` 推到 `800+`）时，差距进一步拉大。

**由该口径直接推出的两点**：

1. 在被动项主导的局面上，主动份额会被压到 `1%` 以下 ⇒ 与 `docs/56i` §6 的 `flop-draw` `0.654%` 一致；
2. 风格差异**只**通过 `parameters.*_percent` 与 `size_preferences` 进入，其中主动侧的档比（最大/最小 `140 / 60 = 2.33` 倍）作用在一个不足 `1%` 的份额上 ⇒ 即便把倍率推到极端，也只能产生**零点几个百分点**的档差，而门槛要求 `10` 个百分点。⇒ **`docs/56h` §7 第 4 项的未满足不是调参问题，而是量级问题**。

### 4.3 根因 B：`value_quality == 0` 且 `bluff_quality == 0` ⇒ 主动候选单位全为 `0`

`_active_candidates` **只在危险尺度被拒时才 `continue`**；非危险候选即使 `quality == 0` 也会进入列表，但权重 `share × aggression_scale × 0 = 0`，量化后 `units = 0` ⇒ 分布里仍有该行，但**没有任何单位** ⇒ 记为「无活跃候选」。

`quality = value_quality + (0 if dangerous else bluff_quality)`，而 `_non_value_quality`：

- `recent_aggression > 1` 或 `live_opponents == 0` ⇒ 直接返回 `0`；
- 翻后还要求 `draw > 0` 或底牌含 A / K；且 `_draw_score` 在**五张公共牌（河牌）上恒为 `0`**。

⇒ 河牌上「未成强牌、且底牌无 A / K」的节点**结构性没有主动依据**。与 `docs/56i` §6 的候选解释（**未经运行验证**）：`missed-draw-river`（`draw` 恒 `0`）、`shared-board`（河牌 `base` 被保守封顶到 ≤`450`，低于河牌价值阈值 `740`）、`overpair-on-high-board`（多人桌扣除人数惩罚后可落到阈值以下）；`one-side-all-in` / `short-stack-call` 另有 `live_opponents == 0` 时 `_active_candidates` 提前返回空列表的路径。

### 4.4 根因假设 C：多人桌上人数惩罚**线性压分**

`_score` 减去 `per_opponent × (contenders − 1)`（翻后 `35`，翻前取规则值 `30`，`@5` 口径）。7 人桌最多 `6 × 35 = 210`、9 人桌最多 `8 × 35 = 280`，而 `value_threshold` / `call_threshold` **只按街与价格取值、不随人数下降** ⇒ 多人桌上 `medium` / `strong` 档的 `value_quality` 与 `passive_score` 被系统性压低。

这与 `docs/56i` §9 的落点（7 / 9 人桌、`medium` / `strong` 档，`weak` 档为正）**方向一致**，但**只是假设**，须由 §7 的针对性回归验证。

**证据地位声明**：§4.2–§4.4 是**对既有实现的静态阅读**，**不是运行读数**；它们**不构成**任何质量结论，**不得**表述为 `docs/56i` 的结论，也**不得**作为验收依据。根因是否成立，必须由 §7 的针对性回归在**实施阶段**验证；若回归不支持，相应改动应**如实记为未获支持并撤回**。

## 5. 候选改动（逐条待裁定）

### 5.1 `P2-A`：让主动分支的风格差异可见（针对根因 A）

| 子方案 | 内容 | 评估 |
|---|---|---|
| **A-1** | 只放大 `aggression_percent` 的档差（现 `90` / `140` / `60`） | 按 §4.2 第 2 点，**单独使用预期不足**（档差作用在不足 `1%` 的份额上） |
| **A-2** | 让**主动权重的口径与被动权重同尺度**（例如把主动权重改为与 `max(0, quality − 门槛 + 常数) × percent` 同形），使风格档差落在与被动项可比的量级上 | 直击根因；改动面大于 A-1 |
| 不做 | 保留现状 | `docs/56h` §7 第 4 项按 §4.2 将继续不满足 |

**新增规则字段（拟议）**：在 `MixedPolicyRules` 增一个**带默认值**的字段（默认值等价于现状），使 `@1`–`@5` 的分布**逐位不变**；`@6` 才启用新口径。

**必须一并记账的耦合**：主动率是所有街共用的口径 ⇒ 改动会同时移动 L3 第 1 项覆盖率（现值 `39.82%`，门槛 `25%`）、类型熵、以及 JS 距离（`aggressive–calling` 余量仅 `+0.0141`）。

### 5.2 `P2-B`：补上河牌的「可主动」公开依据（针对根因 B）

为河牌增加一条不依赖 A / K 的公开依据（例如对手本街主动次数与位置的组合），使非阻断型河牌节点也有非零的非价值质量。

**建议：不做。** 三条理由：

1. **没有判据要求它**：L3 第 1 项（覆盖率 `39.82%` ≥ `25%`）与其余各项均**不**因该形态而不满足；
2. 它正对着 `docs/53c` §4 第 4 条与 `docs/56i` §6 的**疑似弱点**（共享牌面上几乎不主动），而该弱点**从未做过剥削性检验**；在此处增加主动性，**可能提高被剥削面**，且与该弱点的关系**无法由本次整改回答**；
3. `docs/56i` §10 已明确：该读数**只能**表述为「读数存在、可利用性未检验」。

若仍选择做，必须单独裁定，并在规格中写明「**不以修复漏洞为理由**，且可利用性仍未检验」。

### 5.3 `P2-C`：让多人桌的分值不在价值阈值下塌陷（针对根因假设 C）

| 子方案 | 内容 |
|---|---|
| **C-1** | 人数惩罚改为**带上限**：`min(cap, per_opponent × (contenders − 1))` |
| **C-2** | 让 `value_threshold` 随 `contenders` 小幅上调，维持「评分 − 阈值」在多人桌上不塌陷 |
| 不做 | 保留现状；L4 按 `docs/56h` §8 继续不满足 |

C-1 与 C-2 **互斥，择一**（同时实施难以归因）。

**必须一并记账**：这是本次**唯一**直接针对强度类判据（L4）的改动，方向正确性**完全未经运行验证**，**可能反而更差**。按 `docs/53` §13.2，须用**固定对照**报告收益与退化，且**不得**使用 v6 / v7 冻结集合作为该对照。
