## 3. P0-6 规格（冻结）

### 3.1 门槛的地位：定义入库、暂不启用

本轮冻结的是**规则的完整定义**与**可复算的判定函数**，而不是判据本身：

1. 判定函数**必须**输出解释性状态（`exceeds-threshold-observed` / `threshold-not-observed`），**不得**输出「合格 / 不合格 / 通过 / 达标」；
2. 判定结果**不绑定任何验收、不阻塞任何接入、不改变任何已落盘结论**；
3. 因此 `docs/35` §3.1 决策一 (c) **继续有效**；`docs/33` §7 与 `docs/34` §5 的「合格没有已签收的定义」**继续成立**；
4. 本轮的判定函数只是把「若将来要设门槛，必须遵守什么规则」变成**可执行、可复算**的形式，从而消除口径漂移。

### 3.2 判定对象与双向报告

| 项 | 口径 |
|---|---|
| 判定对象 | `probes.gains`：逐座位 `gains[p] = max(0, max over 预注册 probe of delta)` |
| 阈值常量 | `1/20`（= 0.05 BB/hand），沿用 `docs/31a` §3.2 的既有解释边界；**不是**本轮新设的门禁线 |
| 超线定义 | 某个 seed 的观测中 `max(gains) > 阈值` |
| 必须同时报告 | 双向 `results[].delta` 的全部极值（最大正偏离与最小负偏离），避免只看到「阈值策略更强」的单侧 |

**钳位说明（继承 `docs/31a` §3.2，不得省略）**：`gains` 只反映「预注册阈值策略相对训练策略**更强**」的方向；阈值策略明显**更差**（`delta < 0`）不会体现在 `gains` 里，只能从 `results[].delta` 读出。因此本轮的判定结果**必须**与双向 delta 极值成对出现，不得只报 `gains`。

### 3.3 多 seed 规则：以多 seed 结论为准、单 seed 不判定

1. 判定函数接收的是**一组**观测；观测数 `< 2` 时**明确失败**（`QualityGateError`），不产生任何判定；
2. 该规则只消除「单 seed 判定」这一谬误，**不等于** 2 个 seed 足以支撑更强的结论；`docs/34b` §9.7 关于「以更多 seed 估计反转频率」的要求**未被满足**，因为本轮**不新增任何运行**；
3. 同一组观测内的 seed 必须唯一，重复 seed 明确失败；
4. 判定**不追溯改写**任何已落盘记录：输入是只读的，输出是新的对象，既不写文件也不修改入参。

### 3.4 人数隔离：N=6 / N=7 各自独立

1. 一组观测内必须人数一致；把不同人数的观测放进同一次判定**明确失败**；
2. N=6 与 N=7 各自出具独立判定，**不得**用一侧结果外推另一侧；
3. 即使两侧在相同 seed 上判定不同，也**不得**归因于人数：两侧的**信息集数（1 152 vs 3 136）与树规模同时不同**，本轮没有为此设计对照（`docs/34b` §9.7）。

### 3.5 判定层的形态与只读边界

新增 `tools/trainer/src/multiplayer_cfr/quality_gate.py`，提供：

| 名称 | 作用 |
|---|---|
| `ProbeDelta` | 单条 `(player, probe_id, delta)` 观测 |
| `SeedObservation` | 单个 seed 的一次观测：`seed` + `player_count` + `gains` + 双向 `deltas` |
| `ThresholdVerdict` | 多 seed 的解释性判定结果 |
| `observation_from_measurement(record, seed)` | 从**已严格验证**的 `MeasurementRecord` 提取观测；未完成的 probe 明确失败 |
| `evaluate_gains_threshold(observations, threshold=1/20)` | 纯函数判定入口 |

只读边界（冻结）：

- **不得**读文件系统、网络或环境变量；`observation_from_measurement` 只消费调用方已读入并验证过的记录对象；
- **不得**调用任何训练 / 评估 / 测量 / 监督原语，**不得**触发 `mccfr.train`、`evaluate_profile`、`run_manifested_experiment` 等（直接调用属流程违规）；
- **不得**写回任何已有工件，**不得**新增 JSON schema、**不得**修改任何既有模块的行为。

### 3.6 验收口径

| # | 验收项 | 判据 |
|---|---|---|
| C1 | 门槛定义可签收 | 作用对象、阈值、超线定义、多 seed 规则、人数区分、超线处置六项全部在本文写死，且无歧义 |
| C2 | 可复算 | 纯函数对同一组观测给出确定结果；能从**已落盘的已冻结证据**重算出与 `docs/34a` / `docs/34b` 一致的读数 |
| C3 | 单 seed 不判定 | 观测数为 1 时明确失败；重复 seed 明确失败 |

### 3.7 若将来「启用」门槛，需要什么（前置条件，本轮不满足）

1. 用户单独授权**反转** `docs/35` §3.1 决策一，并在文档中如实记录这次反转；
2. 用更多 seed 估计判定反转频率（`docs/34b` §9.7）——本轮**未做**，也不新增运行；
3. 明确门槛是否区分 N=6 / N=7（本轮的隔离设计已给出可直接沿用的结构）与是否对两侧分别签收；
4. 明确超线后的处置是否需要从 `docs/31a` §3.3 升级为「阻塞接入」；
5. 明确门槛作用对象的**误差项**：阈值 probe 的收益差是**精确**计算（全 chance 枚举，非采样），但「预注册阈值策略」本身只是有限的两组探针，**不是** best response、**不是** NashConv、**不是** exploitability（`docs/34b` §9.7）。
