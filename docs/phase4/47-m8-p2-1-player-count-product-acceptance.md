## 3. 现状事实与必然落差（只读核验）

### 3.2 旧 10 人数据事实（只读实测）

真实库 43 局中**不存在** 10 人对局（2 人 3 局、5 人 40 局）。因此：

1. 收紧为 9 **不会**使任何既有历史记录变得不可读或不可展示；
2. 「10 人兼容政策」是**契约层**问题（旧客户端请求、旧 localStorage 配置、`sessions.num_players` 列无上限），**不是**数据迁移问题；
3. 既有测试中没有创建 10 人桌的用例（`test_games_api.py` 全部使用 `num_players = 2`），收紧**不破坏**既有用例。

### 3.3 座位布局现状与必然重叠（只读核验 + 几何推算）

现状实现（`GameTable.vue`）：

```text
seatStyle(seat):  angle = π/2 + seat·(2π/n)
                  x = 50 + 40·cos(angle)   // 百分比
                  y = 50 + 34·sin(angle)   // 百分比
.seat         { position:absolute; transform:translate(-50%,-50%); min-width:110px }
.felt         { min-height:460px }     // 无媒体查询
```

推算（容器宽度取 `.app-shell` 上限下的实际 felt 宽度 ≈ `928px`，高度 `460px`）：

| 人数 | 相邻座位的最小中心距（水平/垂直） | 座位盒（含摊牌明细） | 是否重叠 |
|---|---:|---|---|
| 6 | 约 `0px / 156px`（150°–210° 同 `cos`） | 约 `132 × 200` | 垂直仅 156px < 200px → **重叠** |
| 7 | 约 `77px / 132px` | 约 `132 × 200` | **重叠** |
| 9 | 约 `45px / 105px`（170°–210°） | 约 `132 × 200` | **重叠** |

另有两个结构性原因：

1. 内联摊牌明细由 5 张 `small` 牌组成（`24px × 5 + 3px × 4 = 132px`），**宽于**座位 `min-width: 110px`，使座位实际宽度被撑到 `132px`；
2. `.seat` 的高度随内容（状态行、下注标记、摊牌明细）变化，**没有**确定的盒高，因此无法给出可验证的不重叠保证。

**结论**：`docs/35` §4.2 P2-1 所指的「6/7/9 人的窄屏布局、下注标记、摊牌展开未专项验收」在现状下**确实不通过**；本轮必须引入确定性几何并实测。

## 4. P2-1 规格（冻结）

### 4.1 产品人数范围与 10 人兼容政策

1. **范围**：`2 ≤ num_players ≤ 9`；`2` 仍为默认值。
2. **后端**：`CreateGameRequest.num_players` 的 `le` 改为 `9`；越界请求由 Pydantic 返回 `422`，**不**静默截断、**不**回退到默认值。
3. **前端**：人数输入 `min="2" max="9"`；快捷项为 **2 / 6 / 9**（对应用户「更多使用 6–7 人桌、最多 9 人」的目标；6 与 9 分别代表常用人数与上限）；表单校验文案改为「玩家人数需为 2~9 的整数」；本地配置回读同样限定 2–9。
4. **旧配置**：localStorage 中保存的 10 人配置**不再自动恢复**——`loadSavedConfig()` 判定为非法并返回 `null`，界面回落到设置表单（用户需重新选择人数）。**不**自动改写、**不**静默降级为 9。
5. **旧历史**：`GET /games`（`SessionSummary.num_players`）与 `GET /games/{id}/stats`（`SessionStats.num_players`）继续按库中原值只读展示，**不**过滤、**不**改写、**不**新增列、**不**迁移。
6. **引擎与策略层**：**不改**——引擎仍按 N 人设计且不设上限；`backend/app/poker/**`、`backend/app/strategy/**` 零改动。「上限 9」是**产品**限制，不是引擎能力限制。

### 4.2 座位布局契约（纯几何）

新增 `frontend/src/seatLayout.js`：**只做数学，不碰 DOM**，供组件、回归检查与验收脚本共用。

| 常量 | 取值 | 说明 |
|---|---|---|
| 支持人数 | `2…9` | 与产品范围一致 |
| 缩放档 | `[1, 0.9, 0.8, 0.72, 0.65, 0.58]` | 由大到小；座位内容按该档整体缩放 |
| 基础盒（未缩放，内联摊牌） | `132 × 218` | 宽取「5 张 small 牌」的宽度 |
| 基础盒（未缩放，紧凑摊牌） | `110 × 178` | 摊牌折叠为一行 |
| 内联摊牌的人数上限 | `6` | `n ≥ 7` 使用紧凑摊牌行 |
| felt 高度搜索范围 / 步长 | `420 … 900 px` / `8 px` | 取**最小可行**高度 |
| 水平留白 | `10 px` | 座位盒不得越出 felt |

**几何模型**：

1. 座位中心位于以 felt 中心为心的椭圆上，角度均匀：`θ_i = π/2 + i·(2π/n)`；
2. 椭圆半径由容器与座位盒推导，保证座位盒不出容器：`rx = (W − w)/2 − pad`、`ry = (H − h)/2 − pad`，其中 `(w, h)` 是**缩放后**的座位盒；
3. 不重叠判定用轴对齐包围盒（AABB）两两相交检测；
4. `.felt` 高度由**确定性搜索**决定：对每个缩放档（由大到小）、再对「内联 / 紧凑」两种摊牌形态（内联优先，且只在 `n ≤ 6` 时可用），从 `420px` 起以 `8px` 步长搜索**第一个**使全部座位盒两两不相交的高度；
5. 搜索全部失败时返回 `fits = false`，组件显示**明确降级提示**（提示用户放宽窗口），**不**静默重叠、**不**静默隐藏座位；
6. 座位在 CSS 中用 `left/top` 像素定位（由中心点减去基础盒一半得到），并用 `transform: scale(scale)` 以中心为原点整体缩放，使**渲染盒 = 模型盒**（`getBoundingClientRect` 与实际一致）。

### 4.3 座位内容、下注标记与摊牌展示

为使「模型盒 = 渲染盒」成立，座位内容改为**确定性行高**，每一行**始终渲染**（内容可空）：

| 行 | 固定高度 | 内容 |
|---|---:|---|
| 盲注/庄位标记 | `18px` | 庄 / 小盲 / 大盲（可空） |
| 底牌 | `54px` | 2 张牌或 2 张牌背 |
| 名字 | `22px` | 名字 +（你） |
| 筹码 | `20px` | 筹码数 |
| 状态 + 下注标记 | `22px` | 已弃牌 / 全下 与 `+下注额` **合并为同一行**（这是本轮对「下注标记」的专项处理；原先二者各占一行，会使盒高随状态变化） |
| 摊牌 | `62px`（`n ≤ 6`）/ `22px`（`n ≥ 7`） | 牌型 + 5 张 `small` 牌 / 仅牌型文字 |

行距 `4px`；`.seat` 显式设置基础盒宽高，内容自上而下排布。

**摊牌明细在 `n ≥ 7` 的信息保全**：折叠掉的「最佳五张」在**控制面板**中以文字形式列出（每个摊牌座位一行：玩家名 + 牌型 + 五张牌）；因此折叠只改变位置，**不丢失信息**。

### 4.4 验收视口矩阵

`.app-shell` 为 `max-width: 960px` + `padding: 16px`，故 felt 宽度 = `min(视口宽度, 960) − 32`（`docs/46` 的测量与本轮验收均按此推导，实跑时以浏览器实测宽度为准）。

| 记名 | 视口宽度 × 高度 | 预期 felt 宽度 |
|---|---|---|
| `desktop-wide` | `1440 × 900` | `928` |
| `desktop` | `1280 × 800` | `928` |
| `laptop` | `1024 × 768` | `928` |
| `narrow-laptop` | `900 × 900` | `868` |
| `tablet` | `768 × 1024` | `736` |
| `small-tablet` | `600 × 900` | `568` |
| `large-phone` | `480 × 900` | `448` |
| `phone` | `390 × 844` | `358` |

判定只看**横向**（felt 宽度）与包围盒关系；页面允许纵向滚动，故视口高度只用于渲染而非判定。

### 4.5 验收方式

1. **无头浏览器实测（主判据）**：在 `docs/47a` 记录命令与实测值。对 `2–9` 每个（人数 × 视口）组合：
   - 起后端（`:8000`）与前端开发服务器（`:5173`，Vite 代理 `/games`、`/hands`、`/health` → 后端）；
   - 通过 `POST /games` 建立该人数对局，写入 localStorage 的 `holdem.table.config` / `holdem.table.session` 后加载页面，使牌桌直接渲染该人数；
   - 读取 `.felt` 与全部 `.seat` 的 `getBoundingClientRect()`；
   - **断言**：任意两个 `.seat` 的矩形**不相交**；每个 `.seat` 完全落在 `.felt` 矩形内；每个座位只出现一次；实测盒高 ≤ 模型盒高（容差 `1px`）。
2. **纯几何回归检查（补充证据）**：`frontend/scripts/check-seat-layout.mjs`（**无新依赖**，只用 `node` 直接 import 纯函数），对同一视口矩阵与 `2–9` 断言模型盒两两不相交，输出每个组合的 felt 高度与最小间隙。
3. 前端 `npm run build` 必须无回归；后端 `uv run pytest -q` / `uv run ruff check .` 必须通过。
4. 本轮**不**做任何性能结论：`100ms` 是实时 Bot 决策预算，**不是**整手复盘预算；也不得把本轮实测表述为性能证据。
