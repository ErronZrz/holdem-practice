## 3. 一处必须如实更正的既有认识

本轮开始前的口头认识是「提高不可预测性（模拟对手升级）这一大步已经完成」。**该认识与仓库实际状态不符**，必须记录更正，以免后续轮次重复。

### 3.1 「生产 / 实盘 / 线上」的定义（先把词钉死）

本项目中这三个词同义，指**用户实际打牌时在跑的那个本地服务**，而不是云服务器。三层区分：

| 层 | 位置 | 内容 | 本轮状态 |
|---|---|---|---|
| 离线层 | `tools/trainer/` | CFR 训练、实验、策略产物、campaign 回执 | 候选 A 在此；与平台完全隔离 |
| **生产（实盘/线上）层** | `backend/` + `frontend/` | FastAPI 服务 + Vue 界面 + 真实规则引擎 + 真实 SQLite 牌谱 + HTTP 生命周期 + bot 决策 | 跑的是 `HeuristicStrategy` |
| 云端 | 尚未存在 | 远程部署、HTTPS、访问保护 | 未做（`docs/20` §8.4「本轮不部署、不接服务」） |

依据：`docs/26` §9.1 / 边界条「所有训练/实验能力只能在 `tools/trainer/`，不得依赖 `api/`、`llm/`、真实 SQLite、HTTP 生命周期或**生产运行时**」；`docs/20` §7 分期表中的「**分阶段生产接入**」一行；`docs/20` §9.2「仅本机 CPU，不用付费云」。

因此「**生产接入**」= 把策略从离线层搬到生产层，让 bot 在真实对局里按它行动。**它与「上云」是两件事**：本用户所说的「在本地服务上验证效果」本质上就是生产接入（只是跑在本机），而云端部署是更后面的独立一步。

## 5. 模拟对手升级切片的事前注册（在任何结果产生之前冻结）

本节冻结的是**指标定义与门槛**。**具体的测试节点集、机会分母与评估方式，必须在切片启动时、在任何策略调参之前冻结**并写入该切片的文档——`docs/20` §6 开头的要求是「先冻结测试集、机会分母与评估方式，再调策略；不能调到有利结果后换分母」。

### 5.1 切片范围（D3-a = (iii)）

三者齐备，缺一不算完成：

| 组成 | 解决的问题 | 对应 `docs/20` |
|---|---|---|
| **受约束混合** | 「同一个人不只一套必然动作」 | §4.1 最小策略结构 |
| **2–3 档风格** | 「不同座位像不同人」 | §4.2 人格的最小持久性 |
| **多尺度金额** | 最显眼的固定额度公式 | §3「多尺度解决金额公式」 |

`docs/20` §3 的组合建议即指出「三者缺一，最小版本的体验改善都可能很有限」，本决策与之一致。

**与 `docs/20` §9.1 的关系（澄清，不视为冲突）**：§9.1 已确认的是「**不先**建设**完整**启发式人格系统」——它约束的是**顺序**（不把人格系统排在 CFR 之前）与**规模**（不做完整系统）。本切片按 D1 = B 仍排在 CFR 向生产接入之后，且 §4.2 的定义是「约 3 个基础档 + 受控区间内按 seed 分配参数」，属最小版本，不是「完整人格系统」。二者相容。

**与 `docs/20` §7 M9 的关系**：M9 行写的是「基础策略通过后再加每座位内部混合与稳定风格」。因此本切片在排期上可能被**拆成两个子步**（先混合 + 多尺度，后风格档）——**该拆分在切片启动时另行决定**，本节不预先裁定。

### 5.2 验收口径（D3-b = A，整套采纳 `docs/20` §6）

#### 5.2.1 客观统计指标（第 1–6 条）

| # | 指标 | 口径（冻结） | 现状锚点（`docs/20` §2） | 门槛（冻结） |
|---|---|---|---|---|
| 1 | 实质动作混合覆盖率 | 分母 = **非强制节点**（至少两个合法动作可选）；某节点若有**至少两个不同动作类型**各 ≥10% 概率，记为混合节点；覆盖率 = 混合节点 / 非强制节点 | 最近会话 25/365 = **6.85%**；翻前 **0%**；面对下注 **0/55** | 固定节点集整体 **≥25%**；并**分域**报告翻前 / 面对下注 / 免费行动，**不得**全靠空气诈唬一条分支达标 |
| 2 | 平均类型熵 | `H(s) = −Σ p·log₂p`，对**固定估值**求平均（独立 seed 固定住估值，排除 MC 抖动） | **0.032123 bit** | 固定节点集 **≥0.15 bit**；**不得**靠降低 MC 样本数制造估值抖动达标 |
| 3 | 额度多样性 | 条件于已选 BET/RAISE，先做**同额合并**（合法夹紧后金额相同的候选合并），再统计额度锚点占比与金额条件熵 | 单一「约一池」公式 → 多样性 ≈ **0** | 至少两档合法可区分的锚点中**两档各 ≥15%**；金额条件熵均值 **≥0.5 bit**；短码退化单档**单独报告** |
| 4 | 风格可分度 | **同局面、同估值 seed** 比较不同**风格档**的条件分布；再以**配对对局**报告 VPIP/PFR/主动频率 | 无风格档 → 当前不适用 | 至少**两档**在**预先指定的两个机会域**上有 **≥10 个百分点**的概率差；不能只是「座位原始频率不同」 |
| 5 | 风格稳定性 | 同 session 配置/身份连续；换按钮、rebuy **不重抽**；不同 seed 仍体现倾向 | 无风格档 → 当前不适用 | 足量配对样本中**方向稳定** |
| 6 | 20 手公开预测 | 只用两个公开特征（街道、是否需跟注）分桶，训练 20 手、在**后续独立手**验证 | 单切分 **70.30%**（全局多数动作基线 39.60%） | 至少 **5 个预定 seed 队列**报告 accuracy / balanced accuracy / log loss；原始准确率**下降 ≥5 个百分点**作为**诊断目标，而非唯一阻断门槛** |

读法限定（`docs/20` §6.1 / §11.2）：以上指标**只衡量对手产品效果，不是 GTO 教学指标**，也不强加给未加人格扰动的 CFR 基础策略；**不得**把准确率越低解释为策略越好。

#### 5.2.2 硬护栏（第 7 类，恒为 0，非可选）

非法动作、负筹码、筹码不守恒、使用未来牌或对手暗牌、免费随机弃牌 **必须为 0**；概率有限、非负且归一，同额合并正确，短码全下与最小加注合法。`docs/20` §6.2 明确：**严重漏洞不能被「用户允许适当牺牲 GTO」豁免。**

#### 5.2.3 主观试玩（第 7 条）

≥3 组、每组 30 手、**盲化 A/B 试玩**，由用户确认「更想继续玩且不是乱打」；**不以统计指标代替用户验收**。

D3-b = A 表示本条**已一并采纳**。执行时点不预先指定，但它需要切片先接入本地服务（即需要 D2 之外的单独改动授权）。

#### 5.2.4 探针池与「可接受牺牲」提案的处置（需注意的一处张力）

`docs/20` §6.2 的探针池（旧 heuristic / Random / 偏紧弱 / 跟注站 / 固定尺寸施压 / 过量诈唬）与「配对发牌种子、同位置、同起始深度、报告 BB/100 与 95% 区间」属于评估方式，已一并采纳；「每种对照 ≥5000 配对手牌块」按原文仍只是**评估规模参考**，不是门槛。

**一处必须如实标注的张力**：`docs/20` §6.2 原文把「相对旧版最差收益差 95% 区间下界不低于 `−5 BB/100`」明确标注为「**未拍板的对手风险预算**，不是教学/GTO 标准」。本记录按 D3-b = A「整套采纳」将其**一并事前注册**为对手风险预算。**若这不是你的本意，请指出，本注册可修订**（该修订必须记录原因，不得静默修改）。
