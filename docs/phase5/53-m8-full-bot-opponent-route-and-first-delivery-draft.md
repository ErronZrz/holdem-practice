## 4. 首期方案概述（具体规格见§9–12）

### 4.1 产品与算法范围

- 产品保持 2–9 人、全四街；6/7 人是主要使用场景，不以此省略其他人数的合法性、信息边界和成本验证。
- 新策略为本地、版本化的规则型混合对手。覆盖合法局面的行动能力，不等于每个局面都有可靠 EV 或高质量解。
- 不引入在线 API、实时求解、LLM 决策、神经网络权重或外部策略表；不依赖训练器运行。
- 首期不做跨手玩家建模或自适应追猎。只使用本手公开信息及固定的、版本化的风格配置，减少过拟合、持久化和预算不确定性。
- 范围推断仅可来自公开行动，规则评分必须标注为启发式分数。不能把声明式范围契约的存在当作已经实现了 range-vs-range equity。

### 4.2 决策链与职责边界

链路为：**行动者安全输入 → 状态特征 → 有限合法动作/尺度候选 → 规则权重 → 人格与每手状态的受限变换 → 归一化分布 → seed 可控采样 → 引擎最终合法性检查。**

- 新状态适配由 API/策略层承担；`poker/` 保持只读，策略仍通过 GameState 及受控的公开上下文交互，不直接持有引擎。
- 公共上下文采用§9.2的 Pydantic 模型，逐字段列白名单，区分输入不完整、非法和受限能力，不能在输入缺失时伪造精确历史。
- 既有策略接口保持兼容；额外上下文与手生命周期按§9实现，不为此强制改造旧策略。
- 每个 Bot 座位独立持有可变状态；共享内容最多是只读配置/公开事实。各座位私有底牌、采样流、每手隐变量和策略缓存不能互通。
- 特征缓存必须有手、座位、街、公开状态和策略版本的完整作用域，不以表面相似局面混用；首期优先不引入跨局持久缓存。

### 4.3 三种风格与每手隐变量

| 风格建议 | 稳定差异 | 必须防止的退化 |
|---|---|---|
| 紧稳 | 入池较克制，重视牌力与位置，适度混合 | 固定牌力阈值或固定尺度直接泄漏手牌 |
| 松凶 | 更宽的主动范围与更多施压，仍受人数/筹码/牌面约束 | 不看局面地持续加注、多人底池无条件诈唬 |
| 跟注型 | 相对愿意继续、主动进攻较少，保留合理弃牌 | 无条件跟到底或全街完全没有行动变化 |

风格名不是强度认证，不设「均衡型」标签。三种风格均来自同一规则族，不能宣称已有多个独立算法家族。

建议人格在 session 内稳定，每手只抽取一次幅度受限的隐变量，影响整手决策；不在每步独立改人格。隐变量与人格配置不在进行中对外发送。

风格分配按§9.1冻结的 Bot 座位升序循环配置，session 内固定，以已有策略身份追溯，不增加数据库列。只有一个或两个 Bot 的桌不可能同时出现三种风格：三类能力通过独立配置与测试覆盖，不制造不存在的同桌差异。

### 4.4 混合动作与下注尺度

- 以「动作类型 + 整数金额」作为候选；下注与加注的金额语义、最小加注、短码全下和实际支付必须依据现有合法动作契约处理。
- 尺寸由有限、版本化的候选比例或筹码边界产生，先合法化、去重，再分配概率；不得随意产生任意整数金额。
- 尺寸因短码或最小加注合并后要合并权重，不重复计算成多个尺度；仅一个合法尺寸时不强求尺度熵。
- 合理节点允许非退化混合，明显受限节点允许纯动作；不能要求每张牌、每条街都三种动作或多种尺寸。
- 人格和隐变量只能变换已允许的候选。禁止给被安全规则排除的动作强行设置正概率下限。
- 没有可靠动作价值时不启用名为「EV 容忍带」的伪保护；不能用 equity 差或规则分数冒充 EV 差。
- 具体候选比例、概率变换、概率表示与数值精度按§10.3–10.4；不改候选 A 的 `PROBABILITY_UNITS` 或 artifact schema 来迁就新策略。

### 4.5 随机性、成本与完整对局

- 所有随机过程可注入 seed；固定版本、输入、显式状态和 seed 可重放。查看分布不应额外消耗行动随机流。
- 牌局、各座位策略、每手隐变量与估计用随机流应明确隔离，分流规则稳定且版本化；不得依赖不稳定的进程哈希或通过重置相同 seed 让 Bot 同步行动。
- 不把主 seed、牌堆状态或其他座位状态作为策略特征或发给客户端。不通过当前已知底牌反推未公开牌序。
- 不因为换成独立实例而改变旧 `heuristic@1` / `random@1` 路径的既有随机消费语义。
- 沿用 `<100 ms` 的单次实时决策硬预算，以及既有 50/80 ms 的 p95/p99 指导值；不修改 `lookup_budget.py` 常量。
- 决策计时必须覆盖新接线中为该次动作执行的投影/上下文/特征/分布/采样/校验，不拿 lookup 查询片段替代；冷启动、内存与整手/整桌成本另报。
- 单靠外层计时不能强制中断同步计算；工作量上界与失败处置见§10.5。不能按墙钟随机截断不同采样次数来破坏重放，也不能以降级掩盖超时。
- 既有 `equity()` 语义和调用采样数不变；§10明确首期新策略不新增 Monte Carlo 调用，改用确定性牌型/听牌规则评分。该取舍已获认可，不预称其强度或延迟达标。

### 4.6 接入与旧局兼容

- 新策略标识冻结为 `mixed-local@1`；不冒充 `heuristic@1`，不重新绑定旧别名，不允许客户端任意模块路径。
- 建议先实现并验证新策略，默认保持旧值；只有质量报告获用户签收后，另行明确切换动作，才修改新建请求默认值。
- 新建请求省略策略时使用届时默认；显式请求旧策略仍创建旧策略对局；已有内存 Runtime 不随默认值改变。
- 重连仍在内存中的旧局沿用原策略。进程重启后的 404 和前端新建 session 属既有行为，本期不扩展为数据库续局；不得把新 session 说成旧局恢复。
- 新手只按既有事实字段记录真实策略身份；旧历史缺身份仍为 `unknown`，不按新默认推断，不回写原始历史。
- 复盘继续使用 `heuristic-conservative` 及既有保护。新对手的人格、低频动作或自身分布不参与真人错误判定，也不能用旧复盘评分认证新 Bot 的强度。
- 首期不新增人格选择 UI，不承诺在 UI 展示每个 Bot 的人格；行为差异与可追溯配置是首期交付，显示入口另议。

## 9. 执行规格细化：身份、输入和生命周期（冻结；实施未授权）

2026-09-21 用户原文：「好的，那么继续下一步。」当时据此补齐文档，不将该答复解释成编码、提交、实跑或切默认授权。以下具体技术方案后来获§13.1整体认可，并按§13.3授权冻结提交；它们不是已经实现或已通过质量验证的事实。§4、§7的概述由本节至§13细化。

### 9.1 身份与兼容分派

- 建议唯一新注册标识为 `mixed-local@1`，不增加无版本别名。它指本地规则、风格分配、尺寸表、概率量化和随机分流的整个配置集合，不含候选 A 产物。
- 注册工厂继续是 `factory(seed) -> Strategy`，不修改 `Strategy.choose_action(GameState, LegalActions) -> Action` 或旧工厂。工厂返回 `MixedLocalStrategy`，它只是座位分派器；各座位有独立的 `MixedSeatPolicy`。分派器不保存底牌、特征或跨座位策略缓存。
- 子策略仅得到自己的派生随机键、固定风格和本次安全状态。不能读取分派器、引擎、其他子策略或 session 主种子。子策略除本手模式外不记忆私有历史，模式缓存最多一手；不共享对手模型。
- 生产 Bot 座位升序分配 `tight / aggressive / calling` 循环，session 内不变，不随庄位或手号轮换。低人数桌无法同桌呈现全部风格，离线单独覆盖三类，不引入公开的风格参数或选择器。
- `GameRuntime.bot` 保留；旧策略仍使用原单实例路径。新分派器在首次完整上下文到达时建立各座位子策略，以后拒绝不一致的 Bot 座位集合。创建 session、保存手牌均使用既有 `bot_strategy` 字段。

### 9.2 安全上下文与 GameState 的关系

新增 `MixedGameState`，为定义在 `strategy/` 的冻结 `GameState` 子类，唯一新增属性为 `context: MixedContext`；不修改 `poker/state.py`。策略方法参数类型仍是基类 `GameState`，在内部验证受支持上下文，不能把 Protocol 签名收窄。

`MixedContext` 为 `frozen=True, extra='forbid'` 的 Pydantic 模型。整数用严格整数，嵌套集合用 tuple；以下字段均必填：

| 字段 | 约束与来源 |
|---|---|
| `schema_version` | 固定 `mixed-context.v1`，仅新策略内部输入契约，不是 HTTP/历史/训练记录 schema |
| `hand_number` | 正整数，来自运行态；不使用 UUID、时钟或运行中 seed 当牌理特征 |
| `event_count` | 本手已成功记录的公开事件数，含两条盲注；用作行动标识，不参与牌力分数 |
| `small_blind / big_blind` | 正整数，名义配置；要求 `big_blind == 2 * small_blind`，不将短码实缴当名义盲注 |
| `bot_seats` | 严格升序、无重复的座位元组；生产为现有人类座位之外的集合；离线可为全部座位 |
| `streets` | 恰好四个 `MixedStreetSummary`，按翻前/翻牌/转牌/河牌排列；未来街为零值 |

每个 `MixedStreetSummary` 仅含：`street`、`counts_by_seat`（N×5，fold/check/call/bet/raise 顺序，非负且各项饱和至 3）、`paid_by_seat`（N 项实际累计支付）、`last_aggressor`（seat 或 None）、`preopen_callers`（第一次自愿加注前曾跟注的唯一座位升序集合，仅翻前使用）。两条盲注计入支付和 `event_count`，不计为自愿 call/raise。名称、IP、手牌文本、对手风格、seed、整手底牌、未来牌均不进入上下文。

- API 先取得 `project_for_actor(engine.snapshot())`，再附加受控摘要；不能先附加后调用旧投影，因为旧投影会重建基类并丢掉上下文。
- 新策略在任何求值前验证：人数 2–9、座位唯一且连续、当前行动者有效且未弃牌/全下、非终局、街与公共牌数为 0/3/4/5、自身恰好两牌、其他人底牌为空、已知牌无重复、所有支付非负、`sum(total_committed)==pot`，摘要支付与快照按人/街一致。不以 `PlayerState.name` 做特征。
- 冻结 dataclass 是浅冻结，不能依赖它保护嵌套 `PlayerState`。每次输入沿用投影的独立对象副本；子策略不保留或修改快照。新增 Pydantic 摘要不包含可变 list/dict。
- 缺少上下文、伪造未来事件或不一致支付一律 `MixedContextError`；不悄悄退回 heuristic，不把被截断的历史伪称完整历史。摘要是**明确的信息压缩**，不宣称完整信息集或精确策略映射。

### 9.3 公开摘要的维护与原子性

在 `api/games.py` 维护仅新策略启用的摘要跟踪器，字段为四街固定数组及已消费事件数，额外空间 O(4N)，不每次复制/遍历整手历史。

1. `engine.start_hand()` 返回后先判断终局；若已因盲注全下自动结算，直接沿旧保存路径结束，不构造策略决策。
2. 否则初始化摘要，消费本手恰好两条 `small_blind/big_blind` 记录，金额取实际支付；非盲位初始支付为零。起始筹码以行动前快照 `stack + total_committed` 为准，不用 session 配置替代跨手筹码。
3. 真人或 Bot 的 `engine.apply_action()` **成功以后**，读取新追加的公开事件并更新摘要。普通一次行动应追加一条；非法行动不更新计数。转换仅复制 `street/seat/action/amount` 白名单，历史 amount 是增量，不是 raise-to。
4. 若引擎自动推进多街，历史没有独立街切换事件；当前街从安全快照读取，摘要其他街继续保留零值。不从终局历史倒推进行中的牌。
5. event 数、已消费游标或支付对不上时明确失败，不隐式重放全量或用默认值补齐。新的一手重置摘要；各座位手模式根据新手号更新。
6. 输入校验、规则求值、整数候选校验均在实际 apply 之前完成；出错不提交候选动作。若 apply 后的摘要断言失败，按一致性错误停止推进，不假装可通过重试撤销已发生行动。API 返回固定错误信息，不向客户端暴露快照或内部异常内容。

### 9.4 随机源与可重放范围

- 只对新策略分支分流随机源。显式请求 seed 时，把有符号十进制字符串经 UTF-8 编码、SHA-256 得到主键；seed=None 时由运行态生成一次 32 字节系统熵，并允许测试注入该主键。都不落库、不外发；未保留主键的自然运行不声称可事后逐动作复算。
- 派生规则固定为 HMAC-SHA256：key 为父级键，消息为 UTF-8 的紧凑 JSON 数组（明确元素类型及顺序，禁止隐式对象序列化）。从主键分别派生 `["mixed-local@1","deck"]`、`["mixed-local@1","bots"]`；前者转非负整数传给既有引擎 seed 参数，后者给分派器。
- 分派器以 `["seat", seat]` 派生座位键；子策略以 `["hand", hand_number,"mode"]` 和 `["hand",hand_number,"action",event_count]` 派生手模式/本次动作随机 seed。固定标准库 `Random(派生整数).randrange(上界)` 抽样，不依赖 Python 的 `hash()`。
- 不把动作序号、主键/派生值当作牌力特征。分布查询不消费动作随机状态；相同手号、event_count、输入和版本重复查询/采样得到相同结果。更换手号只允许通过手模式改变分布。
- 三个模式由 `[0,100)` 均匀整数分区：正常 `[0,80)`、谨慎 `[80,90)`、施压 `[90,100)`。一手内固定。
- 主种子只在 API/工厂边界，子策略无法获得牌堆派生 seed。相同显式 seed 的新旧策略不保证得到相同发牌；离线对照必须独立固定牌堆 seed，而不是靠两条 API 路径碰巧使用相同 seed。
- **显式 seed 是非保密的重放/测试模式**：知晓 seed 的调用者可依据公开派生算法重构牌堆及模式，HMAC 域分离并不能使已知根 seed 保密。该模式不计入对调用者不可预测的保证；正常前端不传 seed，使用不可外发的自然生成根键。保持现有显式seed接口兼容，不虚称它是对抗性安全边界；本期也不承诺标准库随机流具有密码学不可预测性。
- **重放承诺限固定策略/依赖版本、相同初态与公开行动序列。** 不新增重启恢复、不声称只有历史中策略身份就能恢复未知随机状态。

## 10. 执行规格细化：有界规则与联合分布（冻结；实施未授权）

### 10.1 计算路线与限制

本期建议新 Bot **不调用 Monte Carlo equity，也不调用旧 HeuristicStrategy**；保留其所有既有调用与采样数。使用真实牌的确定性牌型/听牌特征、公开下注摘要、位置、人数、整数筹码与有限规则权重。这是控制首期成本与隔离旧语义的具体取舍，不是新质量结论。

复用 `poker/evaluator.py` 的 `evaluate_fast()`，输入只由已验证自身两牌+公共牌组成；返回 `HandRank(category,tiebreak)`，不是胜率。每次决策至多一次主牌型评估和一次完整河牌公共牌评估，不枚举对手牌、不枚举 runout，不读取旧 heuristic 私有函数。新 Bot 的全部分数均为 **0–1000 的规则评分**，不是概率或 EV。

筹码运算、比例比较和取整全用整数；权重计算使用整数/有理数，最终量化。筹码值没有现有 API 上界，因此仅承诺循环次数不随筹码金额线性增长，不能声称任意位宽整数都在 100ms 内。验证报告必须写清测试位宽，本期不偷偷收紧旧 API 可接受范围。

### 10.2 特征定义（明确计算而非模糊桶名）

约定 `clip(x,a,b)=min(max(x,a),b)`；点数 A=14，K=13，Q=12，J=11。分数先按以下顺序求值，不跨人数引用表。

**翻前基础分 B：**

- 口袋对子：`500 + 35*(rank-2)`。
- 非对子：`18*high + 10*low + 85*[high==14] + 75*[low>=10] + 45*[同花] + gap_bonus`；点差 1/2/3/其余的 `gap_bonus` 分别 35/20/5/0。
- 截断至 0–1000；此公式是自有强弱排序初值，不宣称来自商业范围表或 Chen/GTO 的校准频率。

**翻后基础分 B：** 优先根据最佳牌型分类；所有“顶/中/低”比较仅用公开牌。

| 牌型/关系 | B |
|---|---:|
| 同花顺 / 四条 / 葫芦 / 同花 / 顺子 | 1000 / 985 / 960 / 900 / 860 |
| 三条：手中对子形成 set / 一张底牌匹配公共对子 / 纯公共三条 | 840 / 780 / 180 |
| 两对：两张不同底牌各匹配公共单张 / 自身口袋对子＋公共对子 / 仅一张底牌贡献一对＋公共对子 / 两对均来自公共牌 | 760 / 600 / 520 / 200 |
| 一对：口袋对子高于全部公共牌 / 口袋对子位于公共最大最小点之间 / 口袋对子低于全部公共牌 | 720 / 520 / 400 |
| 一对：底牌匹配公共最高/中间/最低单张 | 650 / 500 / 360 |
| 一对完全来自公共牌 | 180 |
| 高牌：A 高 / K 高 / 其余 | 180 / 130 / 60 |

牌型关系只按 `HandRank.tiebreak` 中**实际采用的对子/三条点数**判定，不能按手里“存在一个对子”判定。两对依次判断：两个采用点数在公共牌中各至少两张→200；采用点数之一确为自身口袋对子→600；两张不同底牌分别把两个公共单点数配成对→760；剩余一张底牌把公共单点数配对而另一对为公共对子→520。故公共 KK99 + 底牌22 必须为200而非600。

匹配公共单张的一对，只有未配对底牌点数实际进入 `tiebreak` 的三个踢脚、且不是与已有公共同点数重复时，才加踢脚分：J以上+40，8–10为0，其余-40；未进入最佳五张时加0。公共 AKQ82、底牌8J与87均为88AKQ，踢脚增量均为0。牌型优先级由 `HandRank` 决定，不可先用对子规则覆盖三条/葫芦。河牌若整体 `HandRank` 恰等于五张公共牌的 `HandRank`，将 B 上限设为450，明确这是保守共享牌面规则，并非已经证明可弃/该跟；公共绝对大牌可能成为已知薄弱点，必须在质量报告中单列，不能把它称作精确平分判断。

**听牌加分 D：** 只在 flop/turn 且当前没有顺子或更高牌型时计算。

- 对 52 张标准牌中尚未公开且不在自己手里的牌，最多检查 47 张候选下一牌；只做固定长度的点数/花色集合判断，不运行牌型 evaluator，不排除未知对手牌。
- 同花候选要求补牌后有同花，且原有四张同花牌中至少一张是自身底牌；五张公共牌自身已可组成同花的候选不算私有听牌。
- 顺子候选要求补牌后出现任一五连点数集合（包括 A2345），至少一个点数只能由自身底牌提供，且补牌前未成顺；只算完成顺子的候选，不算随便提升一对的牌。
- 两类候选按具体牌去重得 `outs`。flop：`D=min(180,12*outs)`；turn：`D=min(120,8*outs)`；river：0。它不是干净 outs、胜率或未来收益，只作潜力信号。

**公开风险与位置：**

- `m` 为未弃牌的其他人数，**含 all-in**；`live` 为其中仍有筹码可行动者。此处新定义不修改 `_num_pot_contenders`。
- 当前街对手主动动作数 `r=min(3,sum(对手 bet/raise 计数))`，不计盲注，不计自身动作。`limpers=len(preopen_callers)`。
- 位置：翻前从标准首位（N=2 为 BTN，否则 BTN+3）顺时针，翻后从 BTN+1 顺时针；仅保留未弃牌且有筹码者。在此列表中索引为 i、长度为 k，`position=0` 若 k=1，否则 `floor(80*i/(k-1))-40`。实际可否行动仍以 LegalActions 为准。
- 牌面风险 `texture`：公共同花张数至少 4 且自身最佳牌型低于同花时 +80；否则恰好 3 张同花且低于同花时 +40。公共点数有任一五连窗口缺不超过 1 个点、且自身低于顺子时再 +40。preflop 为 0；不读取未发牌。
- 后续所用 SPR 为规则用有效投入比，不冒充所有边池的统一 SPR：`E=min(自己剩余筹码,max(0,各未弃牌对手 total_committed+stack 的最大值-自己 total_committed))`，`spr=E/max(pot,big_blind)`，比较以交叉乘法做，不将浮点写入筹码。

### 10.3 人格/模式参数与连续动作权重

| 参数 | tight | aggressive | calling |
|---|---:|---:|---:|
| 评分偏移 `looseness` | -35 | +35 | +10 |
| fold 倍率（百分单位） | 130 | 85 | 70 |
| call 倍率 | 90 | 110 | 150 |
| 主动动作倍率 | 90 | 140 | 60 |
| 尺度偏好：小/中/大/全下 | 5/4/1/1 | 3/5/3/2 | 6/3/1/1 |

正常/谨慎/施压模式分别为评分偏移 `0/-15/+15`、主动动作额外倍率 `100/85/115`。check 不附加人格倍率；模式不改变合法集或安全排除项。

最终 `S=clip(B+D+position+looseness+mode_offset-35*(m-1)-texture,0,1000)`。若 m=0 或行动者不应行动，输入失败，不借人数惩罚产生异常正偏置。

- 面对下注时，只从 GameState 的公开投入构造 `PotParticipant`，调用一次既有 `project_candidate_call(..., actual_call_amount)`；`eligible_pot` 为其中 caller 有资格的 contested/caller_recovery 层金额之和，排除无资格侧池和退给别人的金额。
- 价格特征 `price=floor(1000*A/max(A,eligible_pot))`，A 为实际跟注支付；无跟注时 price=0。该数只是支付与当前资格池的比值，**不等于 pot odds 已充分修正、盈亏平衡胜率或 CALL EV**，不扣回收冒充增量 EV。
- 跟注阈值 `Tc=(310 若 preflop 否则 350)+floor(450*price/1000)+25*r+depth`，其中 `depth=-40` 若 SPR≤1，`+25` 若 SPR≥6，其余 0。
- 价值主动阈值 `Tv` 按 preflop/flop/turn/river 为 `600/650/700/740`，再加 `25*r` 与上述 depth。
- 未乘人格倍率的被动权重：`F=max(0,Tc-S+160)`、`C=max(0,S-Tc+160)`；免费过牌权重恒为 200。只有 `can_fold/can_call/can_check` 为真的动作进入分布。
- 价值主动质量 `V=max(0,S-Tv+120)`。
- 非价值进攻质量 `U`：preflop 必须 r≤1、position≥0 且 B≥280；postflop 必须 r≤1，且有 D>0 或自身含 A/K（仅作粗粒度阻断提示，不称 range blocker 精确模型）。不满足为 0；满足时 m=1/2/3 时取 12/6/3，m≥4 为 0。无仍可应答的 live 对手也为 0。
- 人格之后质量为 `Wf=F*fold_multiplier`、`Wc=C*call_multiplier`、`Wcheck=200*100`；主动总质量 `Waggr=(V+U)*aggression_multiplier*mode_multiplier/100`。禁止动作质量为 0，不能通过 softmax、epsilon 或归一化重新抬起。
- 全部主动候选被排除时主动质量归零，剩余合法质量重新归一；有效的面对下注状态中 F/C 至少一项大于 0，有免费过牌则 check 正质量。若仍全部为零则显式内部错误，不任意选择动作。

这是**启发式参数初值**而非独立验证结果。尤其固定阈值可能被针对，混合带不等于不可剥削；后续报告必须检验大小注反应、深浅筹码行为和共享牌面弱点，不可只展示分布熵。

### 10.4 尺度生成、风险排除与量化

共至多 6 个最终动作：fold、call 或 check（后二者通常互斥），以及小/中/大/全下至多 4 个主动候选。若收到同时 can_bet/can_raise 或 can_check/can_call 等自相矛盾 LegalActions，明确失败。

1. 对应动作选 BET 或 RAISE，目标一律为**本街总额**；最终须落在合法端点内，不自行重演短码是否重开加注。`all_in_total=street_bet+stack`；不存在独立 ALL_IN 枚举。
2. 翻前尚无自愿加注时，小/中/大目标为 `ceil((5+2*limpers)*BB/2)`、`(3+limpers)*BB`、`(4+limpers)*BB`。这是名义目标，不认为历史盲注一定缴足。
3. 其他情况，令 `P=max(BB,pot+A)`，`A=actual_call_amount`（无跟注为 0）、`b=自己 street_bet`、`q=legal.call_amount`。小/中/大目标为 `b+q+ceil(P/3)`、`b+q+ceil(3P/4)`、`b+q+ceil(5P/4)`。这只是局面尺度特征，不宣称 side-pot EV；全下目标为 all_in_total。
4. 可实际被匹配的主动上限 `cap=b+E`；上界取 `min(legal_max,cap)`。若低于 legal_min，或 live=0，不生成主动候选。普通目标夹到合法有效区间；全下只在 all_in_total 不超过有效上限时生成，避免把未匹配的多余筹码算作有效压迫。
5. 将原始目标夹紧后按 `(type,amount)` 合并；合并时将对应尺度偏好相加。**风险过滤按最终实际金额判断**，不是按“小注”标签判断，否则短码夹紧会绕过保护。
6. 设该候选本次支付 `Dpay=amount-b`。若 `Dpay==自己stack`，或 `Dpay>3*max(pot,BB)`，标为危险候选，必须 `V>0` 且满足 `S≥850` 或 `SPR≤1 且 S≥550` 才保留，并**一律禁用 U**；不满足则删除。其余候选允许 V/U 共同贡献；U=0 不禁止正常价值下注。
7. 在保留且去重后的候选上取偏好总和 `Q=sum(q)`、`a=aggression_multiplier*mode_multiplier/100`。每个主动候选的原始质量唯一规定为 `q/Q * a * (V + (0 若危险否则 U))`。与被动质量共同归一；被禁用的 U 不补发到任何候选。全部普通候选时主动总质量等于 Waggr，不因候选数量增多而提高主动概率；全部危险候选时只有V贡献。Q=0 表示无主动候选。
8. 新策略内部 `MIXED_DISTRIBUTION_UNITS=1_000_000`，独立于训练产物的 `PROBABILITY_UNITS`。先精确有理数归一，乘单位取 floor，再按小数余数从大到小补齐单位；并列按 fold/check/call/bet金额升序/raise金额升序。零质量保持零，零单位项不抽到。
9. 抽样 `randrange(1_000_000)` 在上述规范顺序的累计区间选动作。输出 `MixedDistribution` 为冻结 Pydantic：版本、候选元组（受控动作、整数金额、非负整数 units），总 units 恰等于一百万；不对外暴露内部种子/人格/模式。

### 10.5 工作量和失败策略

- 每次特征工作上界：N≤9 的固定扫描，最多 47 次下一牌点数/花色集合检查、至多 2 次≤7张牌的 `evaluate_fast`、至多一次≤9人逐池资格投影、最多6候选。没有按筹码数、整手历史长度、模拟回合或对手牌组合展开的循环。
- 正常模式不开线程、不读网络/文件，不做全局缓存。输入摘要由成功动作增量维护，不把计算挪到未计时循环冒充便宜。
- 验证/生成错误在 apply 前失败；不回退到另一个未声明策略，不修改局面。端到端计时超 100ms 仍记为失败，即使最终动作合法；不靠墙钟改变抽样结果。
- 这并不保证任意机器、调度或超大整数必然低于 100ms。生产没有新增可强制中断同步 Python 的机制；若本机验证未达标，保持旧默认并修订方案，不能放宽硬预算。

## 11. 回归与有界评测方案（待预注册、待授权）

### 11.1 正常测试与质量实跑分开

正常 pytest 仅做有界单元/集成回归，不运行完整性能矩阵或对抗对局。API 测试使用现有一次性库机制或显式临时 `HOLDEM_DB_PATH`，不访问真实库；不加载 `holdem-campaigns`、不 import 训练器。

首次评测清单冻结前，把以下16类节点整理为确定的 fixtures，按2–9人**适用性矩阵**列明前置行动及期望分布关系，而不是自动搜牌直到得到“好看”结果：

1. HU盲位与N>2首位差异；2. 无人自愿加注的开池；3. limp后开池；4. 面对第一次加注；5. 面对连续再加注；6. 免费过牌；7. 顶对弱踢脚；8. 强口袋对子遇高公共牌；9. flop同花/顺子听牌；10. turn组合听牌；11. river错失听牌；12. 公共两对/顺子/同花的共享牌面；13. 一方已all-in、另两方仍可行动的底池；14. 短码CALL与无资格边池；15. 第三方不足完整加注后不重开原行动者加注权；16. 多个尺寸夹紧为同额。

第13–15类要求N≥3，N=2的三个槽标为 `structurally-not-applicable`，不伪造HU边池或把无人可应答冒充未重开；其余13类覆盖2–9，总计125个可行动节点、3个结构性不适用槽。HU的短码CALL及只有对手已all-in的节点另作正确性测试，不冒充上述三类。若某个其余槽无法构造，应在清单签收前解释并修订，不运行后删除。

牌型、风险特征、听牌、整数边界另以表驱动覆盖全类别（含A2345、公共绝对大牌、无效/重复牌），不把上述16类当作全部牌型测试。信息隔离测试必须含“先让另一个座位看过自己的底牌，再查询当前座位”，并覆盖多次分布查询不改变抽样和非法真人动作不污染摘要。

### 11.2 种子与清单身份

建议验证身份 `mixed-local-v1-validation`，独立于候选 A 的 campaign/evaluator；只作新对手验证，**不是授权标识的续用**。候选主种子值仅列现有的四个数 `1215 / 20260918 / 3311 / 7926`，不追加其他主种子；本轮未使用它们运行任何内容。即便数值重用，也必须获得新的产品验证运行许可，绝不重试对应的旧 A9 authorization。

域分离时消息包含验证身份、用途、人数、街、场景、座位/轮换号、对手族、块序号；派生流是清单内确定性分流，不是看结果追加seed。配对新旧策略时，牌堆与非焦点对手的初始随机流消息**均不含焦点arm或人格**；仅新焦点策略的流区分profile，旧焦点流固定，不随对照标签变更。这样旧arm重复是同一控制样本，不是额外证据。动作分叉可能导致对手后续随机消费不同，固定初始流不保证后续信息集一一配对，报告不得混淆。

冻结清单须包含：代码提交与策略配置摘要、每个 fixture 的确切牌/公开动作序列、场景排序、上述 seed 集合及派生规则、运行阶段/样本数/资源 envelope/停止条件、输出目录和报告格式。**当前文档未包含逐张牌 fixture 清单，也没有已签收的预算，因此只是一份有界方案，不是可立即执行的最终 manifest。** 这些机械明细由实现中的 fixture 定义给出、在首次实跑前只读核对并签收，不能在看过成绩后补写。

### 11.3 分布与风格矩阵

- 125个适用节点 × 3风格 × 3手模式，共1125份**直接分布**，不靠抽样估计已知概率；3个不适用槽单列，不进入分布分母。模式由内部测试接口显式指定，生产无此参数。
- 同节点按同模式比较风格，再比较对80/10/10模式权重边缘化后的分布；不可把抽到不同模式误归因于人格。
- 条件动作熵按类型合并units；尺度熵只在bet/raise正质量下按最终唯一金额计算；JS比较共同的 `(type,amount)` 并集，零概率按标准极限处理。这里为比较分布补齐数学支撑集，不是把抽象外局面补零冒充精确覆盖。
- 只有一个合法尺寸时标注“结构性单尺寸”，无主动概率时为“不适用”，不能算成失败或隐去。报告全部128个计划槽：125个节点的结果/异常和3个结构性不适用，不挑选高熵节点。
- 这组矩阵验证机制和差异，不是对手强度证明，也不是正常pytest默认做的大规模对局。

### 11.4 成本矩阵

- 沿用每个人数 10000 次、共 80000 次的基准量级，不把小规模标定替代正式口径。
- 每人数划为四街 × 三风格 × 三深度（名义 15/100/1000BB，SB/BB=5/10）的36格；按街、风格、深度顺序分配，前28格每格278次，其余8格277次，总数10000。格内轮换对应街的预冻结节点，不因不容易达到某条街而无限采样。
- 各格分别计时；合并只用于该人数的汇总。逐人数/逐街/逐风格/逐深度都有样本数、p50/p95/p99/max、>=100ms 计数，分位复用 `lookup_budget.py` 最近秩口径。已有 50/80ms 仅指导，非新门槛。
- **硬预算路径 `decision_path`** 从本次snapshot/合法动作读取开始，到脱敏、摘要附加/校验、分派、特征、分布、采样和最终整数候选校验结束、尚未apply为止。这是完整的单次Bot决策计算，不是lookup子段；>=100ms计失败。
- **另列执行路径** `engine_apply`（可能包括自动runout/摊牌）、`public_summary_update` 和本次完整 `bot_step`。后者从上述起点到apply/摘要更新完成，实报全部耗时，不把引擎结算擅自纳入或移出决策门槛。摘要增量维护开销不能隐去；若bot_step卡顿，即使decision_path达标也须报告。排除BOT_DELAY、HTTP传输和DB落盘的边界逐字段注明。
- 每次需要的fixture重放/引擎复位在计时外但计入总运行资源；不得复用已有分布结果。冷导入、建局、首手初始化另报，不能把热查询数字称为完整启动延迟。
- 另列2–9人的短码、长历史摘要、64位筹码合法端点小型测试（每人数每类10次，共240次）为补充；其中短码在HU为不足额CALL，N≥3为带边池的不足额CALL，分别标注，不能声称HU也有无资格边池。与主矩阵分开，不声称覆盖无上界整数或全部实际长局。长历史以固定256个合法事件为上限，无法到达列未覆盖，不自动续跑。

### 11.5 抗针对试验：小规模、全披露

第一批仅提供有界对照，不承诺足以判断长期不可剥削。每手重置到100BB、盲注5/10、不设抽水，不用真人历史和真实库。

- 人数 2–9；焦点策略三风格分别评测，对照 arm 为未改的 `heuristic@1`；其余座位为四个同质对手族：旧 `random@1`、旧 `heuristic@1`、被动跟注探针、固定施压探针。
- 被动跟注探针：优先check，否则call，否则fold；不会下注。固定施压探针：若有can_bet/can_raise，令 `b=自己的street_bet`、`q=call_amount`、`A=actual_call_amount`，目标 `b+q+max(BB,pot+A)`，夹到对应LegalActions的闭区间，提交BET/RAISE；不套新Bot的人格、价格评分、有效筹码cap或危险尺度过滤。无主动动作则check，再call，再fold；没有任何合法候选即测试错误。它们是固定机械探针，**不是best response**，只在测试侧，不注册到产品。
- 4 主种子 × 3 焦点风格 × 4 对手族 × 2 arm × 每人数 N 个相对座位轮换 × 每格1手，合计 `4*3*4*2*(2+3+...+9)=4224` 手。轮换在标准 BTN=0 的规范座位系中将焦点置于每个相对座位；两 arm 同格使用相同合法初态与牌堆派生流。旧 arm 在不同焦点风格标签下的重复是配对控制，不计为独立新增证据。
- 每手最多256个自愿行动，达到上限则该手截断、不补终局、不估算赢输。任何截断均按人数/对手/arm 报告，不能只报告完成手数；对应比较标为不完整，不能签收为全覆盖。
- 按人数/风格/对手/主种子报告终局净筹码、以固定BB换算的bb/100及新旧配对差、VPIP/PFR/主动动作率/尺度分布。先按同一主种子内所有轮换聚合，再报四个主种子块的均值、样本标准差、最小最大值；不把同块各手当独立 seed。
- 本批只有4个预设主种子块，**不出具具有总体覆盖承诺的95%置信区间**；报告明确 `interval_status=not-estimated-small-fixed-seed-set`，不靠 bootstrap 重采样制造证据量。若用户需要统计推断，另行预注册更合适的设计，不擅自扩大本批。
- 泄漏/机械弱点用全部节点联合表报告：尺度对应牌力分档、过度弃牌、无条件跟注、多方过度进攻，以及公共大牌共享弱点。聚合相关性不是已证明泄漏对手底牌，异常应追到特征与分布再定性。

### 11.6 资源 envelope、标定与停止

以下仅为**待批准上限提案**，不是新增可用预算，也不是耗时预测。不得据此扩张此前任何已批准预算：

| 阶段 | 样本上限与门禁 | 时间/资源提案 |
|---|---|---|
| A 有界标定 | 主成本矩阵每人数的36格各取首个样本（288次），每人数每个补充类取首个样本（24次）；对抗取第一个主seed、tight焦点、首轮换下全部8人数×4对手族×2arm（64手）。全部保留，属于正式清单的分层子集，不作为独立质量结论 | wall/CPU各不超过120秒，单进程RSS≤1GiB |
| B 剩余正式矩阵 | A实测后披露分街/深度/风格/对手族/arm成本及预计总成本，由用户确认仍在既有可用预算内才继续；A样本不重跑、不替换 | A+B累计wall/CPU各不超过1800秒，RSS≤1GiB，保留文件≤100MiB，单CPU进程，不并行 |

这些界限比既有资源上限更紧，不能被理解成已获30分钟额度。A覆盖昂贵路径但单格样本仍少，单位耗时外推只能作估计，不是最大时间保证；需计入fixture重放、冷启动、旧heuristic和结算成本。A不足以预计B，或预计/实际超界时停止，不自行扩容、补seed或无限重跑。资源监督是本机合作式/采样式检查，不称为内核隔离；同步调用不能被合作式计时即时打断的局限必须披露。

- 任何合法性/信息边界/摘要一致性错误立即停止该轮；保留已完成计数与错误，剩余为not-run。
- 任何新Bot的 `decision_path>=100ms` 样本立即标为性能失败并暂停进入后续阶段；不删除“调度噪声”、不自动复测。旧对手和执行/结算路径耗时另报，不把其延迟伪归因给新Bot。若用户另行授权诊断续跑，须保留初次失败并记录原因，不重用训练authorization。
- 预算、动作上限、输出大小、RSS任一触发停止，报告 `stopped-*`，不是“完成”。未完成矩阵不能作为全部满足成本要求的证据。
- 默认测试不触发 A/B。实现 opt-in 验证入口必须显式接收已冻结清单和允许执行的阶段，默认禁止；不访问或修改旧 campaign 目录。
