# 22 训练前置核验：短码 CALL 的实际成本与逐池资格

> 日期：2026-09-16。代码基线：`7b2cddbc8ab9e1750e4103e24eab3cd1253a23a4`（`fix: count all-in opponents in postflop equity`）。
>
> 状态：**方案 B 的事实字段/展示修复与方案 C 的纯逐层资格投影均已实施并通过验证；逐池收益 EV 未实施。** 本文记录本轮短码 CALL 的事实、影响、确认实施及遗留；不重写 `20`、`21` 或既有复盘权威文档。

## 1. 本轮目标、基线与边界

本轮只核验：短码玩家面对下注时，完整欠注差额、实际 CALL 支付，以及 CALL 后可争夺各层池额是否被当前策略与复盘混为同一个“价格”。

开始时 `master...origin/master` 与工作区均干净，`HEAD` 为上述基线。`21` 的方案 B 仍保持：翻后 equity 的竞争人数纳入所有未弃牌座位，**本轮不回退，也不把它称为完整多人 EV 修复**。

本轮不做：CFR、trainer、人格、位置策略、DeepSeek、UI 人数/布局变更、引擎结算行为变更、保守参考保护回退，或真实历史写入。`backend/tools/inspect_hand.py` 保留且未作为批量统计入口；没有启动应用，也没有调用会推进 Bot 的 `GET /games/{id}`。

需要区分的三个事实如下：

| 事实 | 定义 | 当前可信来源 |
|---|---|---|
| 完整欠注差额 | \(C=\text{current_bet}-\text{street_bet}\)，即补齐当前下注层级所欠金额 | `PokerEngine.legal_actions().call_amount` |
| 本次实际支付 | \(A=\min(C,\text{stack})\)，短码时即全下 | `PokerEngine._apply(CALL)` 的实际 `commit`；历史 `CALL.amount` |
| 假想 CALL 后可争夺的池额 | 用动作前每座位 `total_committed`、`folded` 与明确假设“当前座位支付 \(A\) 并 CALL”分层得出的、该座位在其中具资格的池层 | 当前没有公开、无副作用的生产投影接口 |

结论先行：`call_amount` 当前且应继续表示 **完整欠注差额**，不是实际支付。短码场景应新增、并行表达 `actual_call_amount`；不能把 `call_amount` 全局改成 \(A\)。而“正确行动价格”不是一个可由 \(A/(P+A)\) 单独表达的标量，需按当前玩家可争夺的池层、各层竞争集合、平局份额及后续行动假设计算。

## 2. 代码事实与合法最小复现

### 2.1 当前规则已经分开动作层与实际扣款

`PokerEngine.legal_actions()` 以 \(C\) 生成 `call_amount`，只要 \(C>0\) 就允许 CALL；能否再加注则以 `street_bet + stack` 是否还能超过当前下注层级判断。`PokerEngine._apply()` 对 CALL 才计算 \(A\)、扣减筹码、更新投入，并在余额归零时标记 `all_in`。因此：

- `call_amount` 是“补到当前下注层级的完整缺口”；
- 历史动作中的 `CALL.amount` 是实际支付额；
- 短码 CALL 合法，即使它不能补齐 `current_bet`；
- 全下玩家随后不再阻塞行动轮，但仍可按其投入参与结算。

`_first_active_from()`、`_num_can_bet()` 与 `_betting_round_complete()` 用的是行动资格：

```text
can_act = not folded and not all_in
```

`_settle_showdown()` 则按每个 `total_committed` 层级切池；某层的资格为“在该层有投入且未弃牌”。全下者仍可能在主池或较低边池中竞争；弃牌者的投入是死钱、没有争池资格：

```text
eligible_for_layer = contributed_to_layer and not folded
```

这两种资格本就不应合并。方案 B 修正的是翻后随机范围中的“仍争任一池者”人数，不能得到“当前新增筹码可争哪一层”的答案。

### 2.2 `call_amount` 不应改成实际支付

`call_amount` 的完整差额语义被多个正确依赖点使用：

| 消费面 | 依赖完整差额的原因 | 不能改成实际支付的原因 |
|---|---|---|
| 引擎合法动作与加注区间 | 判断是否面对下注、能否加注、最小/最大 raise-to | 短码实际支付不能代表当前下注层级 |
| 翻前策略 | 中牌/投机牌的价格门槛、小对子隐含赔率 | 对一个远大于大盲的加注，短码余额再小也不是 limp |
| 翻后策略 | 判断面对下注、构造加注目标 | `street_bet + call_amount` 才是完整 call-to 层级 |
| 复盘保守收窄与 mistakes | 现有价格余量、`bad_call`、`bad_fold` 的原始下注压力 | 不能因余额低就绕过既有保护或 limp 豁免 |
| API 与牌桌按钮 | 当前“跟注 X”表达完整欠注，CALL 请求本身不携带金额 | 客户端不应自行计算引擎权威实际扣款 |

特别地，翻前 `cheap_preflop = to_call <= big_blind` 必须继续以 \(C\) 判定。若面对大加注但余额小于一个大盲，\(A\) 很小并不表示这是补盲或 limp，不能获得该豁免。

`LegalActions`、`LegalActionsView` 与 `GameTable.vue` 目前只下发/显示 `call_amount`；玩家视图虽含 `stack`，但不应要求客户端推导规则。`DecisionReview` 当前只含 `to_call`、`pot_odds`、`call_ev`。另一方面，历史动作已经记录实际 CALL 支付，不过没有显式保存动作前的完整欠注额，旧手牌需靠引擎重放恢复。

### 2.3 三个由引擎正常推进的最小复现

以下场景均通过 `PokerEngine.start_hand_with()` 和正常 `apply_action()` 构造，不伪造快照；固定底牌仅为让引擎能完整运行，诊断不把对手暗牌或未来公共牌作为策略输入。

| 场景 | 动作前公开状态 | 合法 CALL 后的事实 | 说明 |
|---|---|---|---|
| 单挑，对手已全下 | 翻牌，`pot=120`，短码 seat 1：`C=100`、`stack=90`，对手未弃牌且全下 | `A=90`；双方累计投入变为 `110/100`；两人均全下；终局筹码守恒 | CALL 的完整压力为 100，现金风险只有 90；对手仍争夺与短码相匹配的层，超出短码覆盖的部分不能视为短码可赢收益 |
| 三人，全下者与可行动者共存 | 翻牌，短码 seat 1：`pot=130`、`C=100`、`stack=60`；seat 0 已全下，seat 2 尚可行动 | `A=60`，seat 1 全下；下一同街行动座位是 seat 2 | 不能把全下 seat 0 当成不存在，也不能把 seat 2 后续可能投入的边池预先算给 seat 1 |
| 四人，弃牌死钱与不可争边层 | 翻前，短码 seat 2：`pot=215`、`C=90`、`stack=60`；seat 1 已弃且留有 5，seat 0/3 各投入 100 | `A=60`，seat 2 累计投入 70 并全下；其可参与的低层含 seat 1 的死钱，但高于 70 的 `0/3` 对抗层不属于 seat 2 | 死钱增加可争夺层金额，但弃牌者不是 equity 对手；短码也不能争自己未覆盖的后续边层 |

三个场景均完成至终局并核对筹码总额与 `last_net` 之和为零。它们只证明规则执行与资格的差别，不为任何范围、权益或行动 EV 作结论。

### 2.4 当前实现为何不足以给出短码 EV

翻后 `HeuristicStrategy._postflop_distribution()` 当前用：

\[
\text{pot\_odds}_{\text{current}}=\frac{C}{P+C}
\]

其中 \(P\) 是已经包含对手下注在内的当前总池。`hand_review._analyze_decision()` 也以同一 \(C\) 输出 `to_call`、`pot_odds` 与：

\[
\text{call\_ev}_{\text{current}}=q(P+C)-C
\]

这里的 \(q\) 又是“面对全部未弃牌对手”的单一随机范围 equity。无短码、无边池且后续不再改变竞争集合时，这是一种已知的单池近似；短码时它不再表达实际现金支付，也不是逐池收益。

若只把两个公式的 \(C\) 替换为 \(A\)，所得 \(A/(P+A)\) 最多是“实际支付占当前总池加支付额的比例”，仍错误地把以下内容混在分母中：

1. 当前玩家无资格参与的高层边池；
2. 只有当前玩家有资格、实质上应回收而非竞争获胜的未匹配层；
3. 后续仍可行动座位尚未知的跟注、加注、弃牌及由此改变的边池；
4. 每层不同的竞争集合与多人平局份额。

因此，对短码 CALL 的正确表达应分层：

- **动作/现金成本**：本次最多支付 \(A\)；
- **原始下注压力**：完整欠注仍为 \(C\)；
- **逐层可争收益**：明确候选 CALL 后，逐层标出贡献者、未弃牌资格者、当前座位是否有资格、是否真正有对手；
- **EV**：只有在固定后续行动情景 \(\sigma\)、范围/权益模型和平局分配后，才可计算：

\[
EV(\text{CALL}\mid\sigma)=R_h+\sum_{\ell\in\text{contested}(h)}E[\text{share}_{h,\ell}\mid\sigma]-A
\]

其中 \(R_h\) 是明确的无对手回收额，不是“可赢收益”；当前玩家无资格的层贡献为零。不同池层的 `share` 需按各自 eligible 集合结算，三人及以上平局不能继续套用现有 `equity()` 固定的“平局半胜”近似。

## 4. 行动差额、实际支付、争池资格与逐池收益的语义对照

| 概念 | 应保留的语义 | 在短码节点中的可用性 | 不能替代的概念 |
|---|---|---|---|
| `call_amount` / `to_call` | 完整欠注差额 \(C\) | 正确表达面对的下注层级、原始压力、raise-to 与翻前豁免边界 | 现金实际支付与逐池收益 |
| `actual_call_amount` | 本次实际支付 \(A\) | 正确表达 CALL 的最大现金流出、是否因 CALL 全下 | 完整下注压力、可争池额或 EV |
| 当前总池 `pot` | 已投入筹码总和 | 可展示全局桌面池量 | 当前玩家可争的净收益 |
| 候选 CALL 后逐池投影 | 每层金额、contributors、eligible、当前玩家资格、无对手回收/不可争层 | 可解释短码到底覆盖哪些层 | 对未来行动、范围、平局与权益的完整预测 |
| `call_ev` | 仅在单池、竞争集固定、权益定义匹配时才可作为近似 | 当前短码/边池场景不应继续显示为完整 CALL EV | 任意行动的精确 EV 或 GTO 结论 |

当前边池结算逻辑内联在 `_settle_showdown()`，它会修改筹码、写入结果并依赖终局状态，不能拿来查询决策期池额。现有 `GameState` 虽已具备生成纯投影所需的公开字段（每座位 `folded`、`all_in`、`stack`、`street_bet`、`total_committed`），却没有该投影 API。

即使先得到层级资格，完整逐池 EV 仍至少需要：

1. 每层不同 eligible 集合下的权益与多人平局份额；
2. 对手范围模型，而非真实底牌；
3. 对本街尚待行动者及后续街下注/弃牌/加注的明确策略假设；
4. 未匹配超额投入与无对手回收的单独处理；
5. 同一公共牌下各层结果相关的联合采样，以及固定 seed 的可复现性。

所以方案 B 的“全下未弃牌者参与翻后竞争人数”仍然有价值，但它只是主池竞争集合的修正，不是逐池货币 EV。

## 5. 修复候选、最小推荐、取舍及涉及层

### 5.1 候选

| 方案 | 内容 | 可安全解决 | 仍未解决 / 代价 |
|---|---|---|---|
| A. 保持现状，仅记录 | 不改代码 | 不引入行为回归 | 短码时策略/复盘继续把完整差额展示成单池成本，UI 不显示实际支付 |
| B. 并行暴露实际支付 | `LegalActions` 增加 `actual_call_amount`，API 透传；UI 显示“补齐差额 C，实际全下 A”；复盘新增实际支付与短码标记 | 规则、API 与展示可如实区分 \(C\)/\(A\)，不改引擎结算和 Bot 行为 | 不能给出正确逐池 EV；复盘既有 `pot_odds`/`call_ev` 仍须明确降级或隐藏 |
| C. 纯逐层资格投影 | 在 `poker/` 增加无副作用、N 人的候选投入层投影；复用/回归验证与结算分层一致 | 能展示可争层、死钱、无资格层、无对手回收；为训练输入和后续 EV 奠基 | 需要明确输出模型与原结算的行为回归；仍没有范围、权益、平局与后续行动 EV |
| D. 逐池收益估值 | 在 C 之上，按每层 eligible 集合做联合采样、平局分配和固定后续策略情景 | 才能讨论某个明确模型下的 CALL 货币 EV | 改动跨 `poker/strategy/analysis`，需范围与后续行动模型，实时成本也要重测；不属于本轮默认实现 |

### 5.2 最小推荐：先 B，C 另作下一切片

推荐将 B 分成两个不可混淆的声明：

1. `call_amount` / 复盘 `to_call` 保持完整差额语义，名称和原有翻前/加注判据不改；新增 `actual_call_amount` 与 `is_short_all_in_call`（或等价明确字段）。这项是事实投影，不改变 CALL 的服务端权威执行。
2. 短码时复盘不应把单一 `pot_odds` 或 `call_ev` 宣称为完整结论。理想展示是：完整欠注、实际支付，以及“逐池 EV 未建模”的明确状态；若保留 `A/(P+A)`，只能命名为现金支付比例，不能命名为赔率或 EV。

B 不改变 `HeuristicStrategy` 的实盘动作、`_conservative_distribution`、`_detect_mistakes`、limp 豁免或既有保护。尤其不能把所有 `call_amount` 使用点替换为 `actual_call_amount`。在 C/D 未定义之前，直接把翻后策略赔率改为 \(A/(P+A)\) 会制造另一种错误的动作阈值；把复盘 mistakes 改成此值也会未经证据改变教学评价。

C 应作为下一独立确认切片：在 `poker/` 抽取小型纯函数/值对象，输入公开快照和候选实际投入，输出分层 contributor/eligible/当前座位资格及“对抗层、无资格层、无对手回收层”。它不能依赖 `api/` 或 `analysis/`，也不能调用或替代有副作用的 `_settle_showdown()`。原结算结果必须以回归测试证明不变。

### 5.3 层级影响

| 层 | 当前状态 | B 的影响 | C/D 才处理的内容 |
|---|---|---|---|
| 规则引擎 | CALL 实际扣款和结算正确；无纯投影 | 仅增加决策前实际支付字段 | 抽取逐层只读投影，不改结算结果 |
| 实盘 heuristic | 翻前/翻后都读完整差额；翻后单池赔率对短码不完整 | 不改行为 | 按逐池收益与后续模型重新定义候选行动价值 |

### 7.5 方案 C 的逐层资格能力

`poker/pot_projection.py` 提供两类无副作用计算：

1. `project_pot_layers()`：只按公开累计投入与弃牌状态切层，输出每层金额、贡献者、未弃牌资格者和无人资格时的退款；`_settle_showdown()` 与候选 CALL 共用它，防止分层规则漂移。
2. `project_candidate_call()`：只在当前行动者的累计投入上增加 `actual_call_amount`，再将每层标为：竞争层、仅当前行动者有资格的确定回收层、仅其他人有资格的单资格层，或无人有资格的退款层。

`PokerEngine.candidate_call_pot_projection()` 仅在 CALL 合法时返回该投影；它不修改 `stack`、`street_bet`、`total_committed`、`all_in`、行动顺序、历史、公共牌或结算结果。投影只表达当前已公开投入下的资格，后续仍可行动者的实际跟注、加注、弃牌和新边池不被预先假定。

该能力暂未接入 API、牌桌或复盘展示，也不计算权益、赢家、平局份额或行动 EV。
