## 1. 本轮目标、基线与边界

本轮核验的问题是：`poker.equity.equity()` 对任意平局固定计入半个胜场：

\[
q_{legacy}=\frac{wins+ties/2}{samples}
\]

当 Hero 与两名或更多对手并列最强时，固定的 `1/2` 是否错误地代替了单层真实名义份额 `1/k`；已有逐层资格能力能解决什么，又不能解决什么。

结论先行：**是，三人及以上同级赢家时固定 `ties / 2` 高估了该固定竞争集合下的名义份额。** 但这不意味着只需把一个常数改为 `1/3`，更不意味着已经得到边池 CALL EV 或 GTO 修复。

本轮严格区分：

1. **并列最强事件**：Hero 是否达到该层所有 eligible 玩家中的最高牌力；
2. **单层实际名义份额**：Hero 是同级赢家之一时，按该层同级赢家人数均分；
3. **最终整数派彩金额**：余数筹码按现有座位顺序分配；
4. **跨层货币期望收益**：需要层金额、逐层资格、联合 runout、范围和后续行动假设，不能由单个平局份额推出。

`21` 的方案 B 保持有效：翻后随机竞争人数仍纳入所有未弃牌座位，包括全下者。`22` 的完整欠注差额 `C`、实际支付 `A` 和无副作用逐层资格投影也保持不变。它们都不是逐池收益模型。

## 2. 当前实现的准确语义

### 2.1 `equity()` 目前计算的量

`backend/app/poker/equity.py::equity()` 为每个样本：

1. 对 `num_opponents` 个随机对手发底牌并补齐公共牌；
2. 计算 Hero 牌力；
3. 只保留所有对手中的最高牌力；
4. Hero 独赢记 `1`，Hero 与最高对手同级记 `1/2`，否则记 `0`。

因此其当前精确语义是：

\[
E\left[\mathbf{1}_{Hero\;strictly\;wins}+\frac12\mathbf{1}_{Hero\;ties\;for\;best}\right]
\]

它不是严格的多人底池期望份额；也不统计有几名对手与 Hero 同级。`num_opponents <= 0` 返回 `1.0` 是“没有竞争者”的泛用边界，本轮没有理由改变它。

在单挑中，平局只有两名同级赢家，`1/2` 正确。三人及以上时，只有恰好两名同级赢家的样本仍正确；Hero 与两名对手三人平分时，当前函数仍给 `1/2`，正确的名义份额应为 `1/3`。

### 2.2 当前消费者与兼容代价

- `strategy/heuristic.py`：翻后把全部未弃牌对手数传给 `equity()`，以结果驱动价值下注、加注、跟注和空气分支。直接修改返回语义会改变受影响实盘节点的阈值结果。
- `analysis/hand_review.py`：以固定 seed 调用 `equity()`，展示 `equity`，计算非短码单池近似 `call_ev`，并驱动参考分布和 mistakes。直接替换会改变历史动态重评结果，不能静默称为同一参考版本。
- API/前端：`DecisionReview.equity` 以“胜率”呈现，`bot_distribution`、`bot_action`、`call_ev` 和 mistakes 都可能间接受影响。
- 引擎结算：**不使用 `equity()`**。`_settle_showdown()` 已按每层 eligible 玩家实际牌力选择赢家、均分并处理余数，本轮不应修改它。

所以，当前 `equity()` 既不是逐层 share，也不是逐池货币 EV；它是“对一个单一、固定、随机竞争集合的旧式静态摊牌分数”。

## 3. 正确的逐层定义

给定一个固定池层 \(\ell\)：

- `eligible_seats` 为 \(E_\ell\)；
- \(W_\ell\subseteq E_\ell\) 为该层最高牌力的同级赢家集合；
- \(P_\ell\) 为层金额。

### 3.1 事件、名义份额与整数金额

| 概念 | 定义 | 不能混同为 |
|---|---|---|
| 独赢事件 | \(Hero\in W_\ell\) 且 \(|W_\ell|=1\) | 平局事件 |
| 至少并列最强事件 | \(Hero\in W_\ell\) 且 \(|W_\ell|\ge2\) | 固定 `1/2` 的价值 |
| 名义份额 | Hero 不在 \(W_\ell\) 时为 `0`；否则 \(1/|W_\ell|\) | 整数筹码占比 |
| 最终派彩 | \(P_\ell\) 先整除 \(|W_\ell|\)，余数再按既有座位顺序分发 | 概率或 equity |

例如：

- 单挑平局：\(|W_\ell|=2\)，名义份额为 `1/2`；
- 三人平局：\(|W_\ell|=3\)，名义份额为 `1/3`；
- 四人平局：\(|W_\ell|=4\)，名义份额为 `1/4`。

当前结算的整数规则是：先给每位赢家 `amount // winner_count`，再将余数按赢家座位号升序分给前若干人。这是确定性派彩规则；它不应反向改写 Monte Carlo 中的概率份额。

### 3.2 跨层货币收益不是单一 share

在给定范围、联合 runout 和固定后续行动情景 \(\sigma\) 后，才可以讨论类似：

\[
EV(\mathrm{CALL}\mid\sigma)=R_h+E\left[\sum_{\ell\in contested(h)}S_{h,\ell}\mid\sigma\right]-A
\]

其中 \(R_h\) 是 `CALLER_RECOVERY` 这类确定回收，\(S_{h,\ell}\) 是该层最终整数派彩，\(A\) 是实际支付。该式仍缺范围和后续行动模型；不能以 `1/3` 直接替换现有单池 `call_ev`，也不能将其称为完整 EV 或 GTO。

## 4. 合法最小复现

所有复现均通过 `PokerEngine.start_hand_with()` 和正常 `apply_action()` 推进，不伪造快照；固定 seed，筹码均守恒。

| 场景 | 结果 | 结论 |
|---|---|---|
| 2 人、公共牌皇家同花顺 | `equity(..., 1)=0.5`；引擎将金额 4 分为 `2/2` | 单挑平局的 `1/2` 正确，不能全局替换为 `1/3`。 |
| 3 人、同一公共牌皇家同花顺 | 当前 `equity(..., 2)=0.5`；引擎将金额 6 分为 `2/2/2` | 固定平局分数与单层名义份额 `1/3` 不同。 |
| 4 人、三位未弃牌同级赢家且一位弃牌死钱 | 层金额 8 的实际 shares 为 `{0:3, 1:3, 2:2}`；下一层金额 6 为 `2/2/2` | `1/3` 是概率名义份额；多出的两枚是整数余数，不可混入 equity。 |
| 4 人、短码全下者、弃牌死钱、同一 runout | 主层金额 12：三人平分 `4/4/4`；边层金额 12：两人平分 `6/6` | 同一 runout 不同层的 eligible / 同级赢家人数不同，不能用一个全局 share。 |
| 4 人、短码候选 CALL | `C=98`、`A=78`；候选层 eligible 依次为 `(0,1,2,3)`、`(0,1,3)`、`(0,3)`，当前行动者仅在前两层 eligible | 全下者只在其覆盖层参与；当前行动者无资格的高层不能进入其 share 或收益。 |
| 9 人、无短码、公共牌皇家同花顺 | 金额 18 分为九份各 2，所有座位净额 0 | 引擎按 N 人工作；现有历史没有 6–9 人样本，不能将五人历史外推为九人生产证据。 |

这些复现还确认：`CALLER_RECOVERY`、`OTHER_UNCONTESTED` 和 `NO_ELIGIBLE_RETURN` 都不是“多人平局份额”。前者是确定回收，后两者分别是当前行动者不可争层和无人资格退款层。

## 5. `PotLayer` / `ProjectedPotLayer` 的能力边界

`poker/pot_projection.py` 已完成的事情：

- `project_pot_layers()` 用公开累计投入和弃牌状态切层；
- `eligible_seats` 排除弃牌者、保留未弃牌全下者的覆盖层；
- 死钱保留在 `amount`，但弃牌者不进入 `eligible_seats`；
- `project_candidate_call()` 仅为当前 CALL 加入实际支付 \(A\)，不修改引擎；
- `ProjectedPotLayer` 区分 `CONTESTED`、`CALLER_RECOVERY`、`OTHER_UNCONTESTED` 与 `NO_ELIGIBLE_RETURN`；
- `_settle_showdown()` 复用同一纯分层计算，实际赢家和整数 shares 已与其一致。

它尚不能提供：

- 某层赢家、同级赢家人数或 Hero share；
- 对手范围、隐藏底牌或未来公共牌；
- 本街待行动者未来的 CALL/RAISE/FOLD；
- 跨层联合 runout 的货币期望；
- `CALL`、`FOLD`、`RAISE` 的完整行动价值。

因此，资格投影可以成为未来逐层 share 采样的**公开输入**，但只能使用动作前公开投入、弃牌状态、当前行动者实际支付和当时已公开公共牌。不得把后续历史动作、最终边池或真实底牌倒灌到决策输入。

## 7. 影响分析

| 层 | 当前影响 | 未经授权不得做的事 |
|---|---|---|
| `HeuristicStrategy` | 多人随机样本中的平局得分偏高可能跨越现有 `0.70`、`0.90` 或赔率阈值 | 不直接替换其 `equity()` 输入或重调阈值；单一 pooled share 仍不是边池 EV。 |
| 复盘展示 | `equity` 以“胜率”展示；多人平局时并非严格静态名义份额 | 不把新 share 静默塞入既有字段，也不把它改称 CALL EV。 |
| 参考分布 / 保守收窄 | 基线分布和保守参考都消费现有估值；mistakes 也依赖同一数字 | 不删除或放宽弱踢脚、被压制对子、强听牌余量、limp 豁免等保护。 |
| `call_ev` | 仅为既有单池、固定竞争集合近似；短码已对外隐藏 | 不因本轮把其扩展为边池或多人完整 EV。 |
| API | 当前是兼容的 `equity: float` 与既有复盘字段 | 不新增或改名字段，除非先定义旧值、新静态 share 与版本语义。 |
| 训练输入 | 将来应携带每层公开金额、eligible、当前行动者资格与确定回收/退款状态 | 不传真实对手底牌、未来牌、未来动作或终局层。 |

## 8. 修复候选与推荐

| 方案 | 内容 | 能安全解决 | 仍不能解决 / 代价 |
|---|---|---|---|
| A. 仅记录与测试 | 保持生产行为，锁定复现、语义和结算回归 | 防止误把 `1/2` 当通用多人份额 | 不提供新的静态 share 能力。 |
| B. 新增 share-aware 静态采样原语 | 在 `poker/` 新增显式命名、seed 可注入的能力；每个样本统计 Hero 同级赢家人数，累加 `1 / winner_count` | 固定随机竞争集合下的单层名义份额；可同时报告独赢率、并列事件率和 expected share | 范围、边池货币 EV、未来行动和整数余数。 |
| C. 直接改现有 `equity()` | 将 `ties / 2` 改为按同级赢家人数均分 | 同 B 的静态份额正确性 | 所有策略、复盘、API 语义会静默漂移，需要逐消费者验收和版本化。 |
| D. 仅展示资格 | 基于已有投影解释哪些层可争、不可争或确定回收 | 可解释性 | 不显示收益，不修改权益或动作价值。 |
| E. 逐池收益模型 | 联合 runout、逐层 eligible、平局分配、范围和固定后续行动 \(\sigma\) | 才能讨论模型条件下的 CALL 货币 EV | 不是完整 GTO，且跨 `poker/strategy/analysis`，需性能与信息边界验收。 |

**当前最小推荐：保持生产 `equity()` 不变，后续若获授权实施方案 B。**

推荐 B 的边界：

- 新原语名称应显式表达“固定竞争集合、随机范围、静态摊牌名义份额”，不要复用含混的“完整 equity”；
- 每个样本统计全部对手牌力；Hero 独赢记 `1`，与 \(k\) 名对手同级记 `1/(k+1)`；
- 保留 `equity(0) == 1.0`；所有随机源继续由调用方注入；
- 初始不替换 `HeuristicStrategy`、复盘 `equity`、`call_ev`、mistakes、API 或 UI；
- 新能力只表示单一 pooled 竞争集合，不读取真实暗牌，也不把 `ProjectedPotLayer` 的资格误说成收益。

不推荐现在直接实施 C：虽然数值更接近“静态 share”，但会悄然改变现有策略阈值、参考分布和历史复盘输出；而它仍无法处理一个 CALL 同时面对 `(3,3,2)` 等不同层资格的情况。
