## 3. 为什么必须预注册（问题陈述）

### 3.1 现制：质量没有冻结门槛，只有用户签收

`docs/53` §7.2 与 §11.7 已把签收方式写死：「正确性和成本满足已冻结要求后，质量仍由用户根据完整报告签收；未签收不切新默认」。`docs/39` §3.1 同时冻结了门槛的**地位**：门槛只入库不启用，判定函数**不得**输出「合格/不合格/通过/达标」。

结论：当前**不存在**任何可用于质量判定的已签收判据。`docs/53c` 的签收结论（「机制与可运行性通过；质量结论未获支持」）正是这一状态的直接结果——判据是「已冻结读数是否支持正向结论」，而全部读数方向一致地不支持。

### 3.2 已看过的读数全部是开发证据

`docs/53` §13.2 冻结的纪律：**已看过的评测结果属于开发证据，不能反复调参后把同一集合当成独立质量验证；新验证样本和运行仍需预注册及授权。**

据此逐项记账（本文件不改写这些含义）：

| 读数 | 性质 | 为什么不能当独立验证 |
|---|---|---|
| v1 的四份回执 | 首期标定 | 已签收为「机制通过、质量未获支持」 |
| v2–v5 的阶段 A/B/补算 | 开发性对照与自定标定 | 同一 125 节点、同一四个主种子（`1215 / 20260918 / 3311 / 7926`），且本轮调参直接以这些读数为目标 |
| `54k` 的选参扫描 | 只读重算 | 偏移为零时与正式分布逐位一致，属同集合内的方法验证，不是新样本 |
| `54k` 的冻结节点预测 | 推算 | 「估算不是读数」已在 `docs/54h`/`54j` 被实证（弹性估算偏差 41%） |

`docs/54m` §9 已自行声明：「不得把 T1 命中或目标带命中表述为对手强度认证：两者都是自定的标定口径」。

### 3.3 「独立」在本项目中的可操作定义

多人无限注德州扑克没有可得的精确 exploitability（`docs/20` §6.2）。因此本项目的「独立质量验证」只能定义为**样本与口径的独立**，不能定义为机构独立或理论最优：

| 维度 | 本项目的可操作要求 | 做不到的 |
|---|---|---|
| 样本 | 被测节点集与主种子集**均与已看过的集合正交** | 无法证明「不存在漏洞」，只能说「本样本集上未观察到」 |
| 口径 | 指标、分母、判定规则在被测样本产生**之前**冻结 | 无法给出真实 EV / GTO / NashConv / exploitability 上界 |
| 执行 | 同一实现方执行，并在回执中**如实标注该限制** | 「独立」**不指**第三方机构复核 |

**必须如实记账的一条**：本文的「独立」是**样本与口径独立**；执行方仍为同一实现方。任何据此产生的结论都不得表述为「第三方独立复核」。

### 3.4 本预注册要解决的问题

1. 让「质量签收」从「看完报告凭方向判断」变成「按预先冻结的判据判定」；
2. 让判据在读数产生之前固定，从而阻断「调到有利结果再换分母」；
3. 把 `docs/53` §7.2 已列为**必做**的「抗针对验证」从机械探针升级为可判读的检验，并明确其结论边界。

## 6. 样本独立性口径（本预注册的冻结项）

### 6.1 节点集

1. 新节点集必须**与现有 125 个可行动节点互不相同**（不得复用任一节点的同牌面同行动线）；
2. 类别配比与规模在实施时按**冻结规则机械生成**，机械明细在运行前随清单一起冻结；
3. **不得按 `@5`（或任一版本）的读数挑选节点**——否则构成「仅在被测策略表现不佳处取证」的反向挑选，违反 `docs/20` §6.1 第 2 条「候选域不得自证」；
4. 按 `docs/20` §6.1 的既有要求，新节点集须覆盖并**分别报告**：强牌保护、边缘跟弃、听牌、多人、短码/再开权；
5. 人数覆盖沿用 2–9，**逐人数分别报告**，禁止跨人数外推（`docs/39` §3.4 的口径继续适用）。

### 6.2 主种子集

1. 新主种子集必须**与 `1215 / 20260918 / 3311 / 7926` 全部不同**；
2. 新种子取值与个数在运行前随清单冻结，属**预注册内**种子；`docs/53` §7.3 禁止的是「擅自新增其预注册外 seed」，本预注册正是合规路径；
3. 种子数量属待裁定决策（见 §10 D5）；
4. 种子派生规则沿用既有口径——牌堆流不含焦点 arm 或人格，两 arm 共享同一牌堆派生流。

### 6.3 冻结时点与不可回退

1. **冻结顺序**：先冻结节点机械明细 + 种子集 + 机会分母 + 评估方式，再产生任何读数（`docs/20` §6 开头原文要求）；
2. 冻结产物：一份新的工作树外目录，含新冻结清单与三份回执（阶段 A、阶段 B、确定性补算），沿用 v1–v5 的目录与文件结构；
3. **不得覆盖** v1–v5 任一目录的文件，不得改写任何既有清单或回执；
4. 一经冻结，样本集不得因读数不利而增删或替换。

## 7. 指标与判定规则（候选集，**未裁定**）

### 7.1 分层与优先级

判定优先级按已裁定顺序：**三维不可预测性 > 可控运行成本 > 尽量减少可剥削性（允许人格有适度弱点）**。不追求完整多人 GTO，不把「随机」当「强」。

| 层 | 内容 | 性质 |
|---|---|---|
| L1 机制与正确性 | 违规 0、截断 0、信息边界、摘要一致、随机可重放 | **必要条件**，已有冻结要求 |
| L2 成本 | 端到端决策延迟硬预算、逐人数分组分位 | **必要条件**，已有冻结要求 |
| L3 不可预测性 | 动作混合覆盖、类型熵、额度多样性、风格可分度、风格稳定性 | **本次新增判定对象** |
| L4 不劣化 | 相对 `heuristic@1` 的配对净筹码/BB-100 | **本次新增判定对象** |
| L5 抗针对 | 固定探针族对照 + 针对性诊断（见 §8） | **本次新增判定对象** |

### 7.2 不可预测性指标（定义沿用 `docs/20` §6.1，门槛为候选值）

| # | 指标 | 定义口径 | 候选门槛（**未裁定**） |
|---|---|---|---|
| 1 | 实质动作混合覆盖率 | 分母 = 非强制节点；某节点至少两个不同动作类型各 ≥10% 记为混合节点 | 整体 ≥25%，并**分域**报告翻前/面对下注/免费行动 |
| 2 | 平均类型熵 | 固定估值 seed 下对策略内分布求 `H(s)=−Σp·log₂p` | ≥0.15 bit；**不得**靠降低 MC 样本制造估值抖动达标 |
| 3 | 额度多样性 | 条件于已选 BET/RAISE，同额合并后统计锚点占比与金额条件熵 | 至少两档锚点各 ≥15%；金额条件熵 ≥0.5 bit；短码退化单档**另报** |
| 4 | 风格可分度 | 同局面同估值 seed 下不同风格的条件分布；配对报告 VPIP/PFR/主动频率 | 至少两档在**预先指定的两个机会域**上 ≥10 个百分点 |
| 4b | 风格间 JS 距离 | 沿用本项目既有口径（含结构恒等节点的 125 节点平均 JS） | 在新节点集上**沿用** D3 = T1 的 `0.15`，**不重标定**（见下方注） |
| 5 | 风格稳定性 | 同 session 配置/身份连续，换按钮/rebuy 不重抽，不同 seed 仍体现倾向 | 足量配对样本中**方向稳定** |

**关于 4b 的注（必须如实记账）**：`0.15` 是在既有 125 节点上标定出来的阈值。把它直接套到**不同**节点集，其松紧度**未经验证**；同一阈值在新节点集上可能过松或过严。本预注册的处理是**不重标定**：直接沿用，未达标即如实报告为未达标。**禁止**在看到新读数后改阈值——那正是 `docs/20` §6.1 第 1 条禁止的「看到有利结果后更换分母」。

### 7.3 成本指标（沿用既有冻结要求，不改数值）

- 端到端单次决策 `DECISION_BUDGET_MS=100` 为硬预算，`>=100 ms` 计失败且**不放宽**；p95 <50ms、p99 <80ms 为指导值；
- 逐人数报告 p50/p95/p99/max/超时数与样本数，**不把合并均值当各人数通过**；
- 建议总计 ≥10000 次决策（`docs/20` §6.3），重点 6/7/9；
- 沿用既有口径：**不把查询延迟当端到端决策延迟**；`coverage.executed_nodes` 须如实标注为清单库存口径而非本轮执行数。

### 7.4 不劣化指标

- 候选底线：相对 `heuristic@1` 在固定对照池上的**最差**收益差 95% 区间下界 ≥ `−5 BB/100`（`docs/20` §6.2 的「可接受牺牲提案」）；
- **该提案在 `docs/20` 原文中明确标注为「未拍板的对手风险预算，不是教学/GTO 标准」**；`docs/35a` §5.2.4 曾如实标注同一处张力。因此本项必须由用户裁定（见 §10 D4）；
- 配对方式：被测与对照用**配对发牌种子、同位置、同起始深度**，重新模拟完整后续，**不得**把新动作接到旧历史后缀算反事实 EV（`docs/20` §6.2）；
- 必须**双向**报告（最大正偏离与最小负偏离），不得只报有利一侧。

### 7.5 判定措辞约束

1. 判定函数只输出**解释性状态**，不输出「合格/不合格/通过/达标」（沿用 `docs/39` §3.1）；
2. 是否把判定结果**绑定**本次质量签收，属待裁定决策（见 §10 D2）；
3. 任何判定都**不追溯改写**任何已落盘回执；
4. 区间口径：若种子块数不足以估计离散度，须沿用 `interval_status=not-estimated-small-fixed-seed-set` 标注，**不得**在无区间的情况下用点估计声称达标。

## 8. 抗针对与剥削性检验（本预注册的一章）

`docs/53` §1.3 已把「抗针对验证必做」列为裁定事项；`docs/53c` §5 如实记录该项**从未做过**。本节把它写成预注册的判定对象，而不是旁路另做。

### 8.1 现有能力与其局限（只读事实）

现有「抗针对」只有**机械探针**：

| 项 | 现状 |
|---|---|
| 对手族 | `random@1` / `heuristic@1` / `passive-call-probe` / `fixed-pressure-probe`（四族） |
| `arm` | `mixed-focus` / `legacy-focus`（配对控制，共享同一牌堆派生流） |
| 座位轮换 | `rotation` 覆盖该人数的全部座位 |
| 手数 | 4 主种子 × 3 风格 × 4 族 × 2 arm × 人数轮换合计 = 4,224 手 |
| 单格手数 | 8–16 手量级；bb/100 的量级由单手全下主导，**其排序不可当结论** |

**局限（必须如实标注）**：探针是**固定策略族**，不是 best response；`docs/53c` §4 已自行声明该批读数「不是强度证据」。因此现有能力**不能**支撑「未观察到可被针对性利用」的表述。

### 8.2 探针池扩充（候选，待裁定）

在既有四族之外，候选增补方向（均只使用公开信息与自己底牌，**不得**读取被测策略内部人格参数或底牌）：

| 候选增补 | 针对的问题 |
|---|---|
| 尺度针对探针 | 检查「见某尺度必有某牌力」的固定尺寸信号 |
| 位置/人数针对探针 | 检查既有人数惩罚口径是否形成可利用的固定反应 |
| 边缘跟弃压力探针 | 检查边缘牌上的可被加价剥削程度 |
| 主动率针对探针 | 检查被动型风格（跟注型 PFR 为 0）是否被利用 |

### 8.3 配对净筹码与区间

1. 每个对照族报告净筹码 / 适用 bb-100，并给出**按手/配对块**计算的区间（种子块数足够时）；
2. 明确禁止：胜过 `Random` 不证明不可剥削（`docs/20` §6.2 原文）；自对局总收益接近零是筹码守恒的结果，不是接近均衡的证据；
3. 区间不覆盖或方差过大时，报告**证据不足**，不自动无限加样本（`docs/20` §6.2）。

### 8.4 针对性诊断

按 `docs/20` §6.2 的既有「额外诊断」，比较探针在**前 20 手**与**更长样本**后的增益，检查是否形成「见某尺度必有某牌力」的新漏洞；按尺度/牌力/街道分桶**分别报告**。

### 8.5 明确不做与不得声称

- **不做**完整 best response 或精确 exploitability：多人无限注下不可得（`docs/20` §6.2）；有限探针池只能发现**已覆盖**的漏洞，**不能**提供最优对手意义上的上界；
- 不得把「共享公共大牌上弃牌率高」直接说成**已可被利用**的漏洞——这正是从 `docs/53c` §4 第 4 条延续至今、**必须由本节检验**的疑似弱点；在检验完成前，它只能记为「读数存在、可利用性未检验」；
- 不得把本节结论表述为「不可剥削」「GTO」「均衡」「真实 EV」；
- 不得把只读重算或确定性补算当作新的抗针对样本。

## 9. 防作弊约束与修订规则

### 9.1 三条防作弊约束（沿用 `docs/20` §6.1 与 `docs/35a` §5.3）

1. **先后顺序**：测试集、机会分母、评估方式**先冻结再调策略**，不得在看到有利结果后更换分母；

3. **熵不得注水**：不得靠降低 MC 样本数制造估值抖动达标；不得以「拉高动作熵」为目标（`docs/53` §13.2）。

### 9.2 本预注册的修订规则

1. 本注册在任何新结果产生**之前**冻结，符合 `docs/20` §6「先冻结再调策略」；

3. 修订必须在**看到新读数之前**发生；一旦新样本开始产生，本文的 L3/L4/L5 判据即锁定；
4. 本注册**不构成**任何实施授权、排期承诺或预算批准。

### 9.3 增量记账要求

- 目标优先序（三维不可预测性 > 成本 > 可剥削性）**不因本次验证而改变**；

- 每次运行只获得**包络级**预算批准，不构成对更大规模运行的授权。
