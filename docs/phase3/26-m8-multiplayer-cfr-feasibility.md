## 1. 本轮目标、已确认事实与未确认边界

M8 的目标不是求解完整多人 Hold'em，而是决定是否值得进入一个有资源上限的离线多人抽象实现轮。它必须优先覆盖 6/7 人，并在同一规则族中尽早触及 9 人的结构、信息集和资源边界。

已确认且不能回退的事实：

1. 长期路线仍是“训练前置核验与通用契约 → M7 Kuhn 工具链 → M8 多人有界验证 → 分阶段接入”；统一设计目标是 2–9 人，当前训练重点是 6/7 人并及早验证 9 人。
2. 每轮训练相关进程累计上限为本机 CPU 2 小时、合计峰值内存 8 GiB、保留实验产物 1 GiB。达到任一上限、出现信息泄漏、规则矛盾或没有有效质量证据时，必须停止并汇报；不得自动增加预算、转云、转 GPU 或无限重跑。
3. `21` 的翻后竞争集合包含 Hero 之外全部未弃牌座位，包含全下者、排除弃牌者；它不是逐层货币 EV。
4. `22` 保留完整欠注差额 `C` 和实际支付 `A` 的区分；`project_pot_layers()`、`project_candidate_call()`、`candidate_call_pot_projection()` 仅投影公开投入与资格，不替代结算或计算逐池收益。
5. `23` 的旧 `equity()` 对任何平局仍使用 `ties / 2`；`24` 的 `StaticShowdownShareEstimate` 只表示固定 pooled 竞争集合的静态名义 share。两者均不能称为边池 EV、完整 CALL EV 或 GTO。
6. M7 已验证独立 Kuhn 工具链，但不能外推为多人 Hold'em 的均衡、GTO、生产策略或线上 lookup 证据。

本轮明确不做：完整 no-limit Hold'em、真实范围、真实公共牌、全下/边池、短码 CALL EV、生产 `GameState` 改造、真实 Bot、复盘、API、UI、持久化、DeepSeek、在线训练、实时求解，以及把 static share 或池层投影接入训练收益。

## 2. 只读核对结果

### 2.1 现有生产边界

`AGENTS.md` 将 `backend/app/poker/` 定义为无 Web 依赖的规则引擎，`strategy/` 只能经 `GameState` 与 `poker/` 交互，并指定 `tools/trainer/` 为离线 CFR 训练目录。当前 M8 不触碰这些边界。

`docs/20` 已明确：统一的是状态表达、训练管线和将来的策略入口，不是一张固定人数概率表。人数、相对位置、公开动作、起始人数、未弃牌者、可行动者和各层资格必须条件化；九人桌弃到两人不能直接退化为原生单挑。当前生产 `GameState` 含有所有座位底牌，且没有完整、脱敏、版本化的公开行动历史投影，因此它不能直接作为训练器输入或信息集来源。

`docs/22` 和 `docs/24` 的现状进一步说明：公开池层资格、固定 pooled 静态 share、实际整数结算、未来范围和后续行动情景是不同能力。本轮的抽象收益模型不读取它们，也不假装它们已经解决了多人收益。

## 3. 多人 CFR 与质量解释的边界

### 3.1 算法不自动给出两人零和同等结论

M7 的 Kuhn 满足 `u0 + u1 = 0`。对固定策略剖面 \(\sigma\)，两侧的 best response 可精确穷举，且：

\[
\operatorname{exploitability}(\sigma)=\frac{\operatorname{NashConv}(\sigma)}{2}
\]

多人即使构造成常和（所有玩家净收益之和恒为零），也不是两人零和博弈。普通 CFR、CFR+、external-sampling MCCFR 的平均策略在此情形下**不自动**继承 M7 的两人零和 Nash 收敛解释。累计 regret 下降、自对局总收益为零、各玩家收益稳定或策略熵上升，都不能单独证明接近 Nash 均衡。

对任意固定多人抽象策略剖面，若存在对每一名玩家都严格遵守信息集的精确 best response，才可以定义：

\[
G_i(\sigma)=\max_{\tau_i\in\Sigma_i}
  u_i(\tau_i,\sigma_{-i})-u_i(\sigma)
\]

\[
\operatorname{NashConv}(\sigma)=\sum_i G_i(\sigma)
\]

这里的 \(\Sigma_i\) 必须是只依赖该玩家私有牌和公开历史的合法行为策略集合。这个量针对的是**固定抽象策略剖面**，不是原始 Hold'em；在多人场景也不能再把它除以二称为 exploitability。当前 M8 推荐切片不承诺实现精确 BR，因此不会输出或阐释 `nash_conv`、`exploitability`。

### 3.2 禁止的伪 best response

以下做法都会泄漏信息或误报质量，均不可采用：

- 在每个完整 deal、完整牌组排列或终局结果上单独选择动作；这会让偏离者看到对手暗牌。
- 用“胜过当前自对局”、总收益为零、正 regret 很小或训练损失下降替代合法 best response。
- 用只测试一组对手阈值策略的收益称为 NashConv。
- 在 6/7 人抽象上得到的数值，宣传为 9 人或真实 Hold'em 的 exploitability。

## 4. 两个候选抽象共享的最小契约

两个候选都使用同一受限的单街道、单次加注机会规则族，以测试位置、公开历史、行动顺序、存活状态、私有信息键、N 人收益、抽样和受限质量测量。它们不模拟 Hold'em。

### 4.1 玩家、位置与公开行动

- 人数 `N` 只允许 `6`、`7` 或 `9`。相对座位固定为 `0..N-1`；`0` 是抽象首个行动者，而非生产引擎绝对 seat、按钮或盲位。
- 每人支付 `ante=1` 个整数筹码单位。没有盲注、公共牌、可变筹码深度、all-in、边池或再加注；每人预设都可支付至多一次额外固定下注。
- 初始阶段按 `0..N-1` 顺序行动。尚未出现下注时，当前玩家只能 `x`（check）或 `b`（以 `bet=1` 开池）。第一名 `b` 后不再允许开池或加注。
- 若所有人都 `x`，全部未弃牌玩家摊牌。若座位 `o` 首次 `b`，其余座位按 `(o+1) mod N` 循环顺序各回应一次，只能 `c`（call `1`）或 `f`（fold）。此前已 check 的玩家也必须在绕回时回应。
- 仅开池者留下时，开池者获胜；否则全部未弃牌者摊牌。折叠者的 ante 是死钱。
- 公开历史使用规范、带相对座位的 token，例如 `x@0|x@1|b@2|c@3|f@4`。解析器从历史唯一推导当前行动者、开池者、已 call/弃牌座位、存活集合、每人投入和待回应顺序；不得把这些派生值与历史不一致地重复写入 key。

因此可审计的公开状态是：`N`、规范公开历史、当前相对行动者、开池者或空值、存活/弃牌集合、行动次序和公开投入向量。真实引擎内部 seat、真实 stack、所有底牌、未来公共牌、未来行动、终局赢家、结算结果和内部训练随机状态都不属于该状态。

### 4.2 信息集键与信息泄漏规则

每一策略信息集的规范键为：

```text
m8/{game-version}/n={N}/actor={relative-seat}/rank={own-rank}/history={canonical-public-history}
```

其中 `own-rank` 是行动者唯一可见的私有牌面；`history` 已编码位置、公开动作、存活/弃牌状态、投入和行动顺序。导出条目还应重复可校验的 `legal_actions` 与由历史导出的公开投影，读取器必须验证它们与 key 完全一致。

下列数据绝不可进入键、策略 lookup 或动作采样：其他玩家牌面或 rank、未发牌、未来公共牌、终局赢家、实际生产底池层、真实数据库记录、对手内部策略参数和训练器隐藏随机状态。将其他私牌替换而保持行动者自己的牌与公开历史不变时，命中的 key 必须不变。

### 4.3 受限整数收益

令玩家 \(i\) 的公开投入为 \(c_i\)，终局总池为 \(P=\sum_i c_i\)，其整数派彩为 \(w_i\)。训练效用固定为：

\[
u_i=w_i-c_i
\]

所有筹码、ante、下注和派彩均为整数，且每个终局必须满足：

\[
\sum_i w_i=P,\qquad \sum_i u_i=0
\]

这只是抽象博弈的净筹码效用，不是生产结算、真实筹码深度、边池 EV 或短码 CALL EV。若未来为了数值优化报告归一化值，只能记录 `normalized_utility = u_i / ante` 作为训练诊断；权威规则和质量计算仍以整数 \(u_i\) 为准。

### 4.4 随机性、迭代和重放语义

推荐候选算法为**同步 external-sampling MCCFR**，不使用 M7 的 full-tree 递归：

1. 一个 `iteration` 固定为按相对座位 `0..N-1` 完成的 `N` 次 traverser pass；不是一局对局，也不是一个 deal。
2. 每个 pass 从该候选的 chance 模型抽取一个新的有序 deal；该 pass 的 traverser 枚举自己的合法动作，对手节点按冻结的当前行为策略抽样。
3. 一轮开始时冻结 regret-matching 策略；收集全部 `N` 个 pass 的更新后再批量应用，避免座位遍历顺序成为未记录的训练偏差。
4. `master_seed` 必须是显式整数。派生 seed 时不得使用进程随机 `hash()`；实现需记录确定性派生规则、PRNG 标识与版本、Python 版本、deal 抽样顺序、对手动作抽样顺序和算法版本。
5. 在同一训练器版本、Python 小版本、配置和 master seed 下，重跑必须得到相同策略和规范产物。策略改变会改变后续抽样分支数，故这种重放是完整重跑语义，而不是只凭某个 iteration 编号随机访问同一轨迹。

M7 的全 chance 枚举不消费随机数；M8 的 seed 会实际影响 sampled trajectory。seed 不可省略，也不能仅作为不生效的元数据。

## 5. 候选 A：唯一等级的 N 牌单次开池博弈

### 5.1 规则、chance、收益与 lookup

候选 A 使用恰好 `N` 张、全序且唯一的私有 rank：`0 < ... < N-1`。chance 均匀抽取该牌组的一个有序排列，每名玩家得到一张，所有牌都被发出。按照第 4 节行动树和整数收益结算，摊牌时仍存活者中的最高 rank 获得全部池。

这使得同级平局不可能发生。它有意验证多人私有信息、相对位置、公开行动、弃牌、固定投入、常和收益、MCCFR 抽样、策略产物和受限偏离探针；但不验证多人平局、整数余数、公共牌、范围、边池、短码或真实 Hold'em 牌力。

规则族和算法在 `N=6/7/9` 时相同，仅 `N`、牌组大小、信息集数和 chance 空间改变。每个产物必须将 `player_count` 作为 game descriptor 的一部分，因此各人数只能比较同一规则族的结构和资源，不能把某人数的策略概率直接 lookup 到另一人数。

### 5.2 结构计数

当有一次开池后，固定开池者下的回应阶段有 \(2^{N-1}\) 个终局组合。该规则族共有：

\[
\text{public decision histories}=N\cdot2^{N-1}
\]

\[
\text{terminal histories}=1+N\cdot2^{N-1}
\]

候选 A 的 chance 有 \(N!\) 个等概率 ordered deals；完整信息集数为 `N` 个私有 rank 乘以公开决策历史数。

| N | ordered deals | 公开决策历史 | 信息集 | 终局历史 | 固定策略的全 chance 叶子评估上界 |
|---:|---:|---:|---:|---:|---:|
| 6 | 720 | 192 | 1,152 | 193 | 138,960 |
| 7 | 5,040 | 448 | 3,136 | 449 | 2,262,960 |
| 9 | 362,880 | 2,304 | 20,736 | 2,305 | 836,438,400 |

最后一列是 `ordered deals × terminal histories` 的朴素完整枚举规模，用于否定不切实际的 full-tree 训练或质量测量，不是已经完成的运行测量。`N=6/7` 的固定策略完整 profile value 和小型受限探针有机会在预算内验证；`N=9` 的 8.36 亿叶规模不允许默认做全 chance 质量计算。

## 6. 候选 B：允许平局的双副本 rank 单次开池博弈

### 6.1 与候选 A 的差异

候选 B 保留第 4 节的玩家、行动树和固定投入，但牌组变为 `N` 个 rank、每个 rank 两张。每人仍只看自己的 rank，不看具体副本身份。摊牌时，存活者的最高 rank 可有 `k>=1` 名并列赢家。

为保持抽象使用整数筹码，令每个赢家先获得 `P // k`，余数 `P % k` 按公开、固定的相对顺序分配：有开池时从开池者的下一个座位开始循环；全 check 时从座位 `0` 开始循环。该顺序是本抽象的明确规则，并不宣称等同生产 `_settle_showdown()` 的余数规则。每名玩家仍取 `u_i=w_i-c_i`，所以总收益保持为零。

候选 B 可以测试“多人平局与整数残余必须有明确规则”，但不等于 `StaticShowdownShareEstimate`：后者是浮点期望的固定 pooled 名义 share；候选 B 是单池、固定规则的整数派彩。它仍不涉及逐层资格或真实 side pot。

### 6.2 chance 计数与不可行性信号

若物理牌组的每个副本可区分，ordered deal 数是 \((2N)!/N!\)。若仅枚举 rank 序列，数量为：

\[
\sum_{s=0}^{\lfloor N/2\rfloor}
\binom{N}{s}\binom{N-s}{N-2s}\frac{N!}{2^s}
\]

但 rank 序列不是等概率的：使用过的不同 rank 数量不同，会对应不同数量的物理副本排列。因此实现必须直接从物理牌组抽样，或显式使用正确 multiplicity 权重；不能把去重后的 rank 序列当成均匀 chance。

| N | 不同 rank 序列 | 物理 ordered deals | 信息集 | 物理全 chance 叶子评估上界 |
|---:|---:|---:|---:|---:|
| 6 | 29,520 | 665,280 | 1,152 | 128,399,040 |
| 7 | 463,680 | 17,297,280 | 3,136 | 7,766,478,720 |
| 9 | 172,504,080 | 17,643,225,600 | 20,736 | 40,667,635,008,000 |

候选 B 的信息集数量与 A 相同，因为私有可见值仍只有 `N` 个 rank；chance 和精确评估却快速膨胀。它必须使用抽样训练和抽样质量诊断，无法在当前预算内默认提供 6/7/9 的全 chance 质量证据。

## 7. 候选比较与推荐

| 维度 | 候选 A：唯一 rank | 候选 B：双副本 rank / 可平局 |
|---|---|---|
| 验证的核心管线 | N 人位置、公开历史、存活状态、固定投入、常和效用、MCCFR、导出 | A 的全部能力，加上平局、整数余数和带 multiplicity 的 chance |
| 不验证的核心事实 | 平局、边池、公共牌、真实范围、真实 Hold'em | 边池、公共牌、真实范围、真实 Hold'em |
| 6/7 的固定 profile 精确测量 | 结构上可尝试，必须受时间 gate 限制 | 朴素全 chance 已很大，不作为默认指标 |
| 9 人边界 | 可构建 20,736 信息集并做小型 sampling probe；禁止默认全 chance 评估 | chance 已远超预算，只做结构与 sampler 边界，不训练 |
| 质量证据 | 可有精确 profile value 和有限合法偏离 probe；仍非 Nash 证明 | 只能有抽样 profile / probe 证据，较弱 |
| 预计实现复杂度 | 最小 | 额外 chance 权重、平局与余数测试 |
| 风险 | 容易被误称为已验证多人平局 | 资源爆炸和抽样方差掩盖质量问题 |

**最小推荐方案：候选 A。** 后续若获得单独确认，先只实现 `N=6/7` 的候选 A，并让 `N=9` 仅走同一构造、信息集和 external-sampling 预检路径；不训练 9 人长期策略，不导出供生产使用的策略。候选 B 只能在 A 的规则、信息集、采样、产物安全和资源门槛均通过后，作为新的、单独确认的“平局能力”切片评审。

该推荐证明不了以下任一结论：6–9 人完整 Hold'em GTO；真实范围或真实下注尺度的质量；边池、短码、静态 share、逐层资格或 CALL EV 的正确性；多人平均策略接近 Nash；生产 Bot 或复盘适用性。

## 8. 质量测量：可审计指标与局限

初始可行性切片把“数学定义”“可计算指标”和“经验诊断”分开记录。

| 指标 | 对象与计算 | 精确性 | 能说明什么 | 不能说明什么 |
|---|---|---|---|---|
| 效用守恒与规则不变量 | 每个终局检查整数投入、整数派彩、\(\sum_i u_i=0\) | 精确 | 规则、死钱、弃牌和派彩未自相矛盾 | 策略质量 |
| 固定 profile value 向量 | 冻结 \(\sigma\)，按完整 chance 和行动树求每位 \(u_i(\sigma)\) | A 的 6/7 可在 gate 内尝试精确；A9/B 为抽样 | 指定抽象、指定策略剖面的收益基线 | 均衡、BR 或实盘 EV |
| 阈值偏离 probe | 每位玩家固定采用合法的 \(\tau_{i,t_o,t_c}\)：无下注时当 `rank >= t_o` 开池，否则 check；面对开池时当 `rank >= t_c` call，否则 fold | A6/7 可完整 chance 计算；其余仅固定 seed 采样 | 发现这一预先声明、信息集合法的完整策略偏离是否明显获利 | 所有合法偏离、精确 BR、NashConv |
| `probe_gain_i` | \(\max_{\tau\in T_i}[u_i(\tau,\sigma_{-i})-u_i(\sigma)]\)，其中 \(T_i\) 是冻结 manifest 中最多两组阈值对 | 与该 manifest 的评估口径一致 | 一个可复查的漏洞下界 | 漏洞上界；零增益不代表不可剥削 |
| sampled regret / visit coverage | 报告每位 traverser 更新次数、访问信息集比例、估计量范围和固定 seed | 采样诊断 | 抽样覆盖、异常权重或未访问状态 | 平均策略收敛或均衡质量 |
| 跨 seed 稳定性 | 在固定审计信息集清单上比较策略概率的 L1 距离、有效支持集和 profile value 区间 | 经验性 | 结果是否对采样轨迹极敏感 | 正确性或均衡 |

阈值 probe 的 `T_i` 必须在训练前写入版本化 manifest，不能看结果后添加或删除。建议每名玩家恰好评估两组阈值对：

```text
(ceil(N / 2), ceil(N / 2))
(ceil(3N / 4), ceil(N / 2))
```

这两组策略只读自己的 rank 和当前公开 phase，因此不泄漏对手牌。它们刻意很弱：不随开池者、call/fold 历史或复杂位置变化；所以通过 probe 只表示没有发现这两个特定漏洞，绝不构成 best response 或 Nash 证据。

若未来要报告精确多人 `NashConv`，必须先得到新授权并实现独立验证的 BR 求解器。该求解器必须在完整 chance 上为一个玩家寻找受信息集约束的整套策略，不能逐 deal 贪心；并需要在独立可手算的小模型上验证。即使完成，也仅可称为该固定抽象剖面的 NashConv，不能输出 `exploitability=NashConv/2`，不能迁移到 Hold'em。

## 9. 资源预测、预算与停止条件

### 9.1 结构性资源预测

下表是按信息集数和 JSON 条目数量给出的保守设计上限，不是实际基准测试。实际实现必须同时记录进程 RSS，而不能只依赖 `tracemalloc`。

| 候选 A N | 训练状态与审计结构预留 | 单个规范策略产物预留 | 质量路径 |
|---:|---:|---:|---|
| 6 | ≤ 32 MiB | ≤ 4 MiB | 允许有时间上限的完整 chance profile / probe |
| 7 | ≤ 96 MiB | ≤ 12 MiB | 允许有时间上限的完整 chance profile / probe |
| 9 | ≤ 512 MiB | ≤ 64 MiB | 只做构造与 sampled boundary probe，不做全 chance profile |

这些不是对最终进程 RSS 的承诺。训练器一旦因 Python 对象、采样缓存、评估数据或产物超过上表预留，就应先停止、记录实际原因和 RSS，再由用户决定是否改变数据结构；不能直接扩大模型、并行 worker 或内存预算。

### 9.2 后续获授权后的单轮时间配额

下列分配是未来实现轮的硬上限计划；当前没有执行其中任何一步。所有训练、评估、重试和临时导出均计入同一轮，不按子任务重置：

| 阶段 | 最多累计时间 | 成功前提 / 停止规则 |
|---|---:|---|
| A6 构造、规则与采样预检 | 5 分钟 | 结构、信息集、种子与守恒失败即停止 |
| A6 external-sampling 训练 | 25 分钟 | RSS 达 6 GiB 预警即停止；任何进程达 8 GiB 立即停止 |
| A6 完整 chance profile 与两组阈值 probe | 15 分钟 | 评估超过时限则标记“无精确质量证据”，不改为更长运行 |
| A7 external-sampling 训练 | 30 分钟 | 同上 |
| A7 完整 chance profile 与两组阈值 probe | 20 分钟 | 同上 |
| A9 同管线构造与短采样边界 | 10 分钟 | 不输出长期策略，不运行全 chance evaluator |
| 产物复读、资源汇总和清理 | 5 分钟 | 总计最多 110 分钟；只保留预算内允许的产物 |

每轮保留策略、临时评估、日志和检查点总量必须小于 1 GiB；默认只允许每个已完成配置保留一个最终规范 JSON 和一份文本/JSON 测量摘要，临时文件完成后删除。任何单个策略读取器必须有更小的独立文件上限，推荐 64 MiB。达到 1 GiB 前不再创建新任务。

以下情形直接阻止进入下一阶段：

1. 信息集键、公开历史或 sampler 被发现读取对手私牌、未来牌、赢家或生产私有状态；
2. 任一规则路径不能证明整数筹码守恒、合法动作、弃牌资格或确定的平局余数规则；
3. A6/A7 的受限质量路径无法在相应时间配额内完成，或输出为非有限数；
4. 策略概率未归一、未覆盖声明的可达信息集，或相同版本/seed 无法重放；
5. 累计时间、RSS、产物总量触达硬上限；
6. 只有自对局、熵、总收益为零等指标，却没有规则不变量和至少一个预声明的合法偏离测量。

停止后只汇报已完成范围、已用资源、未覆盖状态和失败原因；不得自动重试、更换算法名称、降低指标口径、转云或转 GPU。

## 10. 导出、读取与 lookup 的新契约

M8 不可复用 M7 的 Kuhn JSON schema，只能复用其安全原则。未来若获得授权，候选 A 的新产物应具有独立的 `artifact_type` 与 game/version，例如：

```text
schema_version
artifact_type = "multiplayer-cfr-average-strategy"
game
training
probability_units
infosets
quality
resources
```

最少字段如下：

| 部分 | 必须记录 |
|---|---|
| `game` | `id`、`version`、`player_count`、牌组/副本规则、ante、固定下注、行动树版本、平局规则、余数优先顺序、相对位置语义 |
| `training` | 算法、同步/异步更新语义、iteration 数与定义、平均策略起始点、chance 模型、traverser 调度、master seed、PRNG/派生规则版本、Python/训练器版本 |
| `infosets` | 完整规范 key、行动者相对座位、私有 rank、公开历史、由历史验证的公开投影、合法动作和整数概率单位 |
| `quality` | 评估 profile 标识、是否全 chance、抽样 seed/样本数、每位玩家效用、probe manifest id、每位 `probe_gain`、coverage、稳定性结果；不得伪装为 `nash_conv` 或 exploitability |
| `resources` | 累计秒数、峰值 RSS 采集口径、信息集数、产物字节数、是否碰到预警或停止条件 |

读取器必须限制普通文件大小、UTF-8、重复 JSON 键、非有限数、未知/缺失字段、错误 game 版本、错误人数、非法 key、非法 action、负概率单位和单位和不匹配；不得 pickle、加载模块路径、执行内容或对未知键回退。输出以临时文件写入并原子替换，导出后必须重新读取，再按重读策略计算质量字段。

未来的 lookup 只接收受控的抽象投影 `(game version, N, relative actor, own rank, canonical public history)`。它不接收 `GameState`、原始 engine seat、任意 JSON、对手牌或抽象外状态。抽象外、版本不匹配或不完整信息集必须明确失败；本轮不定义任何生产 fallback，更不接入 runtime。
