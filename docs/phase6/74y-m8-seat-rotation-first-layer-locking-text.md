## 4. `seat_rotation`（拟定锁定版本 1；送审稿，未锁定）

**`lock_versions` 字段**：`seat_rotation: 1`（整体生效后）。

**白名单归属**：**属于**「座位轮换」。**② 使用**（在推导引用轮换或默认 schedule 时）；**③ 使用**（`g_h` 中 `button`、`probed_seat` 的确定量核验）。

### 4.1 适用范围

1. **域 C 配对比较**运行前规格中的块内 `schedule`：每条记录对应一手，字段为 `hand_ordinal`、`button`、`probed_seat`（`HandPlan`）。
2. **人数** `N`：与运行前规格 `num_players` 一致，须满足 `2 ≤ N ≤ 23`（与 L-1、`74v` PB-J1 一致）。
3. **块内手序** `h`：即 `HandPlan.hand_ordinal`，正整数；块内总手数记为 `H = |schedule|`。
4. **块索引** `block`：进入 L-3 材料键；**跨块**时本锁定规则**重新**从 §4.2 的块初值起算（不结转上一块末手的庄位）。
5. **域 A／域 B**：本锁定**不**定义层谓词或配额；若未来 A/B 间接依赖座位标签，须另案与域规格一并审查。
6. **不覆盖**：`74v` 已锁定的配对、上界、片段、域 C 权重；`74r` L-2 身份构造与估计对象限定。

### 4.2 锁定规则（正式裁定）

记块内 `h ∈ {1, 2, …, H}`，`N = num_players`。每块**固定**块初庄位索引 **`b₀ := 0`**（不写入 `HandPlan`；为锁定常数）。

| 编号 | 规则 |
|---|---|
| **SR-S1（S-1）** | **供给方式**：`schedule` 由调用方**逐手显式**提供；验证包**不得**从 `hand_ordinal` 或其他字段**生成**或**推断** `button`／`probed_seat`，**不得**在包内自动填充 `schedule` |
| **SR-C1（连续性）** | 块内 `schedule` 的手序**连续且完备**：恰包含且仅包含 `h = 1, 2, …, H` 各一次（无缺口、无重复、无额外 `hand_ordinal`） |
| **SR-B1（庄位）** | 对块内每一手：`button ≡ b₀ + h − 1 (mod N)`；在裁定下等价于 **`button = (h − 1) mod N`** |
| **SR-P1（被测座位，P-1，δ = 0）** | 对块内每一手：**`probed_seat ≡ button (mod N)`**（整数相等，非仅同余于不同代表元）。被测座位随物理座位索引与庄位一并轮换；**相对庄位**，被测座位恒为庄位座位（`probed_seat` 与 `button` 同号） |
| **SR-X1（跨块）** | 每个块**独立**适用 SR-C1、SR-B1、SR-P1，且每块**重新**取 `b₀ = 0`；**不得**把上一块末手的 `button` 作为下一块的初值 |
| **SR-X2（排除）** | **禁止 S-3**：不得依赖 `poker.Engine.start_hand()` 在会话内对 `button` 的默认自增轮转作为验证域轮换规则；**禁止**以引擎构造初值 `button = N − 1` 或未注入路径的庄位推进**替代** SR-B1／SR-P1 |
| **SR-X3（注入）** | 验证域开手须走**注入庄位**路径（`74j` S-a、`74k` §4.2）：实际注入的庄位参数**必须**等于该手 `HandPlan.button`；**不得**依赖引擎隐式轮转得到与 `schedule` 不一致的庄位 |

**与 `74r` L-2 的一致性**：`probed_seat` 为唯一被测座位，须满足 `bot_seats = (probed_seat,)` 与构造映射口径；SR-P1 不更改 L-2 已锁定的身份与风格规则。

**范围校验**：恒有 `0 ≤ button < N` 且 `0 ≤ probed_seat < N`（由 SR-B1、SR-P1 与 SR-C1 推出，当 `H ≤ N` 时第一手为 `button = probed_seat = 0`）。
