## 4. 拟锁定的四类对象（逐类：现状 / 候选 / 推荐 / 待裁定）

本节所列「现状」全部是 `74p` 的**当前实现口径**，**未锁定**；候选中的一切具体取值均**待裁定**。

### 4.1 对象一：牌规范序与发牌映射

**白名单归属（`74o` §8.2.1）**：**不属于** `74f` §4.1 第 1 条白名单所列类别 ⇒ **不得**作 ② 的输入；在 ③ 首次使用前锁定。

**现状（当前实现口径，未锁定）**

- 牌规范序由调用方以 52 个牌面表示的序列显式给出，只校验「恰好一副牌的张数、无重复、各表示可解析」；**不**规定任何具体次序。
- 不放回抽取用「第 k 次取下标 `v_k`，把第 k 张与第 `k + v_k` 张互换后输出第 k 张」的确定函数实现，要求 `0 ≤ v_k < 剩余张数`。
- 分配规则为确定函数：按座位号升序，每座连续两张为底牌；其后五张依次为翻牌三张、转牌与河牌。
- 一手牌的抽取次数为 `2N + 5`；人数须为不小于 `2` 的整数。

**候选**

| 编号 | 候选内容 |
|---|---|
| 1-a | 规范序按牌类型的枚举声明顺序展开（`Suit` 为主序、`Rank` 为次序），并在锁定文本中**逐张写死** 52 项，使锁定后不再依赖任何枚举迭代语义 |
| 1-b | 规范序按牌面表示的字典序升序 |
| 1-c | 不锁定具体次序，只锁定「是完整一副牌的一个排列」这一约束与可执行判据 |

| 编号 | 候选内容（抽取与分配侧） |
|---|---|
| 1-d | 发牌用途索引键为 `(block, hand, draw)`：`block` 为块标识、`hand` 与同手的块内手序一一对应、`draw` 为该手内从零起的抽取次序；定位字段为 `draw`；域为收缩域且 `initial_size = 52`，每步域大小由该次读取的 `draw` 取值决定（`52 − draw`） |
| 1-e | 发牌材料条数写死为 `2N + 5`；分配规则写死为「按座位号升序每座连续两张 + 其后五张」 |
| 1-f | 适用人数写死为 `2 ≤ N ≤ 23`：由每手 `2N + 5 ≤ 52`（一副牌的张数）与「每次抽取的取值必须小于剩余张数」共同导出；`N ≥ 24` 要求发出超过一副牌，**不在**当前发牌映射口径内，须另案裁定多副牌或其它发牌机制 |

**推荐项**：`1-a` ＋ `1-d` ＋ `1-e` ＋ `1-f`。理由：`1-a` 由牌类型的枚举声明唯一确定、可由既有构造式复算且不引入字典序等外部约定，并在锁定文本中显式展开；`1-d` 的索引键含块与手序，使清单的全局键（用途标签 ＋ 索引键）在跨手、跨块时仍然唯一，同时把收缩域的步数留在**手内**定位字段 `draw` 上（收缩域按 `draw` 取值缩小，故 `draw` 必须是手内从零起的次序，不能是跨手累计计数）；`1-f` 的上界直接由一副牌的可发张数导出，与「引擎按 N 人设计」不冲突——后者是对引擎结构的要求，不是对单副牌发牌映射的要求。

**待裁定项**：具体次序（`1-a` / `1-b` / `1-c`）；是否接受在锁定文本中逐张展开 52 项；`block` 的取值与是否在运行前规格中增设块标识字段（见 §4.3）；`block` / `hand` 的渲染规则（见 §4.3）；适用人数范围的最终写法；是否把位宽与域参数在此一并写定（与 §4.3 存在耦合）。

**可执行判据候选**：给定锁定后的次序与一段整数序列，`draw_order` / `deal_for_hand` 的输出必须满足座位集合恰为 `{0…N−1}`、每座恰两张、公共牌恰五张、总数 `2N + 5` 且全局无重复；注入前七项硬失败校验不满足即终止（`74p` §5）；`2N + 5 ≤ 52` 必须在构造运行前规格时即被强制——**当前实现只强制 `N ≥ 2`，上界须由锁定文本与规格校验共同保证**。

### 4.2 对象二：被测身份的规范标识、显式构造映射、风格口径与估计对象限定

**白名单归属（`74o` §8.2.1）**：**不属于**白名单所列类别（白名单排除的是身份**读数**，构造映射不是读数）⇒ **不得**作 ② 的输入；③ 首次使用前锁定。锁定的是**构造口径**，**不**是创建或冻结身份。

**现状（当前实现口径，未锁定）**

- 构造映射以显式、不可变、可规范编码的对象给出：规范标识、构造接口（两种：主键接口、受控注册表种子接口）、是否依赖公开摘要、座位集合口径（仅当依赖公开摘要时给出）。
- 规格中的身份标识必须与构造映射的标识**逐字相同**；两侧标识必须不同。
- 基线侧三项硬限制：必须走受控注册表种子接口、不得依赖公开摘要、不得声明座位集合口径；基线标识硬限定为 `heuristic@1`。
- 材料格式按接口校验：主键接口须为恰好 32 字节的字节串（整数表示须落在 `[0, 2^256)`）；种子接口只要求**非空整数**，实现中**未设上界**。
- `(α)`：只接受显式构造映射，不得由别名、类名或未冻结默认值隐式选择身份；**被测身份尚未创建**。
- 风格口径：座位风格按已绑定 Bot 座位的**升序序号**循环分配三种风格；座位风格分配函数**不接受**显式风格参数。

### 4.3 对象三：随机化协议的结构与参数

**白名单归属（`74o` §8.2.1）**：**不属于**白名单所列类别；② 只使用随机化公理与「逐手独立抽取」这一结构 ⇒ 参数**不**进入 `V_max`，**不得**作 ② 的输入；③ 首次使用前锁定；**不**生成任何材料。

**现状（当前实现口径，未锁定）**

- 协议规格字段：来源标识、环境记录、四个用途规格、遍历顺序、承诺形式、审计格式版本、摘要算法、逐读取记录编码。
- 用途规格字段：角色、标签、索引字段、可选的抽取次序字段（仅发牌用途）、可选的座位号字段（仅非被测座位用途）、输出域（固定域或收缩域）、每次读取的位宽。
- 结构约束：四个角色各出现且仅出现一次；用途标签互不重复；遍历顺序恰好覆盖全部标签各一次；发牌用途必须是收缩域且必须声明抽取次序字段、不得声明座位号字段；其余用途必须是固定域、不得声明抽取次序字段；非被测座位用途必须声明座位号字段。
- 位宽必须是 8 的倍数，且不小于覆盖该用途输出域所需的最小位宽（整数运算，向上取到 8 的倍数）。
- 索引比较口径：声明的定位字段按整数比较，其余字段按字符串比较。
- 已实现的取值域：摘要算法与逐读取记录编码目前各只实现一种取值；协议字段中的来源标识、环境记录与承诺形式均为**非空字符串**，其内容本轮不选定。
- 已实现的拒绝与读取规则：**无偏拒绝按整倍数截断判定**——原始读取范围为 `[0, 2^w)`（`w` 为每次读取的位宽），接受上界为 `B = D · ⌊2^w / D⌋`（`D` 为该次抽取的输出域大小）；`raw_value < B` 时**接受**并输出 `raw_value % D`，只有尾部区间 `[B, 2^w)` 被**拒绝**。因此取值大于域的最大元素仍可能被接受（例：`D = 52`、`w = 8` 时 `raw_value = 53` 被接受并输出 `1`）。拒绝后必须以**同一用途、同一索引、同一位宽**继续读取；被接受的读取不得再读；收缩域的域大小由该次读取的抽取次序字段值决定；同一用途内索引升序、同索引读取必须同键相邻，且「零或多条拒绝之后必须出现恰一条同键接受」。
- 送交材料、逐读取审计记录与材料清单**携带同一份完整索引键**：材料条目的索引键被原样用于审计配对与清单条目，实现中**不存在**「局部索引转全局索引」的步骤；清单按「用途标签 ＋ 索引键」要求**全局唯一**，因此该索引键必须在跨手、跨块时自身唯一。
- 当前**缺失**的机械约束（如实登记）：索引键中的手定位字段与 `HandMaterials.hand_ordinal`、`HandPlan.hand_ordinal` 的**三者一致**没有被校验（实现只校验：材料束与手序计划的手序一致、索引取值数与索引字段数相符、`draw` 取值从零起连续、非被测座位全覆盖，以及取值落在该用途输出域内）；索引键中的块定位字段与所锁定块作用域的一致性也**没有**校验。
- 运行前规格当前只建模**一个手序计划**（逐手给出块内手序、庄位与被测座位），**没有** `campaign configuration` 或块标识字段。
- 承诺结构：来源、环境、生成起止时刻、遍历顺序、各用途条目数与拒绝次数、各项摘要。

**可执行判据候选**：协议结构校验（四角色齐备、标签唯一、遍历顺序完备、域类型与定位字段的角色约束、位宽与输出域相容）；拒绝判定按**整倍数截断**（`raw_value < B = D · ⌊2^w / D⌋` 时接受并输出 `raw_value % D`，仅 `[B, 2^w)` 被拒绝，拒绝后同用途、同索引、同一位宽继续读取）；逐读取审计的机械复核（读取组完整不变量、同键相邻、接受后不得再读、收缩域步数由抽取次序决定）；材料与审计中被接受取值的逐项配对；**待补**：索引键的手 / 块定位字段与 `hand_ordinal`、锁定块作用域的一致性校验（`3-k-i`，须实现与测试授权）；**不**证明实际独立性或均匀性（`74k` §3.2 第 4 条）。

### 4.4 对象四：执行身份覆盖清单的表示方式

**现状（当前实现口径，未锁定）**

- 覆盖清单按固定次序的六类组织：`runner`、`randomization-protocol`、`instantiation-caliber`、`injection-precheck`、`input-mapping`、`engine-and-strategy-code`；缺任一类别、类别内为空、条目名重复或出现未声明类别即失败。

- 已登记的局限：非定位字段的字符串比较要求固定宽度渲染；代码对象载荷摘要受解释器版本与加载实现影响，只是追溯绑定，**不是** `code_identity` 冻结。

| 编号 | 候选内容 |

理由与依赖：`4-a-i` 只覆盖 ③ 前提核验实际引用到的类别，避免把 ⑥ 的自由度提前锁死。`4-b-i-1` 是**唯一不需要改动实现**的候选：现状的 `instantiation-caliber` 条目值是**需逐项比较的原始语义值**（规范标识、构造接口、布尔口径、座位范围、注册表位置、入口位置、参数布局与有效默认值），冻结输入校验按**原值相等**逐项比较；因此「需要为文本值定义确定渲染规则」**推不出**「所有条目值均应哈希化」。`4-b-i-2` 与 `4-b-i-3` 都要求新增摘要域、写定每类的规范编码与算法，并修改实现与测试，属**另行授权**范围；在被授权实现并复审通过之前，二者**不得**被当作可锁定口径。`4-c` 与 `4-d` 照录 K-4 `(2-i)`／`(3-ii)` 与现有实现，不新增字段；`4-e-iii` 把 `code_identity` 的冻结留在第二层，与本文件「不得作 ② 输入」的定位一致。

**待裁定项**：`4-a` 引用范围；`4-b` **必须明确其一**（`4-b-i-1` / `4-b-i-2` / `4-b-i-3` / `4-b-ii`）；若选 `4-b-i-1`，渲染规则的具体形式与宽度；若选 `4-b-i-2`，摘要域与各类规范编码；`4-c` 是否照录四项快照字段；`4-d` 条目集合是否增减；`4-e` 归属层级与（若在本层）表示方式。
