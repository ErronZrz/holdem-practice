## 2. 阻断依据

`73d` §5 已给出该路径在既有包络下的机械下界：

```text
最少配对块数 = 2 × 1,041,216,000,018 = 2,082,432,000,036
最少游戏手数 = 416,486,400,007,200
最低吞吐要求 = 231,381,333,337.33 游戏手 / 秒（在 wall ≤ 1,800 s 内）
```

该下界是机械量，不是候选身份读数，不构成质量证据；它尚未计入域 A / 域 B 的节点查询、探针报告、序列化、日志、统计聚合与任何失败重试。

阻断的结构在于：只要域 C 的块级统计量仍取解析保守界 `V_j ≤ V_max,N = M_N²`，块数即由解析式 `B_N ≥ (4 · V_max,N / m²) · 319` 唯一确定，与清单字段、实现细节、输出 schema 或工程优化无关。因此下列事项无法通过继续填充冻结项而改变：

- 块数可达性未证：`D_set`、`H_set`、层集合、层谓词、`n_ℓ`、偏移量空间与全偏移量验证均未生成；
- 逐块 `V_j` 与片段间协方差的冻结证明未完成；
- 统一分布观测契约未实现；
- wall 可行性未获支持；RSS 与输出可行性未获支持。

结论：该路径的可行性问题位于框架级，而非清单级。继续逐项填充剩余冻结项不能消除这一阻断，因此不再以该路径推进 `73b` 的冻结。

## 3. 处置结论

1. `R2 + V_max,N = M_N²` 路径**不能作为当前 `73b` 的可冻结路线**。
2. 在该路径上终止 `73` 的冻结尝试：不再以该路径补齐 `73b` 的剩余冻结项。
3. `73b` 保持未冻结，其必要冻结项仍为 `28` 项且未齐备；`73c` 已裁定的取值与 `73d` 已登记的解析结果均不回滚、不改写。
4. 本记录不主张关闭 `73`。`73` 的关闭与否需由单独裁定确定；`74` 未授权、未开启。
5. 本记录不指定、不预判任何替代方案。其他方差来源、其他 R2 前提或不同框架路线是否可行，属后续单独裁定的范围。
