## 4. `74r` L-3 v1 与 κ 协议的缺口（只读）

v1 继续有效，直到未来的新后缀锁定文本生效。下表只登记它为何**尚未**满足 `74ak` §4.1。

| v1 条款 | 现文 | 与 κ 材料协议的差距 |
|---|---|---|
| **`non_probed` 键** | `(campaign, block, hand, seat)` | 没有 `event_index`，没有 `σ_public`。同一手同一座只有一条种子 |
| **`arm_b` 键** | `(campaign, block, hand)` | 基线臂被测座位是手级一颗种子，不是逐决策 κ |
| **取值说明** | `non_probed` 与 `arm_b` 都是 `heuristic@1` 的整数 seed | 类型与成员方向可承接；**索引粒度**仍是手级 |
| **共享句** | 同一 `(campaign, block, hand, seat)` 的 `non_probed` 两臂共享（文中记为 K-2′） | K-2′ 已被 `74ai` 不采用。v1 这句话不能当成逐 κ 同值 |
| **`seat` 集合** | 一手的 `non_probed` 座位是 `{0…N−1}` 去掉被测座位 | 与 O-a 的非被测座位一致；**不**覆盖基线臂被测座位的逐决策键 |
| **输出域** | 上述两用途 `D = 2^256`，位宽 `256` | 整数 seed 的域候选可以沿用，但是否沿用由 §5.4 决定，本文不决定 |
| **拒绝** | `D = 2^w` 时该用途不发生拒绝；规则标识 `rejection-whole-multiple-truncation-v1` | 标识写在 v1 里，不得回头改 v1。域变小使拒绝区间非空，并不单独构成换标识的理由；只有接受公式、拒绝处理、读取顺序或同键约束改变时，才在**新文档**里使用新标识（§5.7） |
| **遍历** | `deal` → `non_probed` → `arm_m` → `arm_b`，用途内按完整键升序 | 键里没有决策分量时，这次序表达不了逐 κ |
| **清单值** | 材料清单的 `value` 是 JSON 整数 | 与「整数 seed」同型；八位组相等规则仍要在新文本里写明，v1 没有 κ 单元 |

v1 的来源接口 `python-os-urandom@1`、环境 `local-single-process-no-parallel@1`、一次性生成与「协议不证明真实独立性」维持为 v1 事实。它们要不要原样进入下一版，是未来锁定文本的事；本提案不改 v1，也不在这里生成一次读取。

## 5. 候选修订（并列，本文不选择）

除 §5.3 已写死的键集闭合外，未来锁定文本须在其余小节**恰好写死一组合法候选**（或写死由多节合成的一套）。那些行都还不是条款。本文不把任何一套收成最终锁定套餐。

共同下限（不是候选，是 `74ak` 与 `74ai` 已经要求的）：凡承担 `heuristic@1` 之 `seed` 的用途，其输出必须是整数，并且每个完整 κ 至多对应一条被接受的材料；同 κ 的八位组序列相同；`None` 不是材料。`M(κ)` 在材料生成前已经固定。

### 5.1 材料单元

单元**类型**已由 `74ak` 定为整数 `seed`。候选只涉及该整数在 L-3 载荷里的八位组身份（`74ai` 以八位组序列判断 `M(κ)` 相等）。

| 候选 ID | 内容 |
|---|---|
| **L3κ-U-be32** | JSON 值仍是整数。相等所用的八位组是该整数的 32 字节无符号大端，与 `74r` U-1 的字节序同一方向。域若不是 `2^256`，宽度要另写，不能默示仍是 32 字节 |
| **L3κ-U-decimal** | 相等所用的八位组是该整数的无前导零十进制 ASCII（`0` 为 `"0"`），与 v1 索引整数字段的渲染相同 |

两案都禁止把 `samples`、`bluff_freq` 放进单元。两案都不产生任何具体整数。

### 5.2 用途标签

| 候选 ID | 内容 |
|---|---|
| **L3κ-L-extend** | 在**新版本**中保留标签 `non_probed` 与 `arm_b`，只扩展它们的键。v1 文档里的同名标签仍只表示手级键，两套版本靠 L-3 版本号区分，而不是改 v1 的表 |
| **L3κ-L-new** | 新版本使用新的标签字面量承载逐 κ 种子；v1 的 `non_probed`／`arm_b` 不在新版本里继续表示 κ 材料。新字面量由未来锁定文本确定，本提案不指定字符串 |

两案都要分开两件事：

- **非被测座位**：两臂共享的 `M(κ)`（`74ai`）。标签无论新旧，同一 κ 只能有一条共享值。
- **基线臂被测座位**：同样是 `heuristic@1` 的逐决策整数 `seed`（`74ak` 与 L-2），但**不**与 `arm_m` 共享，也**不**与非被测座位的那条 `M(κ)` 混为同一用途下的同一次抽取。

**不作为候选**：只把非被测座位改成逐 κ、而把基线臂被测座位留在手级一颗 `arm_b` 上。那与 `74ak` §4.1「每一次决策新建实例并注入完整 κ 的整数 seed」不一致。

**不作为候选**：用 `deal` 或 `arm_m` 的标签顺带携带基线 `seed`。

### 5.3 键空间

完整键至少要能区分 `74ai` 的 κ，并保留 v1 已有的战役与块坐标。分量的**有无**不是候选；**字段名**与 **`σ_public` 的无损写法**才是候选。键集必须在生成前闭合，这一点不是候选。

须能对应到的分量：

| κ 分量 | 与 v1 字段的衔接（候选写法，不选择） |
|---|---|
| `seat` | 沿用 v1 字段名 `seat`。非被测用途的取值集合仍是除被测座位以外的座位。基线臂被测座位那条用途的 `seat` 固定为该手被测座位 |
| `hand_ordinal` | **L3κ-K-hand**：继续用 v1 字段名 `hand`，并写明它等于 `HandPlan.hand_ordinal`。**L3κ-K-ordinal**：新增字段名 `hand_ordinal`，与 `hand` 数值相同且同时出现。二选一 |
| `event_index` | 新字段。非负整数，对每个 `(seat, hand_ordinal)` 从 `0` 起，每有一次该座决策机会加 `1`。定义以 `74ai` §4.2 为准 |
| `σ_public` | 见下表。禁止用摘要代替这串字节 |

`σ_public` 进入索引键的无损写法：

| 候选 ID | 内容 |
|---|---|
| **L3κ-K-hex** | 键分量是 `σ_public` 的小写十六进制，位数为字节长度的两倍。由十六进制可以逐字节还原 UTF-8(`EncodeK2PublicV1`)，不截断、不哈希 |
| **L3κ-K-b64** | 键分量是同一字节串的一种明确填充规则的 Base64。同样必须可逆，并且规则要在未来锁定文本里写死字母表与填充；本提案不写死那套字母表 |

**不作为候选**：SHA-256 或任何其他摘要当作 `σ_public` 的替身。`74ai` 已写定它不是哈希，并且禁止替换 `EncodeK2PublicV1`。

**键集闭合（写死，不是候选）**：

```text
未来锁定文本必须写明：完整 κ 键集在材料生成之前，
以有限、预注册、可审计的方式闭合。
协议只为这份键集生成材料。
未列入键集的决策边界是协议失败，不得临时补料。
```

生成开始前，预注册已经列出有限个完整键，审计能够复核这份清单。运行中只查表。`σ_public` 可以依赖公开状态，但允许出现在键里的那些字节串必须已经写在生成前的清单中；牌局走到清单之外时，失败并停止，不为这个新字节串打开一次外部读取。

**排除路线 `L3κ-T-append`**（首轮曾列为候选，复审改为排除）：

- 不得在运行中依据行动历史、策略输出或新出现的 `σ_public` 追加外部随机读取、生成材料或改写 `M(κ)`。
- 该路线让行动过程决定何时、是否产生新材料，与 `74ai` 已写定的「运行前随机化协议确定固定 `M(κ)`」冲突。
- 它把材料生成带入实际执行路径。配对推进可以在包外进行，材料生成不可以跟着决策边界现算现补。
- 同一键不得再读、不得改写，并不能把这条路线救回候选：问题在于键本身是跑出来才出现的。

### 5.4 整数域

| 候选 ID | 内容 |
|---|---|
| **L3κ-D-256** | 沿用 v1 对 `non_probed`／`arm_b` 的域：`0 ≤ seed < 2^256`，读取位宽 `256`。与 L-2 §5.2 的 seed 区间同一上界。此时 `D = 2^w`，整倍数截断下该用途的拒绝区间为空 |
| **L3κ-D-narrow** | 未来文本另写一个严格更小的 `D`，并写明位宽仍是覆盖 `D` 的最小 8 的倍数。该案下拒绝区间可以非空。这是同一整倍数截断公式在较小 `D` 上的推论，**不**因此排除 **L3κ-R-keep-id**（§5.7） |

两案的 seed 都不得为负、不得为空。本提案不给出 `D` 的第三个数，也不抽取任何一个 raw 值。

### 5.5 审计与承诺载荷

v1 的承诺是 `transcript-commitment-v1` 的 14 个字段；逐读取记录有 8 个字段；材料清单项为 `purpose_label`、`index_key`、`value`；摘要算法为 `sha256`（`74r` §6.6、§8.3.7）。候选只讨论 κ 材料迫使载荷**多承载什么**，不计算任何摘要。

| 候选 ID | 内容 |
|---|---|
| **L3κ-A-reorder** | 14 个承诺字段的**集合**保持不变。`traversal_order`、`entry_counts`、`rejection_counts`、材料清单与送交材料束改为包含新版本的用途与扩展后的完整键。`index_key` 的字符串数组按该键的字段顺序排列，其中 `σ_public` 分量使用 §5.3 所择的无损写法 |
| **L3κ-A-extend-fields** | 在新版本的协议载荷或逐读取记录中**增加**封闭字段，用来原样绑定 `σ_public` 字节（或与键分量同一套可逆编码），避免只靠用途标签无法复核字节相等。新增字段的名字与所在对象由未来文本写死 |

两案都要求：审计能够依记录判断两个臂上的同一 κ 是否得到同一整数，以及 `σ_public` 不同的键是否被错用成同一材料。两案都**不**把摘要算法从 `sha256` 改成别的算法；若未来文本要改算法或改承诺形式标识，那是另一项锁定选择，本提案不提议一个新算法的名字。

`campaign-configuration-v1` 仍不得写入具体材料、seed 或 `σ_public` 实例。实际 campaign 摘要继续不可在本文件中生成。

### 5.6 遍历次序

v1 已区分两种顺序：读取的物理 `read_index`，以及清单按用途再按完整键的升序（`74r` §6.4、§8.3.7）。候选保持这个区分，只改「升序」的字段表和用途级次序。

| 候选 ID | 内容 |
|---|---|
| **L3κ-O-after-deal** | 用途级把逐 κ 的非被测用途放在 `deal` 之后、`arm_m` 之前；基线臂被测座位的逐 κ 用途仍放在 `arm_m` 之后（对应现在 `arm_b` 的位置）。`deal` 与 `arm_m` 的相对次序不动 |
| **L3κ-O-tail** | `deal` → `arm_m` 保持 v1 前段，两条逐 κ 的基线种子用途都排在它们之后。二者之间谁先谁后仍要在未来文本写死；本行不代写 |

用途内部的比较次序候选（与 §5.3 的字段名候选对齐之后才能定稿）：`campaign`（字符串）→ `block` → `hand`／`hand_ordinal` → `seat` → `event_index` → `σ_public` 的无损编码（字节序或其所选编码的字典序）。`74ai` 要求 `event_index` 在同一 `(seat, hand_ordinal)` 上不回退；遍历规则不得靠重排键来重复使用同一个 `event_index`。

读取对象只能是 §5.3 已经闭合的那份有限键集。物理 `read_index` 走这批预注册键，不在运行中按新出现的状态追加。用途级选用 **L3κ-O-after-deal** 还是 **L3κ-O-tail**，仍未选定；清单升序的字段表也仍未选定。两套次序都只排列生成前已经列出的键。

### 5.7 拒绝规则

v1 规则标识 `rejection-whole-multiple-truncation-v1` 指称整倍数截断的全部句子。`74r` §6.5 写明：规则内容有变就必须换标识，并且用新的 `74` 后缀承接。本提案遵守该纪律，同时不在 v1 里换标识。

| 候选 ID | 内容 |
|---|---|
| **L3κ-R-keep-id** | 新文本逐字沿用同一接受公式 `B = D·⌊2^w / D⌋`、`raw_value < B` 时输出 `raw_value % D`、仅 `[B, 2^w)` 被拒绝、拒绝后以同一用途、同一完整键、同一位宽继续读取、接受后不得再读、同键拒绝与接受相邻。因此**继续引用**现标识。`D` 变小、拒绝区间非空，仍是该公式的实例，不另写一套算法 |
| **L3κ-R-new-id** | 仅当接受公式、拒绝处理、读取顺序或同键约束发生改变时，在**新后缀文档**中使用新的规则标识。v1 标识保持只指称 v1 的那一套语义 |

与 §5.4 的关系：**L3κ-D-narrow** 与 **L3κ-R-keep-id** 可以同时成立。非空拒绝区间本身不改变整倍数截断规则。把「本用途在 `D = 2^w` 时不会拒绝」写成该公式的推论，也不是新的规则语义。本文仍不选定域，也不选定是否换标识。

| 组合 | 相容 |
