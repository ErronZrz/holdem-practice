## 4. (α) 与条件性 B-1

### 4.1 (α)：运行器按身份无关的方式设计

- 被测座位的构造路径是**可替换的输入映射**；首次实现只支持两种接口：混合策略族的主键接口（`74m` §6.2）与受控注册表的 `seed` 接口（`74m` §6.3）。
- 被测身份的创建与冻结**另行处理**，不在运行器设计范围内。
- **收紧（用户调整原文要点）**：未来运行器**只接受显式的被测身份构造映射**；**不得**在运行时由策略别名、类名或未冻结的默认值隐式选择身份。该映射须以被测身份的规范标识为键，并纳入执行身份（`74m` §7.4）。

### 4.2 条件性 B-1

- B-1 **仅在**被测身份实际采用混合策略族构造时适用；
- B-3 **不**被写为现有运行器选项（照 `74m` §6.2）；
- 被测身份若不属混合策略族，风格口径须随该身份另行裁定。

### 4.3 B-1 的估计对象限定（必写项）

在条件性 B-1 适用时，下列限定是裁定正文的一部分，**不是**解释性备注：

- 比较对象绑定三项：后续冻结的被测身份规范标识；输入口径 `bot_seats = (被测座位,)`；由此确定的固定 `TIGHT` 风格。
- 该条件性 B-1 **不是**「完整混合策略族」的结论，也**不**覆盖该身份在其他风格或其他 `bot_seats` 口径下的行为；任何后续结论只能覆盖该特定风格与输入口径下的比较对象。
- 上述三项须写入域 C 的估计对象定义，并随域规格一同冻结。

## 7. 登记：§6.2 顺序与 `74f` 核验时点之间的张力

`74f` §4.1 第 6 条与 §5 第 3 条登记：形式、机械、前提三类核验「均应在**清单冻结前**完成」。§6.2 的顺序把「③ 核验」置于「预注册冻结」与「生成材料 / 运行」之后。

两者的关系有至少两种读法，本文件**不**选择：

- 读法一：§6.2 中的「③ 核验」指对**已冻结设计与已生成材料**的执行核验；`74f` 所要求的清单冻结前三类核验（对推导与前提的形式 / 机械 / 前提核验）仍须在「预注册冻结」之前另行完成。
- 读法二：§6.2 调整了 ③ 的时点，需以新裁定修订 `74f` 的相应登记（`74f` 正文不改，由新编号文档承接）。

在用户裁定前，本文件按**更保守**的方式处理：`74f` 的「清单冻结前完成三类核验」要求**继续有效**，§6.2 不被视为对其的修订。
