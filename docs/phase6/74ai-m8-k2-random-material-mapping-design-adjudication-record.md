## 4. K-2 映射：固定函数与决策键（写定）

### 4.1 与 `74k` §5 K-2 的对齐

本裁定将 `74k` K-2 具体化为：

```text
「其他座位共用随机材料」= 在域 C 配对比较中，对每一非被测座位 s、每一决策时刻，
存在由下列决策键 κ 索引的固定材料值 M(κ)；
两臂在该手牌局中，对相同 κ 必须使用相同的 M(κ)；
该映射 M 在运行前随机化协议与 L-3 落盘义务下确定，不得由任一侧臂内
可变推进随机源在运行时隐式改写。
```

**禁止表述（延续 `74k` §5）**：

- 不得把「相同初始 seed」或「每手单一注入 seed」表述为：在历史分叉后，各决策点随机取值**必然**相同。

### 4.2 决策键 κ（写定）

```text
κ := ( seat, hand_ordinal, event_index, σ_public )
```

| 分量 | 含义 |
|---|---|
| **`seat`** | 非负整数；须等于决策时刻 `GameState.current_seat`，且为本次注入 `M(κ)` 的**行动者座位**；与运行前 schedule／`HandPlan` 一致 |
| **`hand_ordinal`** | 块内手序正整数，与 `74y`／schedule 显式字段一致 |
| **`event_index`** | 非负整数；对该 `(seat, hand_ordinal)`，从 **0** 起，每在该座发生**一次**决策机会（包外编排调用策略／提交行动之前）递增 **1**；**不**回退、**不**跳号复用 |
| **`σ_public`** | **规范公开投影字节串**（§4.2.1–§4.2.5）；**不是**哈希摘要；两臂在相同决策边界须得到**相同** `σ_public` |

**固定映射**：

```text
M : κ ↦ 材料单元（类型与字节语义由 L-3 用途与基线成员构造注入接口在实现授权中写定）
```

- 对给定 campaign 预注册与一次性生成的 `Z_h`，`M(κ)` 须为 **κ 的函数**，且可从 L-3 审计记录追溯。
- **两臂**：对同一 κ，**同键同值** — `M_m(κ) = M_b(κ) = M(κ)`（`Q_h^{opp}` 共享语义，`74j` §5.1，经 K-2 限定）。

#### 4.2.1 决策边界输入（写定）

在形成 κ 的**唯一**瞬间，包外编排须固定下列输入（**禁止**使用 Python `repr`、`dict` 遍历顺序或未列字段）：

| 符号 | 来源 | 时机 |
|---|---|---|
| **`G`** | `PokerEngine.snapshot()` → `GameState`（`backend/app/poker/state.py`） | **紧接在**该 `seat` 即将行动之前；两手内须与引擎内部状态一致 |
| **`L`** | `PokerEngine.legal_actions()` → `LegalActions`（`backend/app/poker/actions.py`） | 与 **`G` 同一引擎状态**；且须满足 `G.current_seat == seat` |

**排除（不得进入投影）**：`PlayerState.hole_cards`、`PlayerState.name`、牌堆、RNG 内部状态、`history`、私牌映射、身份读数、任一侧臂独有未在 §4.2.3 列出的字段。

#### 4.2.2 规范串 `S` 与 `σ_public`（写定）

1. 计算规范串 **`S`** = `EncodeK2PublicV1(G, L)`，算法见 §4.2.3–§4.2.4。
2. **`σ_public`** := **`S` 的 UTF-8 编码字节序列**（**不**使用 SHA／MD5 等摘要；**不**使用未说明的序列化）。
3. **唯一性义务**：
   - 若两份合法输入 `(G, L)` 经 `EncodeK2PublicV1` 得到不同 `S`，则 `σ_public` **必须**不同（字节级）。
   - 若 `S` 相同，则 `σ_public` **必须**相同。
4. **禁止**：省略字段、追加未规定字段、用「等」扩展字段集、或以语言运行时默认格式化整数／布尔／牌面。

#### 4.2.3 封闭、有序字段集（`EncodeK2PublicV1`）

`S` 由 **恰好** 下列行组成，行分隔符为 **单个 U+000A 换行符** `\n`（最后一行后**无**尾随换行）。每行格式为 **`name=value`**，`name` 为下表给定字面量，`value` 不含 `\n` 或 `=`。

**A. 模式与全局（固定 7 行）**

| 行序 | `name` | `value` 规则 |
|---:|---|---|
| 1 | `schema` | 字面量 `k2-public-projection-v1` |
| 2 | `street` | `G.street` 的 `IntEnum` 整数值，`0`–`4`（`Street`：`PREFLOP=0` … `SHOWDOWN=4`） |
| 3 | `hand_over` | `1` 若 `G.hand_over` 为真，否则 `0` |
| 4 | `button` | `G.button`，规范整数（§4.2.4） |
| 5 | `current_seat` | `G.current_seat`，规范整数 |
| 6 | `pot` | `G.pot`，规范整数 |
| 7 | `n_players` | `len(G.players)`，规范整数；须满足 `n_players ≥ 2` 且后续玩家行数等于本值 |

**B. 公共牌（`1 + len(G.board)` 行）**

| 行序 | `name` | `value` 规则 |
|---:|---|---|
| 8 | `board_len` | `len(G.board)`，规范整数 |
| 9+i | `board.{i}` | `i` 从 `0` 到 `board_len-1`；值为 `G.board[i]` 的**规范牌面**（§4.2.4）；**保持 `G.board` 顺序**，不排序 |

**C. 玩家公开状态（对每个 `s = 0, 1, …, n_players-1` 恰好 6 行）**

对固定 `s`，令 `P` 为 **`G.players` 中满足 `P.seat == s` 的唯一元素**；若不存在则 `EncodeK2PublicV1` **失败**（不得生成 κ）。行名中的 `{s}` 为十进制规范整数 `s`：

| 行名 | `value` 来源 |
|---|---|
| `player.{s}.stack` | `P.stack` |
| `player.{s}.folded` | `1` 若 `P.folded` 否则 `0` |
| `player.{s}.all_in` | `1` 若 `P.all_in` 否则 `0` |
| `player.{s}.street_bet` | `P.street_bet` |
| `player.{s}.total_committed` | `P.total_committed` |
| `player.{s}.has_acted_since_full_raise` | `1` 若 `P.has_acted_since_full_raise` 否则 `0` |

**D. 当前行动者合法动作（固定 12 行，来自 `L`）**

| 行序 | `name` | `value` 规则 |
|---:|---|---|
| — | `legal.can_fold` | `1` 若 `L.can_fold` 否则 `0` |
| — | `legal.can_check` | `1` 若 `L.can_check` 否则 `0` |
| — | `legal.can_call` | `1` 若 `L.can_call` 否则 `0` |
| — | `legal.call_amount` | `L.call_amount` |
| — | `legal.actual_call_amount` | `L.actual_call_amount` |
| — | `legal.is_short_all_in_call` | `1` 若 `L.is_short_all_in_call` 否则 `0` |
| — | `legal.can_bet` | `1` 若 `L.can_bet` 否则 `0` |
| — | `legal.min_bet` | `L.min_bet` |
| — | `legal.max_bet` | `L.max_bet` |
| — | `legal.can_raise` | `1` 若 `L.can_raise` 否则 `0` |
| — | `legal.min_raise_to` | `L.min_raise_to` |
| — | `legal.max_raise_to` | `L.max_raise_to` |

**行序总规则**：先 A（7 行），再 B，再 C（按 `s` 升序），再 D（上表顺序）。**不得**重排、合并或省略。

#### 4.2.4 规范化规则（写定）

| 类型 | 规则 |
|---|---|
| **规范整数** | 与 `74r` L-3 整数字段一致：非负时十进制 ASCII、**无前导零**（`0` 本身为 `"0"`）；负整数不在本投影中出现（若出现则编码失败） |
| **规范布尔** | 仅字符 `0` 或 `1` |
| **规范牌面** | 与 `str(Card)` 一致：一点数字符 + 一花色小写字母；点数表 `2–9`、`T`、`J`、`Q`、`K`、`A`；花色 `c`,`d`,`h`,`s`（见 `backend/app/poker/cards.py`） |
| **字符串拼接** | 每行 `name=value`；`name` 仅含 `[a-z0-9_.]` |

#### 4.2.5 κ 与 `M(κ)` 的相等比较（写定）

| 对象 | 相等 |
|---|---|
| **`σ_public`** | UTF-8 字节序列**逐字节相同** |
| **`seat`、`hand_ordinal`、`event_index`** | 整数**数值相同** |
| **κ** | 四分量**分别**按上表相等 |
| **`M(κ)`** | 在 L-3 落盘的材料单元上**八位组序列相同**（具体单元类型由 L-3 写定；本裁定**不**生成实例） |

**推论（写死）**：规范投影 `EncodeK2PublicV1` 中**任一规定字段**不同 ⇒ `S` 不同 ⇒ `σ_public` 不同 ⇒ 除非 `seat`／`hand_ordinal`／`event_index` 亦变，否则不得复用同一 κ 的 `M(κ)`。

### 4.3 历史分叉与同键规则（写定）

| 规则 | 内容 |
|---|---|
| **分叉后键不同** | 若两臂在对应决策边界的 `(G, L)` 使 `EncodeK2PublicV1` 得到不同 `S`，则 `σ_public` 不同，后续 κ **不同** |
| **禁止复用** | **不得**在 `σ_public`（字节）不同的情况下，复用同一 `(seat, hand_ordinal, event_index)` 的 `M(κ)` 并声称满足 K-2 |
| **`event_index` 单调** | 固定 `(seat, hand_ordinal)`：每次在该座新的决策边界递增 `event_index`；**禁止**在不同 `σ_public` 下重用同一 `event_index` |
| **私牌不影响 `σ_public`** | 仅 `hole_cards`／`name` 不同而 §4.2.3 投影相同 ⇒ `σ_public` **相同**（配对比较同 deal 下预期行为） |
| **与 P-a 衔接** | 仍接受 `74k` §4.2 **P-a** 方向：每手每臂每座可新建实例；本裁定要求：对基线成员（K-1 待定），在**每一决策**注入 `M(κ)`，**而非**仅手级单次 seed |

### 4.4 与 `heuristic@1` 的关系（不选定 K-1）

- `heuristic@1` 仅作为用户选择 K2-P-i 时的**只读事实引用**（§3.1）；
- **K-1 未选定**时，不得登记「基线已是 `heuristic@1`」为战役冻结事实；
- 若将来 K-1 裁定的单一基线成员**不能**支持「逐决策新建实例 + 按 κ 注入 `M(κ)`」构造，则本 K-2 裁定**失效**，须**新后缀** K-2 设计裁定（**不得**就地改写本文件）。
