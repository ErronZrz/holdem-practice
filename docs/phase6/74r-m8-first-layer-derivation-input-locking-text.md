### 4.2 抽取规则（不放回互换抽取）

- 必须满足 `0 ≤ v_k < 52 − k`，越界即硬失败；
- 交换工作序列第 `k` 位与第 `k + v_k` 位；
- 输出交换后的第 `k` 位。

一手的抽取次数恰为 `2N + 5`。`v_k` 就是 L-3 中用途 `deal`、索引键 `draw = k` 的被接受输出。

- 座位 `s`（`s = 0…N−1`，按座位号升序，与庄位无关）的底牌为 `(o_{2s}, o_{2s+1})`；

2 \le N \le 23
\]

### 6.3 索引字段口径

| 字段 | 取值规则 |
|---|---|
| `campaign` | `campaign-configuration-v1` 规范载荷的 SHA-256 摘要，小写 64 位十六进制；按字符串比较（定长小写十六进制，字符串序与数值序一致） |
| `block` | 非负整数块序号；必须等于运行前规格中新增的块序号字段 |
| `hand` | 正整数；必须同时等于同手 `HandMaterials.hand_ordinal` 与 `HandPlan.hand_ordinal` |
| `draw` | 手内从 `0` 起连续的整数，数量恰为 `2N + 5` |
| `seat` | 非负整数；一手的 `seat` 取值集合恰为 `{0…N−1} \ {被测座位}` |

- **承载与渲染**：当前实现中索引键是字符串元组（`materials.py:23`、`protocol.py:300`）。本锁定下整数字段在索引键中一律渲染为**无前导零的十进制 ASCII 数字串**（`0` 渲染为 `0`，不带符号、空白或分隔符），并**按整数解析与比较**；**不**采用固定宽度零填充字符串作为数值比较方式（本轮裁定 ② 第 4 条）。本条的渲染形式取自本轮裁定 ⑤ 第 2 条的整数渲染规则。

- **运行前规格**须新增显式的 `campaign` 标识与 `block` 序号字段，不得再以清单外隐含作用域或固定字符串代替（缺口 G-2）。

### 6.4 遍历顺序

- 用途级：`deal` → `non_probed` → `arm_m` → `arm_b`（写死）。
- 用途内：按完整索引键升序，逐字段比较；`campaign` 按字符串比较，其余字段按整数比较。
- 同一完整索引键的全部读取（零或多条拒绝、恰一条接受）必须**相邻**。

### 6.5 拒绝规则（整倍数截断）

对该次抽取的输出域大小 `D` 与位宽 `w`：

\[
B = D\left\lfloor \frac{2^w}{D} \right\rfloor
\]

- 原始值取值范围为 `[0, 2^w)`；
- `raw_value < B` 时接受，输出 `raw_value % D`；
- 仅 `[B, 2^w)` 被拒绝；
- 拒绝后必须以**同一用途、同一完整索引键、同一位宽**继续读取；
- 接受后不得再读取同一键；
- 同一键的拒绝与最终接受必须相邻。

由本规则直接推出（不是额外假设）：`non_probed`、`arm_m`、`arm_b` 的 `D = 2^w = 2^256`，所以 `B = 2^256`，这三种用途不会发生拒绝；`deal` 在 `draw = 0` 时 `D = 52`、`B = 208`，拒绝区间为 `[208, 256)`，其余各步按同一公式逐步计算。

**规则标识与规范绑定（第三轮复审裁定 R3-3）**：本节规则的规范标识为 `rejection-whole-multiple-truncation-v1`。该标识**指称且仅指称**本节上述规则的全部内容——接受上界公式 `B = D·⌊2^w / D⌋`、`raw_value < B` 的接受判定、输出 `raw_value % D`、仅 `[B, 2^w)` 被拒绝、拒绝后以同一用途、同一完整索引键、同一位宽继续读取、接受后不得再读、同键拒绝与接受相邻。标识必须作为字段写入协议载荷（§8.3.4 的 `rejection_rule`），因而进入 `randomization-protocol-digest`；对本节规则任何一项内容的变更，**必须**同时变更该标识（升版本后缀），并以新的 `74` 后缀文档承接。标识相同而规则内容不同，一律视为违反本锁定。标识字符串 `rejection-whole-multiple-truncation-v1` 与字段名 `rejection_rule` 已经审查方第四轮复审对 Q-12 **确认**。

### 8.1 补充裁定内容（写入）

#### U-1 字节序（影响 L-2、L-3）

采用**无符号大端**，两条路径统一：

1. 原始字节段转整数：`raw_value = int.from_bytes(segment, "big", signed=False)`；`segment` 长度必须恰为 `bit_width / 8`。
2. `arm_m` 整数转主键：`key = value.to_bytes(32, "big", signed=False)`；必须先满足 `0 ≤ value < 2^256`；输出必须恰为 32 字节。
3. 禁止小端、符号整数、变长字节串、截断、补模或其他隐式转换。
4. 字节序属于输入映射规范；改变时 L-2、L-3 及依赖它们的 ③ 结论全部失效。

该裁定与当前实现一致（`protocol.py:569-575`；`identity.py:135-141`），但一致性本身不代替后续测试审查（G-9）。

#### U-2 普通文本条目渲染（影响 L-4）

采用**可见 ASCII 原样文本**：

1. 值必须非空。
2. 每个字符必须位于 ASCII `0x21`–`0x7E`。
3. 禁止空格、换行、制表符、其他控制字符及首尾空白。
4. 不执行 Unicode 归一化、大小写转换、引号包裹、反斜杠替换或路径标准化。
5. 值在 `CoverageEntry.value` 中按原字符序列保存；进入外层规范 JSON 时，仅由 JSON 编码器进行必要转义。
6. 规范标识、注册表位置和入口位置均逐字比较。

本版已知普通文本固定值：`heuristic@1`、`mixed-local@9`、`app.strategy.registry.create_strategy`、`app.strategy.heuristic.HeuristicStrategy.__init__`、`python-os-urandom@1`、`local-single-process-no-parallel@1`、`per-hand-arm_b-material`。后三项由审查方第四轮复审补入（R4-2）：`python-os-urandom@1` 与 `local-single-process-no-parallel@1` 本已是 §6.1 的来源与环境锁定字符串，`per-hand-arm_b-material` 是 §7.3 的 `baseline-effective-seed` 固定文本。未来若需要超出可见 ASCII 的普通文本，须以新编号修订。

#### U-3 浮点渲染（影响 L-4）

#### U-5 时间格式与生成器代码摘要（影响 L-3、L-4）

**时间格式**：`generation_started_at` 与 `generation_finished_at` 固定采用 UTC RFC 3339：

```text
YYYY-MM-DDTHH:MM:SS.ffffffZ
```

- 固定六位微秒；
- 只允许后缀 `Z`，不允许时区偏移；
- 必须是有效公历时间；
- `generation_started_at ≤ generation_finished_at`；
- 按实际生成过程记录，不得事后改写以筛选结果。

**源码清单**：所有 `*-code-manifest-digest` 统一使用 `source-manifest-v1`。规范载荷固定为：

```json

  "entrypoints": ["<workspace-relative-posix-path>"],
  "python_version": "<major.minor.patch>",
  "files": [
    {
      "path": "<workspace-relative-posix-path>",
      "sha256": "<lowercase-64-hex>"
    }
  ],
  "dependency_files": [
    {
      "path": "backend/pyproject.toml",
      "sha256": "<lowercase-64-hex>"
    },
```

- **与材料清单的关系**：同一份材料的两种编码——本载荷按逐手分组，`material-manifest` 载荷（§8.3.7）按全局遍历顺序展平；两者的定位集合与取值必须逐项一致（K-5）；二者摘要不同属预期，不得混同。
- 与当前实现的差异：当前材料束按调用方给定次序编码，手间与手内次序均不被约束（`materials.py:80-82`；仅发牌材料手内的抽取次序有校验，`protocol.py:754-765`）；缺口 G-20。本载荷含实际材料取值，**只**在 ⑥ 产生；③ 只用非实际材料夹具核验其结构与排序（P-8）。
