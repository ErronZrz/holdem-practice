## 5. 纯函数、校验与编排（写定）

### 5.1 纯函数只消费公开局面

`k2_public_projection.py` 中的纯函数只消费 `GameState` 与 `LegalActions`。

- 它不导入、不依赖 `strategy/`、`verification/`、`api/` 或 `llm/`。
- `poker/` 因此不因本模块依赖 `api/` 或 `llm/`。`strategy/` 仍只经 `GameState` 与 `poker/` 交互，不读取材料清单，也不改 `HeuristicStrategy` 来注入 κ。
- 决策时刻由包外编排把当时的 `GameState` 与 `LegalActions` 交给该函数，得到 `σ_public`，再在**已生成**材料表中查 seed。
- 本裁定不给出任何 `σ_public` 字节或十六进制实例。

### 5.2 `verification` 只校验已提交记录

`verification/` 保持可配置且不可执行。

- 它只校验已经提交的记录：闭合键集、材料清单、审计，以及 `74an` §4 已列的版本、键形、十六进制文法与摘要绑定。
- 它**不**调用 `k2_public_projection`／`EncodeK2PublicV1` 来推进牌局，不据此从正在进行的对局形成新的 `σ_public`。
- 它不创建引擎，不注入发牌，不提交行动，不调用 `choose_action` 或 `create_strategy`，不读取 `os.urandom`，不补料。
- 三方相等（§3）仍是「未列键不得变成材料」在校验侧的落点。校验失败不触发补读。

### 5.3 包外编排只查已生成材料

编排器位于 `backend/tools/`（§4.2）。它只查生成结束后的材料表。查表键是用途加上该次决策的完整 κ。

- 命中：取出该 κ 的整数 `seed`，再按 `74ak` 新建 `heuristic@1` 实例。
- 未命中：硬失败并停止。不调用生成器，不追加读取，不改写已有 `M(κ)`，不把这次 κ 写回闭合集。

生成在牌局开始前结束。编排只查表。二者之间没有「现用现补」。把查表失败改成回调生成器，就是已排除的 `L3κ-T-append`。
