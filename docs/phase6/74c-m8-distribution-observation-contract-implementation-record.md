## 3. 规范字段名与实现标识符的一一映射

### 3.1 能力声明字段（`74b` §7.2）

| 规范字段 | 实现标识符 |
|---|---|
| `capability_id` | `distribution_observation.CapabilityDeclaration.capability_id`，固定取值由 `CAPABILITY_ID` 给出 |
| `supported` | `distribution_observation.CapabilityDeclaration.supported` |
| `probability_units` | `distribution_observation.CapabilityDeclaration.probability_units`，固定取值由 `PROBABILITY_UNITS` 给出 |
| `modes` | `distribution_observation.CapabilityDeclaration.modes`，固定取值由 `OBSERVATION_MODES` 给出 |
| `mode_weights` | `distribution_observation.CapabilityDeclaration.mode_weights`，固定取值由 `MODE_WEIGHTS` 给出 |
| `amount_semantics` | `distribution_observation.CapabilityDeclaration.amount_semantics`，固定取值由 `AMOUNT_SEMANTICS` 给出 |

声明读取的键为 `resolve_identifier()` 返回的规范策略标识。本轮**只登记一个**身份：研发中的受测身份 `mixed-local@8`。登记不改变该身份的标识、版本、工厂、描述或分布行为；`StrategySpec` 未新增字段，声明存放在与身份记录分离的另一张登记表中。其余身份没有声明条目，读取时按声明缺失失败。

三态义务的落地：声明缺失（含未知标识）→ `DeclarationMissingError`；`supported = false` → 校验直接返回，其余参数不读取、不比对；`supported = true` → 六个字段必须齐备且逐项等于固定取值，否则 `DeclarationInvalidError`。已删除字段 `partition_version` 未在实现中出现。

## 4. 三项能力入口的登记

| 入口 | 实现标识符 | 输入 |
|---|---|---|
| 声明读取入口 | `registry.capability_declaration` | 客户端提交的策略标识 |
| 能力健康读取入口 | `registry.capability_health` | **无输入** |
| 查询调用入口 | `registry.observation_entry` | 客户端提交的策略标识；返回观测句柄 |

三项入口在模块级登记于 `registry.OBSERVATION_ENTRYPOINTS`（键为 `declaration` / `health` / `query`），因此三项均可被静态引用。

- 声明读取与策略实例化**解耦**：读取只访问登记表与标识规范化，不构造策略对象。
- 调用侧不使用隐式探测：实现中不存在以 `hasattr` / `getattr` / `try` + `except AttributeError` 探测能力的分支。
- 观测句柄（`DistributionObservationEntry`）的观测输入为三项：安全状态、合法动作集、可选模式覆盖。
- 查询入口另设一道拒绝执行的守卫：声明为不支持时取句柄即失败。该守卫**不是**判定依据——「能力不可用」由声明得出，见 §6。

## 5. 能力级探测的落地（`74b` §7.2 `P_cap`）

### 5.1 静态入口检查

只读 `registry.OBSERVATION_ENTRYPOINTS` 的三个键是否齐备且为可调用对象；**不发起任何调用**。入口存在但调用时出错**不**构成该项成立。

### 5.2 无状态能力健康读取

- 实现标识符：`distribution_observation.health_status()`，由 `registry.capability_health()` 转发。
- 无任何输入：不接受 `GameState`、`LegalActions`、节点标识、种子或任何状态化输入。
- 不读取对局状态、不影响任何随机流与对局状态。
- 返回语义为二元封闭枚举：`CapabilityHealth.AVAILABLE`（`available`）与 `CapabilityHealth.UNAVAILABLE`（`unavailable`）。载体的形态是**枚举成员本身**，不是异常、不是超时、不是不可解析结果。
- 判据：能力实现（观测入口登记表）是否已装载。已装载返回 `available`；未装载返回 `unavailable`。
- `unavailable` 是该项成立的**唯一**触发；`available` 时该项不成立。

### 5.3 固定完成时点与边界

- 两项探测只依赖注册表与实现装载情况，**不依赖**任何节点、清单、seed、`code_identity` 或状态化探测对象，因此不引入任何需要另行冻结的探测输入。
- 两项探测可在注册表读取与声明校验通过之后、首次节点查询之前一次性完成；结果一经产生即固定，实现中不提供任何重判、追加或按节点结果修正的入口。
- 固定返回语义之外的任何情况（异常、超时、不可解析、枚举外取值）：本实现的无状态读取无输入、无可变状态且不抛异常，故不产生该路径。若未来该入口被替换实现，调用方必须按契约把此类情况记为**探测证据不足**（既不判为声明与行为不一致，也不得解释为能力可用）。
- 禁止由节点级技术错误计数、其连续性、已发起查询数或作废率推导该判定：实现中不存在此类推导，节点查询路径也不向该判定写入任何信息。

## 6. 失败类别、错误类型与发生阶段

类别与类型（六类，声明阶段失败细分为两个类型）：

| 类别 | 实现类型 | 发生阶段 | 触发条件 |
|---|---|---|---|
| 声明阶段失败 | `DeclarationMissingError` | 注册表读取阶段 | 登记表中无该标识的声明条目；或标识本身未注册 |
| 声明阶段失败 | `DeclarationInvalidError` | 声明读取 / 校验阶段 | `supported = true` 时字段缺失或固定取值不符 |
| 能力不可用 | `CapabilityUnavailableError` | 注册阶段 | 声明 `supported = false`；由调用方依据声明判定，查询入口仅设拒绝执行的守卫 |
| 声明与行为不一致 | `DeclarationBehaviourMismatchError` | 查询阶段 | 输出元数据与已通过的声明逐项不一致 |
| 非法输入 | `IllegalObservationInputError` | 查询阶段（输入侧） | 安全状态不可用、合法动作集自相矛盾或区间不成立、行动者不在该身份的座位集合内、模式覆盖取值不受支持 |
| 技术错误 | `ObservationTechnicalError` | 查询阶段（技术侧） | 分布构造过程中出现内部故障，结果不可进入单位校验 |
| 语义不合规 | `ObservationSemanticError` | 查询阶段（输出侧） | 输出结构或取值不满足硬约束，或合并与取整守卫不通过 |

可区分性：七个类型互不继承彼此（共同基类为 `DistributionObservationError`），调用方可按类型分别识别上述六类。类型与阶段一一对应，不存在同一事件同时落入两类或两条阶段的路径。

封闭集合与可达性说明：

- 声明与行为不一致只覆盖「已通过的声明字段与后续可观察行为直接矛盾」：输出元数据与声明比对（对应 `probability_units` / `mode_weights` 两项），以及静态入口检查与无状态健康读取。实现中不存在以「违反冻结的行为要求」为覆盖条件的分支。
- 「参与合并的权重与已通过的声明不一致」不存在可达路径：参与合并的权重取自声明校验通过的固定常量；声明若取值不符已在声明阶段失败。实现未为此增设分支。
- 成功路径的两项输出元数据与声明取自同一组冻结常量，因此天然一致；保留比对守卫的目的，是让未来可能出现的偏离显式失败而不是静默通过。
- 声明阶段失败与能力不可用都发生在注册与声明阶段，实现中不向任何节点级计数写入信息（实现本身也不持有此类计数）。

## 7. 金额语义与两类整数的落地

- `amount`：非负整数**筹码**单位。`FOLD` / `CHECK` / `CALL` 的输出金额恒为 `0`，由输出结构的校验强制；`BET` 取值须落在闭区间 `[min_bet, max_bet]`（本街新增投入总额）；`RAISE` 取值须落在闭区间 `[min_raise_to, max_raise_to]`（加注后本街总额）。区间两端均合法，比较使用闭区间，**不排除端点**。上述区间与动作类型一致性在查询阶段以「与合法动作集比对」的守卫检查。
- `units`：非负整数**概率**单位，**无量纲**；候选单位总和**恰等于** `1_000_000`。不以重新归一化掩盖不合规输出：总和校验不通过即按语义不合规失败。
- 两类整数分别落在 `amount` 与 `units` 两个字段上，实现中不存在把二者相加、比较或混入同一聚合的代码路径；两者都以 `int` 表示，不引入浮点、分数或近似浮点表示。
- `FOLD` / `CHECK` / `CALL` 输出金额为零是**输出侧**要求，不是引擎取值域；实现不据此推断或改变引擎行为，引擎与金额语义未被改动。
- 单位数为 `0` 的候选可以出现在输出中（合并与单一模式两种口径都可能产生），它们不影响任何抽样结果，因为观测路径不执行抽样。
- **未落地**：金额分区及其归属规则、主动单位总和与条件额度分布的定义链属域 B 规格内容，本轮不在第 (2) 步实现范围内，因此实现中不含金额桶、补集桶、静态完备性或运行时守恒的代码路径。

## 8. 合并口径的算术与确定性取整

- 权重以整数比 `8 : 1 : 1` 表示，不引入浮点。
- 对候选 `x`，先按 `weight · units` 累加整数分子；同一动作类型与金额相同的候选在**先合并**后参与计算（合并由键 `(动作类型, 金额)` 完成）。某模式缺该候选时按 `0` 计入。
- 精确值以「整数分子 / 权重总和」表示。取整：先向下取整，再按小数余数**降序**逐一加 `1`；余数相同者按候选的规范排序破平——先动作类型序 `FOLD < CHECK < CALL < BET < RAISE`，再金额升序。
- 取整后逐项校验偏差小于一个定点单位（以整数比较实现，不做除法），并校验总和恰为 `1_000_000`；任一项不通过即按语义不合规失败。
- 候选集合是三个模式候选集合的**并集**；某模式缺某候选不视为错误。
- 某模式整体不返回任何候选时**不**按全零静默处理，而是显式失败（按语义不合规类别）。
- 候选输出按规范排序给出：先动作类型序，再金额升序。单一模式口径返回该模式的候选集合，其排列次序同样是规范次序。

## 9. 缓存

**无缓存**。观测句柄只持有身份口径常量（标识、声明、规则口径），每次观测按输入重算，不写任何实例级或模块级可变状态（模块级登记表在导入后只读）。

因此本节没有缓存键口径需要冻结：不存在跨调用复用的中间结果，也就不存在缓存键包含对手私有信息、对局结果或身份读数的风险。观测路径不访问对手底牌、不访问对局结果、不访问本身份或其他身份的历史读数，也不访问除登记表外的任何共享可变状态。
