## 4. 现状（只读事实，非采纳规则）

### 4.1 验证包 `HandPlan` 与规格校验

- `HandPlan` 含 `hand_ordinal`、`button`、`probed_seat`；`DomainRunSpec` 要求 `schedule` 非空、手序严格递增且互不重复、`0 ≤ button, probed_seat < N`（`config.py`）。
- 模块说明写明：手序计划由调用方逐手显式给出；**庄位与轮换规则尚待冻结，本包不代为实现，也不推断**。
- **无**从 `hand_ordinal` 计算 `button`／`probed_seat` 的包内函数；合法性与轮换恒等式**尚未**锁定。

### 4.2 扑克引擎庄位（对照用，**不得**默示为验证规则）

只读事实（`poker/engine.py`）：

- 构造时 `button = num_players - 1`；注释称首手庄位为最后座位。
- `start_hand()` 每手先将 `button` 设为 `(button + 1) % num_players`，再发牌下盲。
- `start_hand_with_injection(..., button=...)` **由调用方指定**庄位，**不**执行上述自增轮转。

验证设计方向（`74j` §6 S-a、`74k` §4.2）为注入开手路径；故**验证域的庄位应以规格／锁定轮换为准**，**不得**把「未注入时会话内自增」当作已锁定的 `seat_rotation` 规则。若将来锁定文本选用的公式与引擎默认自增**不一致**，以锁定文本为准，实现须通过显式 `schedule` + 注入庄位对齐，而不是依赖引擎隐式轮转。

### 4.3 设计文献中的方向（未冻结）

- `74j` §4.1：被测座位相对庄位按块内手序**确定性轮换**为**设计方向**；须冻结属域规格，**不等于**已审查的 `74w` 方差推导已引用。

## 5. 候选方案

以下候选均**待裁定**；编号只用于本提案内引用。

### 5.1 庄位 `button` 与 `hand_ordinal`

记块内手序 `h := hand_ordinal`（正整数），人数 `N`。

| 编号 | 候选 | 内容 | 备注 |
|---|---|---|---|
| **B-0** | 纯显式 | 不规定 `button` 与 `h` 的函数关系；只要求每条计划落在 `[0, N−1]` | 与当前实现校验一致；轮换「规则」最弱 |
| **B-1** | 块内标准递增 | 存在块常数 `b₀ ∈ [0,N−1]`，对 schedule 中每一手：`button = (b₀ + h − 1) mod N` | 与 `74u` R-1 示例同类；`b₀` **待裁定**（是否写入 campaign／块模板） |
| **B-2** | 首手固定末座 | `b₀ = N − 1`，同 B-1 公式 | **形似**引擎构造初值，**但**验证仍走注入路径；**不得**仅因与引擎默认相同即视为已裁定 |
| **B-3** | 跨手任意显式 | 允许 `button` 在块内任意合法序列，仅受范围与（可选）连续性约束 | 估计对象须如实登记「非规则 schedule」 |

### 5.2 被测座位 `probed_seat`

须与 `74r` L-2／`74n` §4.3 一致：`bot_seats = (probed_seat,)`，单被测座位。

| 编号 | 候选 | 内容 | 备注 |
|---|---|---|---|
| **P-0** | 纯显式 | 不规定与 `button`／`h` 的关系；仅 `0 ≤ probed_seat < N` | 与 `74w` §4.3 C-sched 兼容 |
| **P-1** | 固定偏移 | `probed_seat = (button + δ) mod N`，`δ` 为冻结常数（例如 `1`） | 相对位置固定 |
| **P-2** | 随 `h` 轮换 | `probed_seat = (button + h − 1) mod N` 或等价写死的 `f(h)` | 对应 `74j`「按手序轮换」方向；`f` **须写死** |
| **P-3** | 全桌扫描 | `probed_seat = (b₀ + h − 1) mod N`（与 `button` 解耦的独立公式） | 须单独说明与盲注位置、O-a 的关系 |

### 5.3 schedule 供给方式

| 编号 | 候选 | 内容 |
|---|---|---|
| **S-1** | **调用方显式 `schedule`**（`74u` R-4） | 锁定文本规定合法计划须满足的恒等式；包内**不**推断、不生成 |
| **S-2** | 工具生成 `schedule` | 锁定后由包外工具按公式填充 `HandPlan`；须**另案**实现授权（`74u` R-5；**本提案不推荐**） |
| **S-3** | 引擎隐式轮转 | 依赖 `start_hand` 自增庄位、不显式 `schedule` | **排除**：与当前 `DomainRunSpec` 与 S-a 注入路径不一致 |

## 10. 与显式 `HandPlan.button`／`probed_seat` 的关系

| 原则 | 内容 |
|---|---|
| **数据模型不变（提案层）** | 继续每条手一行显式 `button`、`probed_seat`；**不推荐**在本阶段改 `HandPlan` 形状 |
| **锁定的是约束，不是字段** | 锁定文本规定：合法 `schedule` 必须满足哪些恒等式；字段仍由调用方填入 |
