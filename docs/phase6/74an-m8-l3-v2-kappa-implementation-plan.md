## 4. `verification/` 只做校验

当前包的自述与 `runner.py` 的职责是：比对冻结清单和运行前输入，重算摘要，核对材料与审计。本方案把 v2 的校验仍放在这个边界内。

**允许的未来改动（校验，不是推进）**：

- 接受并核对 `randomization_protocol = 2` 的配置载荷，拒绝把版本号 `1` 的摘要当作 v2 键的 `campaign`；
- 核对六字段 κ 键、`sigma_public` 的十六进制文法、`event_index` 在同一 `(campaign, block, hand, seat)` 上只有一条 `sigma_public`、座位是否属于该用途；
- 对**已经提交**的闭合键集、材料清单和审计记录做 §5.1 的相等性校验；生成器不得把「未提交的键」留到校验时再补；
- 核对 32 字节无符号大端与 JSON 整数是同一个 `seed`，且 `0 ≤ seed < 2^256`；
- 核对承诺的 14 个字段名、`sha256`、拒绝标识没有被换成另一套算法；
- 构造计划只**描述**逐 κ 的身份、接口和材料引用，不调用工厂。

**禁止放进 `verification/`**：

| 动作 | 原因 |
|---|---|
| 创建 `PokerEngine` 或任何对局引擎 | 不可执行 |
| 注入发牌、提交行动、循环到终局 | 推进牌局 |
| 在决策边界调用 `choose_action` 或 `create_strategy` | 那是包外编排 |
| 调用 `os.urandom` 或按新状态补一条材料 | 生成属于包外；追加读取已被排除 |
| 为了算出 `EncodeK2PublicV1` 去读取一局正在推进的引擎 | 校验只消费已经给出的记录 |

包内可以有一个**纯函数**，用来检查「已经提交的公开字段字节」和「已经提交的十六进制」是否互逆。这个函数不持有引擎，也不代替决策时刻的编码。决策时刻谁来调用 `EncodeK2PublicV1`，见 §6，本文不选定。

## 5.1 预注册 κ 键集：来源、载体、交接与校验

首轮只写了生成器「消费」键集。本节补上这条链。来源方式并列，**不选择**。闭合集一旦交给生成器，就不再因牌局过程变长。

### 5.1.1 来源／形成方式（候选）

两条候选都在**第一次** `os.urandom` 之前得到一份有限列表。它们都不推进牌局，不调用策略，不读取熵。

| 候选 ID | 形成方式 | 本文 |
|---|---|---|
| **AN-K-explicit** | 运行前预注册逐条写下每一个完整索引键。列表本身就是来源，不再从别的规则展开 | 不选择 |
| **AN-K-product** | 运行前只登记有限分量：允许的 `(campaign, block, hand)`、按用途分开的 `seat` 集合、每个 `(seat, hand)` 上允许的 `event_index` 有限集、允许的 `sigma_public` 十六进制有限集。在读熵之前把这些分量物化成完整键列表，并按用途规则去掉座位不合法的组合 | 不选择 |

物化结果必须可审计，而且在第一次读取之后不得再变。生成器看不到「以后可以再加键」的规则，只看到已经物化的列表。

**排除 `AN-K-runtime`**：用行动历史、策略输出或新出现的 `σ_public` 来追加键。这就是 `L3κ-T-append`。也排除由 `verification/` 创建引擎来枚举键。

### 5.1.2 生成器接收的闭合集对象

不论来源是 **AN-K-explicit** 还是 **AN-K-product**，交接给包外生成器的都是同一角色的输入对象。这里只写最小字段，**不**指定类名、模块路径或序列化格式（那些属于 §6 尚未选定的接口）。

| 最小字段 | 要求 |
|---|---|
| **版本标记** | 整数 `2`，表示 L-3 v2。不是摘要 |
| **条目** | 有限序列。每条有 `purpose_label`，以及该用途在 `74am` §6.1 中的全部索引字段 |
| **κ 键** | `non_probed` 与 `arm_b` 必须带 `campaign`、`block`、`hand`、`seat`、`event_index`、`sigma_public` |
| **其余用途** | `deal` 带 `draw`；`arm_m` 不带座位与 `sigma_public`。键形与 v1 相同 |
| **不允许的内容** | 不带 seed、raw、材料值、digest，也不带「允许运行中追加」的标志 |

对象里的字段顺序不必预先排成规范序。规范序由 §5.1.4 按 `74am` §9 复核。本方案不把「存储时是否先排序」定成唯一接口。

### 5.1.3 生成器的只读门闩

生成器在第一次 `os.urandom` 之前，对这份对象做只读检查。检查函数不增删条目、不读熵、不创建引擎、不调用策略。检查失败则生成器**不返回任何材料、不留下读取记录**。

失败至少包括：

- 版本标记不是 `2`；
- 条目不是有限序列，或出现重复的完整键；
- 同一用途、同一 `(campaign, block, hand, seat, event_index)` 对应两条不同的 `sigma_public`；
- `seat` 与用途不符（`non_probed` 含该手被测座位，或 `arm_b` 不是该手被测座位）；
- `event_index` 为负、`hand` 非正、`block` 为负，或 `sigma_public` 不是正偶数长度的小写十六进制；
- 同一对象里各条目的 `campaign` 字符串不一致；
- 对象带有开放区间或允许追加的标志。

门闩通过之后，生成器只按规范序为清单中的每个键读取到一条接受值（`D = 2^256` 的用途一次读完）。不得读取清单以外的键。`campaign` 是否等于版本号 `2` 的配置摘要，由 §5.1.4 重算核对；门闩不代替那一次重算，也不在本文件里算出摘要。

### 5.1.4 `verification` 的相等性校验

`verification/` 不形成键集。它只接收三份**已经提交**的记录，并在冻结输入主链里做集合与次序核对：

| 记录 | 比对用的键 |
|---|---|
| 闭合键集对象 | 全部条目的完整索引键 |
| 材料清单 | 被接受条目的完整索引键 |
| 审计逐读取记录 | 其中 `accepted` 的完整索引键 |

三者必须相等：不少、不多。此外：

- 审计里出现的每一个 `index_key`（含 `deal` 上被拒绝的读取）都属于闭合集；集外键即失败；
- 材料清单的次序与审计的 `read_index` 符合 `74am` §9，且没有运行中插入的新键；
- 每个键的 `campaign` 等于按 `randomization_protocol = 2` 重算的配置摘要；版本号为 `1` 的摘要失败。

这三份记录的相等，就是「未列键不得变成材料」在校验侧的落点。校验失败不触发补读。

### 5.1.5 包外编排的缺键硬失败

编排器只查生成结束后的材料表。查表键是用途加上该次决策的完整 κ。

- 命中：取出整数 `seed`，新建 `heuristic@1` 实例；
- 未命中：硬失败并停止。不调用生成器，不追加读取，不改写已有 `M(κ)`，不把这次 κ 写回闭合集。

因此生成器与编排器之间没有「现用现补」的交接。闭合集只在生成前进入生成器；材料表只在生成后进入编排器。

## 8. 依赖边界

```text
poker/        不依赖 api/、llm/、verification/、编排器
strategy/     只经 GameState 与 poker/ 交互；不读取材料清单
verification/ 只校验；不依赖编排器或生成器；不创建引擎
生成器        包外；只接受 §5.1 的闭合集；门闩通过后才向 os.urandom 读取；不推进牌局
编排器        包外；可调用 poker 的推进、strategy 的现有工厂、verification 的校验；只查已生成材料表；缺键硬失败，不回调生成器
```

生成器与编排器分开：生成在牌局开始前结束；编排只查表。把二者写成同一个「边打边补料」的过程，就是 `L3κ-T-append`，本方案不予映射。
