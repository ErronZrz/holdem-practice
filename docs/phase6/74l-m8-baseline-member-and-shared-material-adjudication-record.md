## 4. K-1：单一基线成员为 `heuristic@1`

### 4.1 裁定内容

在每个域 C 比较中固定：

| 位置 | 身份 |
|---|---|
| 臂 `m` 被测座位 | 被测身份 |
| 臂 `b` 被测座位 | `heuristic@1` |
| 两臂全部非被测座位 | 同一 `heuristic@1` |

- 一律使用规范标识 `heuristic@1`，**不**使用无版本别名 `heuristic`。
- 只读事实：注册表以规范标识 `heuristic@1` 登记该策略，别名为 `heuristic`，描述为「基于胜率与底池赔率的启发式策略，同时是教学参考基线」（`registry.py` 第 131–140 行）。
- 只读事实（须区分两层接口）：
  - **受控注册表工厂接口**：注册项工厂的类型为「接受 `int | None` 并返回策略」（`registry.py` 第 43–51 行）；按标识构造的入口接受 `seed: int | None = None` 并原样传给注册工厂（第 87–89 行）；`heuristic@1` 的注册工厂只把该 `seed` 传给类构造器，其余构造参数取类默认值（第 136 行）。
  - **`HeuristicStrategy` 类构造接口**：除 `seed: int | None` 外，还有 `samples` 与 `bluff_freq` 两个参数（`heuristic.py` 第 127–135 行）。**不得**声称该类构造器只接受一个整数参数。
- 验证运行通过受控注册表为 `heuristic@1` 提供一个 `seed` 参数；预注册必须冻结原始材料有限输出域到实际整数 `seed` 的固定映射（见 §6 第 3 项）。

### 4.2 角色限定（写死）

`heuristic@1` 在本战役中的角色**仅限于迁移 / 比较基线**。**不得**表述为：真实强度上界、GTO、质量基准，或「可接受强度」的定义。

### 4.3 未选其他成员的理由（照录）

- `heuristic@1`：当前默认策略，且为受控注册表中的稳定版本化身份。
- `random@1`：同样有推进随机源，但作为对手条件的解释价值较弱。
- `mixed-local@8`：仍属质量未获支持的研发身份，不宜作为此阶段唯一基线。

## 5. `74k` §7.1：选定候选 (ii)，K-2 收窄为有限共享声明

### 5.1 裁定内容

选定 **候选 (ii)**：

> 两臂中每个非被测座位在同一手收到相同的「每手初始随机材料」；一旦两臂历史分叉，不主张后续逐决策随机取值仍相同。

### 5.2 理由（照录）

1. 域 C 的 C-2′ 只要求不同手的 `Z_h` 独立，不依赖非被测座位在两臂内逐决策共享。
2. `heuristic@1` 的胜率抽样与动作抽样共用同一实例随机源；同一手中不同决策会推进该随机源（只读事实：`heuristic.py` 第 133、151–162、214–221 行）。直接主张逐决策共享不符合其当前随机结构。
3. 候选 (i)（每次决策新建实例）会改变其**一手内**的随机化供给方式，比「每手新实例、手内保持现有行为」更偏离既有执行语义。
4. 候选 (iii)（修改策略代码）默认越界，也更可能触及策略与参考版本化问题。

### 5.3 不建议项（照录）

- **(i)**：除非后续明确目标是最大化逐决策公共随机数，并愿意把「每次决策新建启发式实例」作为新的执行身份口径审查。
- **(iii)**：会修改策略随机化实现，超出当前未授权范围，并可能改变 `heuristic@1` 的语义。
- 不将 `mixed-local@8` 选为唯一基线：质量仍未获支持，且与当前研发 / 验证战役的对象边界不够清晰。

### 5.4 K-2 替代表述（取代 `74k` K-2）

**K-2′**（用户裁定文本）：

> 对每手 `h`、每个非被测座位 `s`，两臂共享同一份按 `(campaign configuration, block, h, s)` 索引的初始随机材料。该材料仅保证两臂从相同的该手、该座位初始随机状态开始；若两臂历史分叉，**不主张**后续逐决策随机取值、随机调用次数或行动结果相同。此共享仅作为可能降低配对差离散度的设计选择，不是 C-2′、C-1′ 或任何质量结论的依据。

**附加要求**（用户裁定）：

1. 索引键中**不得**包含策略输出、收益、结果或候选身份读数；
2. **不**以状态摘要作为主键（两臂分叉后状态不同，易使共享规则变成结果依赖规则）；
3. 实际随机材料、键值、seed 与清单仍在 ⑥ 前才生成 / 冻结；
4. K-2′ **不改变** `74k` K-3（不同手 `Z_h` 独立生成）的要求。

**补充（经本次授权一并落盘）**：
