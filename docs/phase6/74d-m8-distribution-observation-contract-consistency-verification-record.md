## 3. 要求 A：逐模式条件分布与运行态采样同源（`74b` §4.1）

**方法**：对每个节点与每个模式 `m`，把三处产物逐项比对：

1. 观测入口的单一模式输出（`aggregation = mode_override`，`overridden_mode = m`）；
2. 运行态实例的显式模式查询（按该身份与状态座位集合构造的实例，指定模式 `m`）；
3. 采样前直接构造的条件分布（同一安全输入、同一合法动作集、同一风格、同一规则口径、同一模式）。

对照项为逐项相等：候选的动作类型与金额、单位向量、规范次序，以及输出口径标记。

**结果**：`32` 节点 × `3` 模式 = `96` 组比对，全部逐项一致。

**说明**：三处共用同一分布构造路径，且观测入口按运行态的座位集合与风格分派还原风格，实现未另建「报告用分布」，也未对采样分布作平滑、截断、重归一化或四舍五入。

## 4. 要求 B：边缘化输出由同一组条件分布唯一构造（`74b` §4.1 / §5.5）

**方法**：对每个节点，取三个模式覆盖输出，按整数权重 `8 : 1 : 1` 与确定性取整规则用**独立复算**求合并结果，再与主判输出逐项比对。独立复算的取整为：精确有理值 → 向下取整 → 剩余单位按小数余数降序逐一加一 → 余数相同者按候选规范次序（先动作类型序，再金额升序）破平。同时逐候选校验偏差小于一个定点单位，并校验总和。

**结果**：

- `32` 节点全部逐项相同；候选集合等于三个模式候选集合的并集，且按规范次序排列。
- 每个节点、每个候选都满足偏差小于一个定点单位，总和恒为 `1_000_000`。
- 主判输出未携带任何单一模式标记（`overridden_mode` 恒为空），即未被某一次具体模式取值替代。
- 合成用例固定了破平规则的黄金值：两个候选余数相同（各为 `5`）且只剩一个单位可分配时，归规范次序在前的跟注候选，结果为跟注 `460_001` / 主动 `539_999`。

**说明**：合并只在输出层进行，候选金额取自各模式构造结果，未在合并中新增或拆分候选。

## 5. 观测无副作用（`74b` §4.2）

**方法**：对每个节点，先记录引擎状态签名（街、公共牌、底池、当前行动者、是否终局、公开事件数、逐座位的剩余筹码 / 本街投入 / 累计投入 / 弃牌 / 全下）与运行态动作采样的基准结果，然后多次执行两种口径的查询，再复核。

**结果**：`32` 节点全部成立：

- 查询后同一实例与新建实例的动作采样结果都与基准一致；
- 引擎状态签名与合法动作集均未改变；
- 同一输入重复查询结果相等（可重复一致）。

**说明**：观测句柄只持有身份口径常量，不持有跨调用可变状态；实现中不存在缓存，因此不存在「缓存影响采样结果」或缓存键越界的可能。

## 6. 单位、金额与输出结构（`74b` §5.2–§5.4 / §7.4 / §7.5）

**方法**：对每个节点分别执行主判口径与三个模式覆盖口径，共 `4` 种查询。

**结果**：`32` 节点 × `4` 口径 = `128` 组，全部成立：

- 输出元数据与已通过的声明逐项一致（定点单位总和、模式权重）；
- 候选键（动作类型 + 金额）唯一，且按规范次序排列；
- 单位与金额两类量都是整数，均非布尔、非浮点；
- 单位总和恒为 `1_000_000`；
- `FOLD` / `CHECK` / `CALL` 的输出金额恒为 `0`；
- `BET` 金额落在闭区间 `[min_bet, max_bet]`、`RAISE` 金额落在闭区间 `[min_raise_to, max_raise_to]`，端点包含在内；
- 口径标记与覆盖模式字段的约束成立：主判口径不携带覆盖模式，单一模式口径必须携带且取值属于受支持模式集合。

## 7. 信息边界与非法输入（`74b` §4.3 / §7.2 / §7.6）

**结果**：

- 泄漏其他座位底牌的快照：`32` 节点全部被拒绝（输入层即拒绝，观测路径无法读到对手私有信息）；
- 未附加公开摘要的状态、自相矛盾的合法动作集、不受支持的模式覆盖取值、行动者不属于该身份座位集合：均被拒绝，且拒绝类型可区分；
- 观测入口的安全输入只有三项：安全状态、合法动作集、可选模式覆盖。

## 8. 声明、三项入口与失败类别（`74b` §6.1 / §7.2 / §7.6 / §7.7）

**结果**：

- 声明读取键为规范策略标识；六个字段的取值与冻结值逐项相等；未知标识与「未声明该能力的已注册标识」都按声明缺失失败；`supported = false` 时只认两个字段，其余参数不被读取或比对。
- 三项能力入口（声明读取、能力健康读取、查询调用）在模块级登记且可静态引用；静态入口检查不发起任何调用。
- 无状态健康读取不接受任何输入，返回二元封闭枚举的 `available`；不可用状态同样是**返回值**，不是异常或不可解析结果。
- 七类失败类型两两不互为子类、都派生自同一基类，从而形成六类可区分性（声明阶段失败细分为「声明缺失」与「声明取值不符」两个类型）。
- 「参与合并的权重与已通过的声明不一致」没有可达路径：参与合并的权重取自声明校验通过的固定常量，声明取值不符在声明读取阶段即失败。输出元数据与声明的比对守卫保留，使未来可能的偏离显式失败而不是静默通过。

## 9. 模式概率无关性：P1 / P2 的验证工件（`74b` §4.5）

### 9.1 (a) 取值集合与概率值的逐项对照

| 随机源取值 | 模式 | 概率 |
|---|---|---|
| `0 – 79` | `normal` | `80 / 100 = 0.80` |
| `80 – 89` | `cautious` | `10 / 100 = 0.10` |
| `90 – 99` | `pressed` | `10 / 100 = 0.10` |

判据（已执行）：对 `[0, 100)` 的全部 `100` 个取值逐一枚举模式映射，得到 `80 / 10 / 10`，与分段边界常量 `(80, 90, 100)` 一致。

### 9.2 (b) `Ω`、`P` 与 `M` 的显式定义

```text
Ω      = {0, 1, …, 99}
P      = Ω 上的均匀分布（每个取值概率 1/100）
M(ω)   = normal    当 ω ≤ 79
       = cautious  当 80 ≤ ω ≤ 89
       = pressed   当 90 ≤ ω ≤ 99
```

随机源：每个「座位 × 手号」对应一个派生随机源，其种子取该派生摘要的整数形式；派生链为「主键 → 身份标识 → 座位键 → 手号与模式标识」，摘要在核验程序中独立复写并与实现逐项相符（`7` 个手号 × 全部座位）。

说明：座位键的派生消息**包含身份标识**，因此随机源取值依赖身份；但随机源的**取值分布**（`Ω` 上的均匀分布）不依赖身份，模式取值也不读取身份、人格、节点或对局状态。这正是「取值实现可以依赖派生流、概率分布不得依赖」的落点。

### 9.3 (c) P1 / P2 的构造性说明与可复现判据

- **P1（权重一致性）**：模式只由取值 `ω` 决定，`ω` 在 `100` 个取值上均匀，分段边界把 `100` 个取值切成 `80 / 10 / 10`，因此三个模式的概率逐项为 `0.80 / 0.10 / 0.10`。
  可复现判据：全部 `100` 个取值的映射枚举结果（已执行）；分段边界常量的逐项核对（已执行）。
- **P2（无关性）**：给定任意一组配置（身份、人格、座位、节点），模式取值的分布都是「`Ω` 上的均匀分布经同一分段映射」的结果；派生过程只读取座位键与手号，不读取人格（风格）、特征、合法动作集或对局状态。
  可复现判据：(i) 独立复写的派生链在 `7` 个手号 × 全部座位上与实现逐项相符（已执行）；(ii) 取值分区枚举（已执行）；(iii) 派生消息固定为「手号 + 模式标识」，不含人格、节点或对局字段。
- **上游事实声明**：`ω` 的均匀性来自标准库随机源在固定区间上的取值方式（拒绝采样），属上游性质，本核验不复算该性质；若上游改变它，P1 / P2 的结论必须重核。
- **禁止项遵守**：未使用实测频率，未使用事后估计权重，未由候选身份读数反推任何取值。

### 9.4 (d) 单次取值的差异不违反 P2

同一手号下不同座位、同一座位下不同手号，单次取值可以不同——这是派生随机源的结果，不是边际分布的差异。P2 只约束**边际分布**。核验程序对此只作描述性记录，不作分布估计。
