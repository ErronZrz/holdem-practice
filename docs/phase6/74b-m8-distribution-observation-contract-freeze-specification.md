## 4. 能力条款（规格文本）

### 4.1 与采样同源（**修订**，关闭阻断 14）

实时采样是**两阶段**过程：先按潜变量模式 `M` 取值，再按该模式的条件分布 `q_M` 采样。主判输出要求的是该过程的**无条件（边缘化）**分布。两者**通常不逐项相同**，因此「同源」必须拆为**两项独立要求**，不得用「查询与采样逐项相同」一语概括。

- **要求 A（条件分布层级，逐模式）**：对**每一个** `m ∈ {normal, cautious, pressed}`，`mode_override` 查询在覆盖模式 `m` 时返回的条件分布 `q_m`，**必须**与运行时在 `M = m` 下动作采样所使用的条件分布**逐项一致**（同一候选集合语义、同一单位、同一金额语义、同一概率值）。
- **要求 B（边缘化层级，唯一构造）**：主判 `marginalized` 输出**必须**由**同一组**三个条件分布 `q_normal`、`q_cautious`、`q_pressed`，按权重 `0.80 : 0.10 : 0.10` 与 §5.5 的**确定性取整规则唯一构造**：

```text
q = 0.80 · q_normal + 0.10 · q_cautious + 0.10 · q_pressed
```

- **不可替代性（写死）**：主判边缘分布是两阶段采样过程的**无条件分布**；**不得**以单次具体模式的条件分布替代它，**不得**以「本手实际取到的模式」决定主判输出，也**不得**把 `mode_override` 输出当作主判输出（其误用分类见 §6.1）。
- **允许**：查询与采样为两次独立调用；**允许**实现缓存或复用中间量。
- **禁止**：要求两者是同一对象或同一次调用的产物；**禁止**另建一套「报告用分布」（例如对采样分布做平滑、截断、重归一化或四舍五入后再报告）；**禁止**缓存键包含**对手私有信息**、对局结果或身份读数。安全状态中属**公开**的信息（如其他座位的公开筹码、弃牌状态与已投入额）是合法安全输入的一部分，**可以**进入缓存键（见 §2.3）。
- **可核验表述**：
  1. 对同 (节点, 模式 `m`) 分别执行一次 `mode_override` 查询与一次「以 `M = m` 为固定模式」的采样前条件分布构造，两者的候选集合、单位向量与金额语义必须逐项相同（要求 A）；
  2. 对同一节点，用三个 `mode_override` 输出按 §5.5 复算边缘化结果，必须与 `marginalized` 输出**逐项相同**（要求 B）。

### 4.2 观测无副作用

- 查询**不得**消耗、推进或重置任何行动随机流，**不得**改变后续采样结果，**不得**改变对局状态。
- 同一次查询**可重复执行且结果一致**（相同输入 ⇒ 相同输出）。
- 观测路径**不得**读取或写入与采样共享的可变状态；如需缓存，缓存必须对采样结果无影响。

### 4.3 输入口径与信息边界

- 输入**必须**为：(a) 行动者的**安全状态**（不含对手底牌）；(b) 该状态的**合法动作集**；(c) 可选的**模式覆盖**（仅用于离线核验与测试，实时主判路径不得使用；其口径见 §7.5）。
- 查询路径**不得**扩大信息边界：不得访问对手底牌、不得访问对局结果、不得访问本身份或其他身份的历史读数。
- 安全状态的具体载体与字段形状属**实现记录**内容，不由本规格冻结；本规格冻结的是「只含行动者可见信息」这一约束。
- 输入的合法动作集与安全状态必须自相一致（例如可跟注性与目标额一致）；不自一致按 §6 的非法输入处置。

### 4.4 手模式口径：既有语义与待实现能力的区分（**修订**）

- **主判口径（冻结要求）**：主判观测输出**唯一**为按预注册外生权重**边缘化**后的联合分布：

```text
q(x) := 0.80 · q_NORMAL(x) + 0.10 · q_CAUTIOUS(x) + 0.10 · q_PRESSED(x)
```

- **既有事实（照录，不得误认为已满足本要求）**：当前混合策略的分布查询在未指定模式时返回**本手确定模式的单一分布**；显式指定模式时只返回**该指定模式**的分布。因此**边缘化查询属于待实现能力**，不是当前查询能力的既有语义。
- 模式集合冻结为 `normal` / `cautious` / `pressed` 三项；逐模式分解**只作非阻断报告**，模式数**不进入**比较数。
- 权重来源：模式自身的理论外生分布，与身份、座位、人格、节点无关；不来自候选读数、实测模式频率或实时使用频率。
- 人格比较**必须**在**完全相同的节点集与同一模式口径**下进行；**禁止**让某一座位私有的模式取值混入人格差——这正是要求返回**边缘化**结果而非单次模式取值的原因。

### 4.5 模式概率无关性的可验证定义（**修订**）

本节定义待实现时应验证的**概率空间、待验证命题、配置来源与验证工件**。现有实现的取值分区**不构成**下述命题的证明。

1. **概率空间**：`(Ω, P)`，其中 `Ω` 为模式生成机制的随机源取值空间，`M: Ω → {normal, cautious, pressed}` 为模式取值随机变量。
2. **待验证命题**：
   - **P1（权重一致性）**：`P(M = normal) = 0.80`、`P(M = cautious) = 0.10`、`P(M = pressed) = 0.10`，逐项相等。
   - **P2（无关性）**：对任意两组配置（身份、人格、座位、节点各取任意值），`M` 的**边际分布**相同，即 `P(M = m)` 不随上述任一项变化。
3. **配置来源**：权重 `0.80 / 0.10 / 0.10` 来自**外生固定配置**（本规格冻结常量）；**禁止**由身份读数、实测频率或运行时状态派生。
4. **验证工件（须由后续核验授权产出）**：
   - (a) 取值集合与概率值的**逐项对照**；
   - (b) `Ω`、`P` 与 `M` 的显式定义（含随机源与其分布）；
   - (c) P1、P2 的**构造性说明**与可复现的判据；
   - (d) 明确声明：**单次取值**在不同座位 / 手号上可以不同，这不违反 P2；P2 只约束**边际分布**。
5. **判定**：P1 或 P2 任一不成立 ⇒ 契约**验证失败** ⇒ 域 A / 域 B 记**不可判定**；**禁止**改用实测频率或事后估计权重凑合。

## 5. 金额语义与概率单位（规格文本）

### 5.1 规范对象（**新增，关闭阻断 1 / 2**）

1. 本规格冻结的对象**仅是观测输出中候选的 `(动作类型, 金额)` 对**，以及与之配套的单位与语义。
2. 本规格**不**规定引擎如何解释、存储或记录金额；引擎**历史记录额**（该次动作实际产生的支付）与观测输出中的金额**不是同一个量**，两者**不得混同**，也不得互相替代。
3. 因此，凡涉及 `FOLD` / `CHECK` / `CALL` 的「金额为 `0`」，其含义一律是**本规格对观测输出候选的规范化要求**，**不是**引擎对输入强制或既有的取值域。

### 5.2 逐动作类型的「引擎事实 / 本规格要求」对照（**替换原表**）

| 动作类型 | 引擎事实（只读核验所得） | 本规格对观测输出候选的要求 |
|---|---|---|
| `FOLD` | 执行时不读取输入金额；历史记录写 `0` | 输出的候选金额**必须**为 `0` |
| `CHECK` | 执行时不读取输入金额；历史记录写 `0` | 输出的候选金额**必须**为 `0` |
| `CALL` | 执行时不读取输入金额，实际投入由引擎按「目标额与剩余筹码的较小者」计算；历史记录写**该实际支付额**（短码跟注可小于 `legal.call_amount`） | 输出的候选金额**必须**为 `0`（跟注规模在同一节点内由合法集决定、不是自由维度） |
| `BET` | 仅在翻牌后且无待跟注时合法；按「本街新增投入」应用；输入金额需落在**闭区间** `[min_bet, max_bet]` | 输出候选金额表示本街新增投入总额；取值须落在**闭区间** `[min_bet, max_bet]` |
| `RAISE` | 按「加注后本街总额」应用；输入金额需落在**闭区间** `[min_raise_to, max_raise_to]` | 输出候选金额表示**加注后本街总额**；取值须落在**闭区间** `[min_raise_to, max_raise_to]` |

补充说明：

1. 就当前引擎路径而言，`BET` 合法时玩家本街既有投入为 `0`，故「本街新增投入」与「下注后本街总额」同值；本条是就当前路径的推导，不隐含引擎不可变。
2. **端点包含**：`BET` / `RAISE` 的区间两端均合法；**禁止**排除端点。
3. **同额合并先行**：同一动作类型下金额相同的候选，**必须**在分桶之前合并为一个候选；合并后不得再拆分。
4. **夹紧后端点金额的唯一归属**：若实现将候选金额夹紧到端点，其归属按 §5.6 的区间规则唯一确定；**禁止**同一金额落入两个桶，也**禁止**因夹紧新增候选。
5. `CALL` 候选金额为 `0` 不改变引擎语义（引擎不读该字段），也不改变实际投入。

### 5.3 两类整数：筹码单位与概率单位（**修订，关闭阻断 3 / 10**）

1. **两类量必须分开表述，不得互称、不得互换**：

| 量 | 类型与单位 | 取值约束 | 量纲 |
|---|---|---|---|
| `amount`（候选金额） | 非负**整数筹码**单位 | 落在 §5.2 的闭区间内（`FOLD` / `CHECK` / `CALL` 为 `0`） | 有量纲（筹码） |
| `units`（概率质量） | 非负**整数概率**单位 | 总和恰为 `1_000_000`（见 §5.4） | **无量纲**（定点计数） |

2. **禁止**把 `units` 称为筹码单位、把 `amount` 称为概率单位，或把两者相加、比较、混入同一聚合；概率单位不得携带筹码语义，金额不得携带概率语义。
3. **共同点**：两类整数均**禁止**浮点、分数或近似浮点表示。
4. **引擎事实（照录，不作为上述要求的依据）**：核心引擎对动作金额**仅有类型标注**，**没有**整数性的运行时校验；`BET` / `RAISE` 上只做区间比较，可参与比较的非整数值不会被运行时拒绝。
5. 因此第 1–3 条是**新增契约要求**，**不得**表述为「引擎已保证无浮点」。

### 5.4 概率单位

1. 概率质量以**定点非负整数**表示（**无量纲**，见 §5.3），单位总和**必须恰等于**冻结常量 **`1_000_000`**（沿用既有混合策略实现所用的分布单位常量，避免引入新的任意常量）。
2. **禁止**输出总和不为 `1_000_000` 的分布；**禁止**以重新归一化掩盖不合规输出（按 §6 判为语义不合规）。此处守恒的是**整个观测输出**的单位总和；金额桶的守恒对象另行规定于 §5.6。
3. 单位数为 `0` 的候选**不得**被采样到；零单位候选是否出现在输出中由实现决定，但不得影响采样结果。
4. 概率单位一经冻结，金额分区、桶归属与报数**一律**以该单位计（其守恒对象见 §5.6）。

### 5.5 边缘化算术与确定性取整（**新增，关闭阻断 5 的配套缺口**）

1. 权重以**整数比** `8 : 1 : 1`（`normal : cautious : pressed`）表示，避免浮点参与。
2. 记三模式分布在同一候选 `x` 上的单位为 `u_N(x)`、`u_C(x)`、`u_P(x)`（某模式缺该候选时按 `0` 计）；精确值为

```text
e(x) := (8·u_N(x) + 1·u_C(x) + 1·u_P(x)) / 10
```

3. 输出单位 `units(x)` **必须**为整数，并满足：
   - 对每个候选 `|units(x) − e(x)| < 1`（取整）；
   - `Σ_x units(x) = 1_000_000`。
4. **确定性校正规则**：先取 `floor(e(x))`；将剩余总额按 `e(x) − floor(e(x))` **降序**逐一加 `1`；余数相同者按候选的**规范排序**（先动作类型序 `FOLD < CHECK < CALL < BET < RAISE`，再金额升序）决定先后。禁止随机、禁止实现自定义顺序。
5. 候选集合为三模式候选集合的**并集**；某模式缺某候选不视为错误，按 `u = 0` 计入上式。
6. 若某模式**整体未覆盖**（该模式不返回任何候选），按 §6 的非法输入 / 未覆盖语义处置，**禁止**静默按全零处理。

### 5.6 金额分区：完备性、归属规则、定义链与守恒对象（**修订，关闭阻断 9 / 13 / 17**）

记 `U(c)` 为候选 `c` 的**单位数**（即 §5.5 的 `units(x)`），`type(c)` 为候选动作类型，`bucket(c)` 为 `c` 的金额所属桶。候选集合与 `U(c)` 均由 §5.1–§5.5 确定；本节只使用它们。

1. **分区集合**：金额分区 `P_B` 由**未来域 B 规格**单独预注册；**本规格不冻结 `P_B` 的具体桶边界**，但冻结其**完备性要求**与**归属规则**。
2. **无条件互斥完备（写死，替代原「含 `other` 桶时」的条件表述）**：
   - `P_B` **必须**对**每个节点**的全部合法 `BET` / `RAISE` 候选金额形成**两两互斥、完备**的分区；
   - **数值桶**按冻结顺序为**左闭右开**，**最后一个数值桶包含右端**；
   - 若数值桶**不能**覆盖该节点全部合法主动金额域，则**必须**设一个固定 `other` 桶，其定义为「不落入任一数值桶的**合法主动金额**」的**补集**（即 `other` 不是宽松兜底，而是补集）；
   - **冻结前**必须验证分区规则对合法主动金额域的**静态完备性**（覆盖与互斥在规则层面成立）；**运行时**再验证第 5 条的守恒式。**两者不可相互替代**：运行时守恒不能用来补证静态完备，静态完备也不能免除运行时检查。
3. **归属与合并次序**：同额合并（§5.2 第 3 条）**先于**桶归属执行；落入某桶的候选其**全部单位**计入该桶。
4. **定义链（写死）**：

```text
U_act := Σ_{c : type(c) ∈ {BET, RAISE}} U(c)
q_act := U_act / 1,000,000
U_x   := Σ_{c : bucket(c) = x} U(c)
q_x   := U_x / 1,000,000
```

   并且：

```text
U_act = 0  ⟺  q_act = 0
r_x := U_x / U_act = q_x / q_act    （仅当 U_act > 0 时有定义）
```

   `q_act` 与 `q_x` 只是同一批整数单位按 `1_000_000` 换算得到的比值，**不引入第二套数据来源**；两式在任何时候都必须一致。
5. **守恒对象与适用条件（写死）**：金额桶只覆盖 `BET` / `RAISE` 的**主动质量**，**不**覆盖 `FOLD` / `CHECK` / `CALL`。
   - **若 `U_act > 0`**：`Σ_x U_x` **必须恰为 `U_act`**；**禁止**要求其等于整个输出的 `1_000_000`。
   - **若 `U_act = 0`**：金额条件熵**无值**；**不执行**金额桶守恒检查，**不执行**任何归一化检查，`r_x` **无定义**（按 §6.2 的结构性零值处置）。
6. **仍不冻结的部分**：未来域 B 规格仍自行冻结条件额度分布 `r_x` 的**定点输出格式**与其取整 / 归一化细节；本规格只补齐第 4 条已引用量之间的语义关系与第 2 条的完备性要求。
7. 不满足第 2、5 条即按 §6 判为**语义不合规**；**禁止**用重新归一化掩盖不符。

## 6. 失败与缺失处置（规格文本）

### 6.1 事件分类（冻结）

| 类别 | 定义 |
|---|---|
| **声明阶段失败** | **纯声明错误**，只发生在**注册表读取 / 声明校验**阶段：①声明缺失；②`supported = true` 时任何字段缺失或固定值不符（含 `capability_id` ≠ `"distribution-observation@1"`、`probability_units` ≠ `1_000_000`、`modes` 不符、`mode_weights` 不符、`amount_semantics` 不符） |
| **能力不可用** | `supported = false`；由调用方依据声明得出的**状态**，不是查询方法的返回值 |
| **`sys_decl`（声明与行为不一致）** | **封闭集合**：声明**已通过校验**且 `supported = true` **之后**，**已通过的声明字段**与**后续可观察行为直接矛盾**的事件，且**仅限**下表 `D1`–`D4`。**不得**以「违反本规格冻结的行为要求」作为其覆盖条件 |
| 非法输入 | 安全状态与合法动作集不自一致，或模式覆盖未覆盖任何候选、或取值不在 `modes` 内 |
| `tech` **技术错误** | 查询在处理该节点时抛出异常、超时，或返回不可解析的结果；结果**不可**进入单位校验 |
| `sem` **语义不合规（兜底定义）** | 凡违反本规格 §§4.1–5.6、§7.2–§7.7 中「必须 / 禁止 / 唯一 / 不得」要求的、可观察且可核验的事件，除已归入**上述五类**者外，**一律**归为 `sem` |
| 结构性零值 | 仅指 `U_act = 0`（等价 `q_act = 0`）等**结构性**无值情形，**不**包括任何输出不合规 |

**`sys_decl` 的封闭集合（穷尽列举，`D1`–`D4`）**：

| 编号 | 事件 | 与哪一声明字段直接矛盾 |
|---|---|---|
| `D1` | 声明的 `supported = true`，但能力在**与节点查询、节点与清单完全无关**的证据下不可用：`D1(a)` 实现记录登记的三项能力入口中存在**不可被引用**者（**静态**判定，不发起任何调用）；`D1(b)` **无状态能力健康读取**（`P_cap.P2`，§7.2）返回 **`unavailable`**。二者均**不得**由节点查询的失败推导 | `supported` |
| `D2` | 实际参与边缘化的**权重**与已通过的 `mode_weights` 不一致（即 §4.5 的 P1 不成立） | `mode_weights` |
| `D3` | 输出元数据 `probability_units` 与已通过的 `probability_units` 不一致 | `probability_units` |
| `D4` | 输出元数据 `mode_weights` 与已通过的 `mode_weights` 不一致 | `mode_weights` |

`D1` 的判定边界（写死，关闭与 `tech` 的竞争路径）：

1. `D1(a)` **只**由**静态证据**判定：依实现记录登记的三项能力入口（声明读取入口、能力健康读取入口、查询调用入口），在**不发起任何调用**的前提下判定其是否存在 / 可被引用。若入口存在、仅调用时出错，**不**构成 `D1(a)`。
2. `D1(b)` **只**由**无状态能力健康读取**（`P_cap.P2`，定义见 §7.2）返回 **`unavailable`** 判定。该读取**无任何输入**（不接受 `GameState`、`LegalActions`、节点标识、种子或任何状态化输入），不涉及节点、清单、seed 或 `code_identity`；在任何节点查询之前一次性执行，结果**一经产生即固定**，后续不再重判。
3. **单节点异常、超时、不可解析，以及任何仅由这些结果推导出的「无可用输出」，只能归 `tech`**（并仅依 §6.3 门槛处置）；**不得**触发 `D1`。
4. **禁止**由下列任一项推导 `D1`：`n_tech`、`n_tech_consecutive`、`n_attempted`、作废率、「当前已尝试节点集合」，或「尚未取得成功结果」这一状态。
5. 判为 `D1` 后，该实例的全部受影响分域直接记不可判定；此前已记录的节点级 `tech` **保留为历史记录**，但**不再**据此推进块作废。
6. `D3` / `D4` 只覆盖**输出元数据字段与声明不一致**这一件事；与之不同的事件分别归类，例如「候选 `units` 之和 ≠ `probability_units`」归 `sem`、「输出缺字段」归 `sem`。
7. **除 `D1`–`D4` 之外的一切事件**，一律**不**归 `sys_decl`；特别地，条件分布不同源、边缘化取整不符、随机流被推进、越界信息访问、输出结构违规、`overridden_mode` 违规、主判误用 `mode_override` 等**均归 `sem`**。

**类别判定的唯一性与优先级（写死）**：每个事件**只能**归入**一个**类别；按下表**先命中者优先**，**禁止**重复归类、**禁止**同一事件同时计入两条路径。`sys_decl` 与 `sem` 的集合由上面的封闭集合与兜底定义划分，**两者互斥**；优先级仅为判定次序，不改变该互斥性。

```text
① 声明阶段失败    ← 注册表读取 / 声明校验阶段；尚无节点，不进入任何分域计数
② 能力不可用      ← 注册阶段；尚无节点，不进入任何分域计数
③ sys_decl        ← 仅限封闭集合 D1–D4（声明字段与可观察行为直接矛盾）；
                   D1 仅由静态入口检查（D1a）或能力级探测专用结果（D1b）判定，
                   不得由任何节点查询失败推导
④ 非法输入        ← 查询阶段（输入侧）
⑤ tech            ← 查询阶段（技术侧）
⑥ sem             ← 兜底：其余一切违反硬约束的可观察事件
```

**关键事件的显式映射（冻结）**：

| 事件 | 唯一分类（阶段） | 处置 |
|---|---|---|
| 声明缺失、声明字段缺失或固定值不符（含 `capability_id` 不符）（违反 §7.2） | **声明阶段失败**（注册表读取 / 声明校验） | 注册阶段停止；域 A / 域 B **不可判定**；**不进入** `n_attempted` / `n_tech` / `sys_decl`，也不产生节点级记录 |
| `supported = false` | **能力不可用**（注册阶段） | 记不可判定；**不得**实例化或调用查询入口；**不进入**任何分域计数 |
| 静态检查发现三项能力入口中存在不可被引用者（`D1(a)`；**不发起任何调用**） | `sys_decl` | 单次 `sys_decl`；受影响分域直接记不可判定 |
| 无状态能力健康读取返回 **`unavailable`**（`D1(b)`，§7.2；**在任何节点查询之前一次性判定**） | `sys_decl` | 单次 `sys_decl`；受影响分域直接记不可判定 |

| 边缘化算术或确定性取整不符（违反 §4.1 要求 B / §5.5） | `sem` | 单次 `sys_sem` |
| 查询推进随机流、改变后续采样或对局状态（违反 §4.2） | `sem` | 单次 `sys_sem` |
| 访问对手私有信息或对局结果信息（违反 §4.3） | `sem` | 单次 `sys_sem` |
| 输出缺字段、排序不符、候选重复（违反 §7.4） | `sem` | 单次 `sys_sem` |
| 候选 `units` 之和 ≠ 输出的 `probability_units`（违反 §5.4 / §7.4） | `sem` | 单次 `sys_sem` |
| `overridden_mode` 缺失 / 取值越界 / 在 `marginalized` 下出现（违反 §7.4） | `sem` | 单次 `sys_sem` |
| 调用方在主判使用 `mode_override`（违反 §4.1 / §7.5） | `sem` | 单次 `sys_sem` |
| 节点查询中抛出异常、超时、不可解析 | `tech` | 仅依 §6.3 门槛处置；**不得**升格为 `D1` |

- 该映射表**不穷尽** `sem`：凡符合兜底定义且未被①②③④⑤命中的其它事件同样归为 `sem`，并按 §6.2 处置。
- **凡不在 `D1`–`D4` 之列的行为违规，一律归 `sem`**；`sys_decl` 与 `sem` 不得对同一事件同时成立。
- **`D1` 与 `tech` 互不推导**：`tech` 事件（无论数量、连续性、占比或是否「尚未成功」）**不得**作为 `D1` 的证据；`D1` 一经成立也不再需要、不再产生任何节点级 `tech` 判定。
- `sem` 与 `sys_decl` 的判定**均不设比例门槛**（见 §6.3）。

### 6.3 系统性失败门槛（冻结，**修订，关闭阻断 11**）

计数口径（冻结，按**分域**分别统计）：

- `n_attempted`：该分域**已发起查询的节点数**，包含成功、`tech` 与 `sem` 三种结局；
- `n_tech`：该分域内以 `tech` 结束的节点数；
- `n_tech_consecutive`：该分域内**当前连续**以 `tech` 结束的节点数（任一非 `tech` 结局即归零）；
- `sem` 与 `sys_decl` 事件另行单次判定（见下）；
- **声明阶段失败与能力不可用发生在注册阶段、尚无节点**，因此**不进入** `n_attempted` / `n_tech` / `n_tech_consecutive`，也**不进入** `sys_decl` 计数（它们在阶段上先于本节的任何分域统计）。
- **能力级探测 `P_cap` 与静态入口检查发生在任何节点查询之前**，同样**不进入**上述任何计数；它们只决定 `D1` 是否成立。
- **本节四项计数与 `sys_tech` 门槛只处理真正的 `tech` 路径**：`n_attempted` / `n_tech` / `n_tech_consecutive` / 5% 门槛均**不得**用于判定或推导 `D1`，也**不得**因「出现过若干次技术错误」而改判为 `sys_decl`。反之，`n_tech` 只统计以 `tech` 结束的节点查询。

`sys` 成立的条件（满足任一即成立）：

```text
sys_sem   ⇔ 出现任一 sem 事件
sys_decl  ⇔ 出现 §6.1 封闭集合 D1–D4 中的任一事件
            （声明字段与可观察行为直接矛盾；不含声明阶段失败，
              不含能力不可用，也不含任何归入 sem 的行为违规）

sys_tech  ⇔ ( n_tech_consecutive ≥ 3 )
            ∨ ( n_attempted ≥ 20 ∧ n_tech / n_attempted ≥ 0.05 )
```

1. `sys_sem` 与 `sys_decl` **单次即成立**，不设比例门槛。
2. `sys_tech` **必须同时**满足 `n_attempted ≥ 20` 与比例 `≥ 0.05` 两项，或满足连续 `≥ 3` 项；**仅**满足比例而 `n_attempted < 20` **不**成立。因此早期（`n_attempted < 20`）的技术错误不会被比例门槛判为系统性，仍按 §6.2 走**允许块作废**路径；「连续 3 个节点」条目在早期仍然有效。
3. 比例取值保留 **5%**（`1/20`），不改为其他比例。

上述门槛为**契约层门槛**，不等于域级统计阈值。域级的**作废率上限**与**有效块数下限**仍属域规格内容，须另行冻结；在其冻结前不得运行验证。

### 6.4 允许块作废 / 必须直接契约验证失败的事件清单（冻结）

清单按 §6.1 的**唯一分类**给出，每个事件只出现在一处：

- **注册阶段终止**（不发生查询、不进入任何分域计数）：**声明阶段失败**（声明缺失、字段缺失 / 固定值不符，含 `capability_id` 不符）；**能力不可用**（`supported = false`）。两者均直接使域 A / 域 B 记**不可判定**。
- **允许块作废**（双侧同时、计入作废率）：仅 `tech`，且**未**触发 §6.3 的任一门槛。
- **必须直接记契约验证失败（不可判定）**：`sem`（含模式覆盖输出被用于主判等，见 §6.1 映射表）、`sys_decl`（**仅限 `D1`–`D4`**）、`tech` 触发 §6.3 门槛。
- **`D1` 与 `tech` 路径互斥**：`D1` 只由**静态入口检查**（`D1(a)`）或**能力级探测专用结果**（`D1(b)`）判定，且两者都在**任何节点查询之前**完成；因此节点查询阶段的 `tech` **不能**被累积成 `D1`，`D1` 成立后也**不再**产生新的节点级 `tech` 判定。
- 一切处置**不得**修改阈值、比较数、分区或样本量；**不得**在读数后放宽判定；**不得**把一个事件同时计入上述两处。

### 6.5 结构性零值（`U_act = 0`，等价 `q_act = 0`）的豁免范围（冻结）

- `U_act = 0`（等价 `q_act = 0`）**仅**表示「金额条件熵在该节点无值、`r_x` 无定义」，属**必报非阻断量**的无值情形，须单列计数报告。
- **禁止**把它推广为其它输出不合规的豁免理由；**禁止**据此作废整块、跳过其它主判量或放宽 §5 的硬约束。

## 7. 接口形态（规格文本）

### 7.1 定性

该契约为**接口层面的新增契约**（由 `73b` §5.6 第 `7` 条提出要求、由 `74a` §6 裁定确认）。契约以**独立的分布观测能力协议**形式提供，与统一 `Strategy` 协议**并列**；统一 `Strategy` 协议**不新增方法**，仍仅含 `choose_action`。

### 7.2 能力声明：身份绑定、最小字段、三态义务与取值（**修订，关闭阻断 7 / 12 / 16**）

**身份绑定（写死）**：

1. 声明读取的**键**必须是 `resolve_identifier()` 返回的**规范策略标识**（`backend/app/strategy/registry.py`）；每一规范标识**只对应一份**声明，不得按别名、实例或座位分别声明。
2. `capability_id` 的**固定值**为 `"distribution-observation@1"`。
3. `supported = true` 时，声明中的 `capability_id` **必须等于**该固定值；不等即属**声明阶段失败**（§7.6）。

能力声明**必须**可从注册表元数据读取，**无需实例化被测策略**。规范字段如下：

| 规范字段 | 取值约束 | 含义 |
|---|---|---|
| `capability_id` | **必须恰为** `"distribution-observation@1"` | 分布观测能力标识 |
| `supported` | `true` / `false` | **唯一权威**的能力判定依据 |
| `probability_units` | 正整数，**必须恰为** `1_000_000` | 输出定点单位总和 |
| `modes` | 有序列表，**必须恰为** `["normal", "cautious", "pressed"]` | 参与边缘化的模式集合 |
| `mode_weights` | 整数比，**必须恰为** `8 : 1 : 1`，顺序与 `modes` 对应 | 边缘化权重 |
| `amount_semantics` | 标记，须表明 `BET` 为闭区间新增总额、`RAISE` 为闭区间加注后总额、`FOLD` / `CHECK` / `CALL` 输出金额为 `0` | 金额语义声明 |

**已删除字段**：原 `partition_version` **不再属于能力声明**。理由：金额分区 `P_B` 属**未来域 B 的验证配置**，不是被测策略的分布观测能力；能力输出必须保持**原始** `(动作类型, amount, units)`，**不得**预先绑定 `P_B` 或未冻结的分区版本。`P_B` 的版本及其与验证调用的对应关系由未来域 B 规格与验证清单自行冻结。

**三态义务（写死，三种情形的处理路径互不替代）**：

1. **声明缺失**（注册表中**不存在**该实例的能力声明条目）：调用方在**注册表读取阶段**直接判为**声明阶段失败**（配置 / 契约验证失败）；**禁止**实例化该策略、**禁止**调用查询入口。此情形下**不得**假定能取得任何返回值（没有可承载返回值的实例协议）。
2. **`supported = false`**：声明**只需**含 `capability_id` 与 `supported = false` 两个字段；其余能力参数**不得**被当作可用能力配置（即使存在也不得读取、比对或据以调用）。调用方**直接记能力不可用**，且**不得**实例化策略或调用查询入口。
3. **`supported = true`**：声明**必须完整具备**上表**全部字段**，且每个字段**必须满足**其固定取值；任何字段缺失或取值不符（含 `capability_id` ≠ `"distribution-observation@1"`、`probability_units ≠ 1_000_000`、`modes` 不符、权重不符、`amount_semantics` 不符）⇒ **唯一**归为**声明阶段失败**（§6.1 类别①），在注册表读取 / 声明校验阶段停止；**不得**改记为 `sys_decl`、**不得**计入任何分域或节点计数。

其余规定：

- **「能力不可用」是调用方依据声明得出的状态**，**不是**要求一个「声明缺失」的策略返回的查询结果；**禁止**把该状态实现为调用查询方法后再解析错误。
- **本声明字段与后续可观察行为直接矛盾的全部情形**即 §6.1 的封闭集合 `D1`–`D4`；除此之外的任何行为违规**不得**记为本声明的「声明与行为不一致」（归类见 §6.1 / §6.2）。
- 规范字段名用于规格内引用；实现标识符可不同，但**必须**在实现记录中登记一一映射，且语义不得改变。

**能力级探测 `P_cap`（冻结，`D1` 的唯一依据）**：

1. 探测集合**封闭**，**仅含**下列两项，**不得**扩充或缩减：

| 编号 | 探测 | 完成方式 | 判定 |
|---|---|---|---|
| `P1` | **静态**入口检查 | 依实现记录登记的三项能力入口（**声明读取入口**、**能力健康读取入口**、**查询调用入口**），**不发起任何调用**即可判定其是否存在 / 可被引用 | 任一不可引用 ⇒ `D1(a)` 成立 |
| `P2` | **无状态能力健康读取** | 调用**能力健康读取入口**一次；该入口**不接受任何输入**，**不得**读取对局状态 | 见第 2 条两类结果 |

2. `P2` 是**无状态**能力健康读取：**不接受** `GameState`、**不接受** `LegalActions`、**不接受**节点标识、种子或任何状态化输入，**不读取**对局状态，**不影响**任何随机流与对局状态。其**固定返回语义**为**二元封闭枚举**：
   - ① `available` ⇒ **能力可用**，`D1` 不成立；
   - ② `unavailable` ⇒ **能力整体不可用**，`D1(b)` 成立。
3. `P2` 的返回**只允许**上述二值，**不设第三类**；**禁止**为状态化查询输入设置任何探测分支，也**禁止**以「非法输入」为由返回任何表示「能力可用」的结果。
4. **不属于 `P2` 固定返回语义的任何情况**（`P2` 入口抛异常、超时、返回不可解析或不在此枚举内的取值）⇒ **探测证据不足**：`D1(b)` **不成立**、**不产生** `sys_decl`，该实例**继续**进入正常节点查询流程，由 `tech` / `sem` 路径处置；**不得**把「非法输入」或「入口不可调用」之外的任何失败解释为「能力可用」。
5. **固定完成时点**：`P1`、`P2` **必须**在注册表读取 / 声明校验通过之后、**首次节点查询之前**完成；结果**一经产生即固定**，**禁止**在后续任何时刻重判、追加、替换或按节点结果修正。
6. **`P2` 的专用返回不得与 `tech` 混用**：第 2 条的 ② 是一个**独立的结果类别**，**不得**实现为异常、超时或不可解析，也**不得**由这些事件推断得到。
7. **不引入任何探测工件**：`P_cap` **不**需要、**不**使用独立的节点、清单、seed、`code_identity` 或状态化探测对象；本规格因此**不**新增任何需要另行冻结的探测输入。`D1` 的判定**不依赖**域 A / 域 B 清单，也**不依赖**任何节点。
8. **禁止**以节点查询结果、`n_tech`、`n_tech_consecutive`、`n_attempted`、作废率，或「尚未取得成功结果」这一状态作为 `D1` 的证据；`P_cap` **不得**在节点查询开始后重复执行。

### 7.3 查询输入（冻结）

输入为三元组：安全状态、合法动作集、可选的模式覆盖。模式覆盖的取值只允许 §7.2 的 `modes` 成员或「未指定」；其它取值按 §6.2「非法输入」处置。

### 7.4 查询输出：最小结构（**新增，关闭阻断 7**）

输出**必须**至少含下列语义字段（规范名，映射规则同 §7.2）：

| 字段 | 约束 |
|---|---|
| `probability_units` | 必须等于该实例能力声明中的 `probability_units` |
| `mode_weights` | 必须等于该实例能力声明中的 `mode_weights` |
| `aggregation` | 取值 `marginalized`（主判口径）或 `mode_override`（离线口径）；两者语义见 §7.5 |
| `overridden_mode` | **仅当** `aggregation = mode_override` 时必填，且值必须属于 `modes`；`aggregation = marginalized` 时**不得**携带任何单一覆盖模式 |
| `candidates[]` | 每项含：动作类型、`amount`（非负整数**筹码**单位）、`units`（非负整数**概率**单位，无量纲）；**规范排序**（先动作类型序，再金额升序） |

`overridden_mode` 的约束（写死）：

1. 该字段是边缘化复算的**输入证据**：调用方与核验须能据此取回对应的 `q_m` 并复算 §4.1 要求 B；
2. `mode_override` 输出缺失该字段、或取值不在 `modes` 内 ⇒ `sem`（§6.1）；
3. `marginalized` 输出携带该字段 ⇒ `sem`（§6.1）；
4. 该字段**不得**用于主判聚合，也**不得**进入任何区间或功效式（见 §7.5）。

对 `candidates[]` 的硬约束：

1. `units` 为非负整数；`Σ units = probability_units`；
2. 动作类型与金额**不得**超出合法动作集，金额**不得**超出 §5.2 的闭区间；
3. 同一 `(动作类型, 金额)` 只允许出现一次；
4. 单位数为 `0` 的候选可省略；
5. `aggregation = marginalized` 时，候选集合为三模式候选集合的并集，单位按 §5.5 计算；
6. 输出**不得**把逐模式分解作为主字段；分解若提供，必须是**独立**的非阻断字段。

### 7.5 模式覆盖与唯一边缘化输出的共存（**新增，关闭阻断 7**）

1. **主判查询**只允许「未指定模式覆盖」，返回 `aggregation = marginalized` 的边缘化分布。
2. **离线核验 / 测试**允许指定模式覆盖；此时返回 `aggregation = mode_override` 的**单一模式**分布，并在输出的 `overridden_mode` 字段中携带**被覆盖的模式标识**（§7.4）。
3. 两种口径共用同一查询入口，但**输出必须自带口径标记**；调用方与清单**必须**拒绝把 `mode_override` 输出用于主判——该误用按 §6.1 归为 **`sem`**（单次 `sys_sem`），**不得**降格为块作废。
4. **禁止**在主判路径上指定模式覆盖；**禁止**把 `mode_override` 输出与 `marginalized` 输出混入同一区间、同一功效式或同一聚合。

### 7.6 错误语义（**修订，关闭阻断 7 / 12**）

| 情形 | 唯一分类 | 语义 | 发生阶段 |
|---|---|---|---|
| **声明缺失**（注册表内无该条目） | **声明阶段失败** | 配置 / 契约验证失败；**禁止**实例化策略、**禁止**调用查询入口；**不得**假定能取得任何返回值 | 注册表读取阶段 |
| 声明字段缺失 / 固定值不符（`supported = true` 但取值不合规，**含 `capability_id` ≠ `"distribution-observation@1"`**） | **声明阶段失败** | 契约不受信：该实例的观测输出一律不得使用；**不进入**任何分域计数 | 注册表读取阶段（声明校验） |
| `supported = false` | **能力不可用** | 调用方记为能力不可用 → 域 A / 域 B **不可判定**；**不得**实例化策略或调用查询入口 | 注册表读取阶段 |
| 静态入口检查发现三项能力入口中存在不可被引用者（`D1(a)`） | **`sys_decl`** | 记**不可判定**；单次即成立；受影响分域直接记不可判定 | **查询之前**（声明校验后、无任何调用） |
| 无状态能力健康读取返回 `unavailable`（`D1(b)`） | **`sys_decl`** | 记**不可判定**；单次即成立；受影响分域直接记不可判定 | **查询之前**（首次节点查询之前，一次性判定） |
| 能力健康读取出现固定返回语义之外的情况（异常 / 超时 / 不可解析 / 枚举外取值） | **不属于 `D1`** | 探测证据不足：不产生 `sys_decl`，继续进入节点查询流程（不得解释为「能力可用」） | **查询之前**（无处置） |
| 输出元数据与已通过的声明字段直接矛盾：`probability_units`（`D3`）或 `mode_weights`（`D4`）与声明不一致 | **`sys_decl`** | 记**不可判定**；单次即成立 | 查询阶段 |
| 非法输入（安全状态与合法动作集不自一致） | 非法输入 | 查询**明确失败**，拒绝服务该次查询；**不得**返回近似分布，也**不得**按零单位填充 | 查询阶段 |
| 模式覆盖未覆盖任何候选、或取值不在 `modes` 内 | 非法输入 | 查询**明确失败**；**禁止**按零单位填充 | 查询阶段 |
| 内部技术异常 | `tech` | 按 §6.2 的 `tech` 处置 | 查询阶段 |

- 所有失败**必须**可区分：调用方**必须**能分别识别「声明阶段失败」「能力不可用」「`sys_decl`」「非法输入」「技术错误」「语义不合规」六类，**禁止**合并为单一错误、**禁止**重复归类。
- **声明阶段失败只发生在注册表读取 / 声明校验阶段**，此时尚无查询行为，因此**不得**称其为「声明与行为不一致」，也**不得**计入 `sys_decl`。
- **「能力不可用」是按声明得出的调用方状态**（第三行），不是查询方法的返回值；**禁止**把它实现为「调用查询后解析错误码」。
- **`D1` 与节点技术错误严格分离**：`D1(a)` / `D1(b)` 均在**任何节点查询之前**判定；节点查询中的异常 / 超时 / 不可解析**只能**归 `tech`，**不得**上抛为 `D1`，也**不得**由 `tech` 计数或作废率反推 `D1`。
- 具体异常类型与错误码属**实现记录**内容，但**必须**满足上述可区分性、唯一性与阶段划分。

### 7.7 调用侧：禁止隐式方法探测（**新增，关闭阻断 7**）

1. 调用方**只能**通过 §7.2 的能力声明判定可用性，**禁止**使用 `hasattr` / `getattr`、属性存在性检查、`try/except AttributeError` 等隐式方式探测能力。
2. 能力声明的读取入口**必须**与策略实例化解耦（即无需实例化被测策略即可读取声明）。
3. 实现记录**必须**登记**三项**入口：**声明读取入口**、**能力健康读取入口**（§7.2 `P2`，无状态、无输入）与**查询调用入口**。
4. 声明为支持但查询不可用 ⇒ **唯一**归为 `sys_decl` 的 `D1`（§6.1 封闭集合 / §6.2），其判定**只**来自 §7.2 的**静态入口检查**（`D1(a)`）或**能力级探测专用结果**（`D1(b)`）；**不得**与声明阶段失败混淆，**不得**由节点 `tech` 事件推导，也**不得**因「违反冻结行为要求」而扩张 `sys_decl` 的覆盖范围。
