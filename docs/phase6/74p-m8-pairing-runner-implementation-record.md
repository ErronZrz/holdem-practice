## 3. 实现结构（逐模块口径）

`backend/app/verification/` 为纯 Python 包，只读依赖 `poker/` 的牌类型、`strategy/` 的座位风格顺序与基线实现入口的元数据（只读读取 `HeuristicStrategy.__init__` 的默认值及受限代码对象元数据，不构造实例）、`analysis/` 的参考版本快照；不依赖 `api/`、`llm/`、`storage/`，不读写数据库与文件，单进程无并行。**不导入、不调用受控注册表模块**：只在载荷中记录其构造位置的字符串。

| 模块 | 内容 |
|---|---|
| `errors.py` | 十类可区分的失败类别：规格缺项、协议结构、审计材料、材料绑定、冻结绑定、发牌材料、注入前校验（携带项名）、身份映射（含构造口径与执行身份记录不一致）、主键材料 |
| `digests.py` | 规范编码（紧凑 JSON、键排序、ASCII 转义）与内容摘要；未实现的摘要算法显式失败 |

| `protocol.py` | 四种用途角色的结构、固定域与收缩域规则、用途规格（含抽取次序字段、座位号字段与索引比较口径）、协议规格、无偏拒绝采样的判定函数、需要的位宽、逐读取记录、汇总承诺、逐读取审计的机械复核（含索引读取组的完整不变量与用途内索引顺序）、清单与材料绑定的机械复核 |
| `deal.py` | 牌规范序规格（须为完整一副牌的排列）、不放回抽取的确定函数、发牌到各座位底牌与公共牌的固定分配 |

| `config.py` | 手计划与运行前规格：人数、起始筹码、盲注、显式引擎种子、两侧身份标识、发牌映射、随机化协议、手序计划；全部必填，不设默认值，基线标识硬限定为单一基线身份 |

关键实现口径（**均为当前实现口径，未锁定、未冻结**）：

1. 两臂共用同一份显式注入的发牌材料；注入前逐项校验，任一不满足即终止本次运行。
2. 构造计划是已校验构造口径的确定函数：基线一侧的「是否依赖公开摘要」与「座位集合口径」两项直接取自经硬限制的口径（恒为假与空），不由计划自行改写语义。
3. 每手发牌材料的条数与抽取次序由协议声明校验：条数等于 `2N + 5`，抽取次序恰为连续整数。
4. 不放回抽取按「第 k 次把第 k 张与第 k + 取值 张互换后输出第 k 张」实现，第 k 次取值须严格小于剩余张数。
5. 发牌分配：按座位号升序每座连续两张为底牌，其后五张依次为翻牌三张、转牌与河牌，顺序与引擎注入路径要求一致。
6. 主键材料以 32 字节大端整数表示：整数材料先按范围校验，再还原为恰好 32 字节。
7. 两侧构造口径由调用方以不可变对象显式给出：规格里的身份标识必须与之逐字相同；进程内不存在可被隐式选中的登记表或默认值。
8. 基线执行口径由本包**只读读取策略代码**得到：入口位置、参数布局、位置默认值（`seed=none`、`samples=500`、`bluff_freq=0.1`）与受限代码对象载荷；调用方不声明这些取值。
9. 输出结构只含逐手被测座位在两侧的净筹码与定位字段（块内手序、庄位、被测座位）以及运行元数据，不含策略内部量；该结构只描述字段，产出它的执行路径尚未实现。

## 5. 注入前硬失败校验（七项）

按固定顺序执行，任一不满足即抛出携带项名的失败并终止本次运行；**不**回退到随机开手，**不**修补，**不**重取材料：

| 序号 | 项名 | 内容 |
|---:|---|---|
| 1 | `hole_card_seats_complete` | 底牌映射的座位集合恰为 `{0, …, N−1}` |
| 2 | `hole_cards_per_seat` | 每个座位恰好两张底牌 |
| 3 | `board_size` | 公共牌恰好五张 |
| 4 | `card_total_and_uniqueness` | 总牌数恰为 `2N + 5`，全局无重复 |

## 6. 冻结产物与输入绑定

**冻结清单（十项，全部由内容重算）**：

| 项 | 内容 |
|---|---|
| `spec-digest` | 域规格内容的摘要 |
| `schedule-digest` | 手序计划内容的摘要 |
| `protocol-digest` | 随机化协议内容的摘要 |
| `supplied-materials-digest` | 送交运行器的材料束内容的摘要 |
| `material-manifest-digest` | **材料清单内容本身**的摘要 |
| `audit-transcript-digest` | 原始字节转录的摘要 |
| `audit-read-record-digest` | 逐读取记录的摘要 |
| `audit-commitment-digest` | 汇总承诺内容的摘要 |
| `construction-caliber-digest` | **构造口径、基线执行口径与其构造计划**的摘要 |
| `execution-identity-digest` | 执行身份覆盖清单内容的摘要 |

`construction-caliber-digest` 的载荷包含：两侧规范标识与构造接口、是否依赖公开摘要及座位范围、基线三项硬限制的约束声明、**基线执行口径**（受控注册表构造位置、入口位置、参数布局、位置默认值与受限代码对象载荷摘要）、规格侧的定位字段，以及逐手逐臂逐座位的确定构造计划。

校验顺序为：先复核审计材料本身，再逐项确认材料与审计中被接受的取值配对，再走清单三步链，再校验材料与规格的结构一致，再走身份口径主链，最后用本次输入重算十项摘要并与清单比对。任一项不符即失败，不重取材料、不修补、不改用随机开手。

**读取级规则（拒绝与索引）**：同一用途内按索引升序给出；同一索引的多次读取必须同键相邻；每个「用途 ＋ 索引」读取组必须满足完整不变量：**零或多条被拒绝读取之后，必须出现恰一条同键的接受读取**，索引切换或审计结束时仍未收尾的组不成立，已接受后不得再读；收缩域的抽取步数由该次读取的抽取次序字段值决定，发牌用途在各分组内的已接受抽取次序须从零起连续。

**三步链（清单 ↔ 审计 ↔ 材料）**：材料清单携带逐用途逐索引的取值并按遍历顺序、索引升序规范给出；清单条目必须与审计中被接受的取值逐项一致，也必须与送交材料逐项一致；清单本身的摘要由内容重算，并须与承诺里记录的清单摘要相同。

**身份口径主链**：同一入口内强制核对规格标识与显式构造口径逐字一致、强制基线三项硬限制、按各身份的构造接口校验逐条材料格式，并为每个臂、每一手构造座位计划；计划中的基线座位字段直接取自已校验口径。因此「口径声明」与「计划语义」不可能互相矛盾。

**基线执行口径（K-4 `(2-i)` 的追溯字段）**：本包从 `app.strategy.heuristic` 的 `HeuristicStrategy.__init__` **只读读取**：入口的模块与限定名、参数布局、位置默认值（`seed=none`、`samples=500`、`bluff_freq=0.1`）以及经明确白名单允许的代码对象载荷摘要（含 `co_code`、`co_consts`、`co_names`、参数布局与默认值等）。约定必须存在的默认值参数缺失、或入口位置与预期不符时**硬失败**。受控注册表一侧**只记录位置** `app.strategy.registry.create_strategy`，不导入、不调用、不计算其代码摘要。该口径同时进入 `instantiation-caliber` 条目集与 `construction-caliber-digest`，并由执行身份一致性校验逐项比对。

**本轮为满足严格调用规则所作的语句拆分（语义等价，全部登记）**：`errors.py` 1 处（父类初始化改为先取 `super()` 代理）、`protocol.py` 6 处、`digests.py` 2 处、`instantiation.py` 1 处、`execution_identity.py` 2 处，共 **12 处**。全部只拆出中间变量：公开函数签名、摘要算法与输出、错误类别、返回值、异常类型与业务语义**均未改变**；`errors.py` 保留合作式继承语义。
