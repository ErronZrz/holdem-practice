## 4. `heuristic@1` 的现有构造入口（只读）与 K2-P-i 兼容性

本节说明默认策略的构造事实，供唯一可进入候选 `K1-C-heuristic-1` 使用。**不**把该标识选为本次 K-1 裁定结果。

### 4.1 两层接口

| 层 | 只读事实 |
|---|---|
| **受控注册表** | `StrategySpec.factory` 的类型是接受 `int \| None` 并返回策略。`create_strategy(value, seed=None)` 把 `seed` 原样交给该工厂。`heuristic@1` 的工厂只把 `seed` 传给类构造器 |
| **类构造器** | `HeuristicStrategy.__init__(self, seed=None, samples=_SAMPLES, bluff_freq=_BLUFF_FREQ)`。除 `seed` 外还有 `samples` 与 `bluff_freq`。**不得**声称该类只接受一个整数参数 |
| **与 L-2 的对应** | L-2 v1 §5.2 的构造接口 `registry-seed`、不依赖公开摘要，与上述注册表入口一致。基线入口参数布局在 L-4 候选条款中写为 `["self","seed","samples","bluff_freq"]` |
| **规范标识** | 注册标识为 `heuristic@1`；别名 `heuristic` **不是**规范标识。描述文本含「教学参考基线」，该描述**不是**强度或质量裁定 |
| **默认数值的位置** | 类内 `_SAMPLES = 500`、`_BLUFF_FREQ = 0.10`。经注册表构造时这两个参数取类默认值，不来自 L-3 材料 |

### 4.2 随机源如何被消费

- 构造时 `random.Random(seed)` 成为该实例的唯一随机源。
- 翻牌后胜率估计与（仅混合分支上的）动作采样**共用**这一随机源。
- 实例在多次 `choose_action` 之间会推进该随机源。确定性分支本身可以不抽动作随机数，但翻牌后路径仍会为胜率估计消耗随机数。
- `seed is None` 时，初始化落到 `random.Random` 的默认播种，**不是**预注册整数材料。

### 4.3 与 K2-P-i 的兼容性（条件，不是选定）

| 供给方式 | 与已裁定 K2-P-i 的关系 |
|---|---|
| **逐决策新建实例**，且该次实例的 `seed` 是 `M(κ)` 的固定像 | **可以**在不改 `strategy/` 的前提下对齐 K2-P-i：手内推进被实例边界截断；同 κ 得到同一种子，因而同一次决策上的随机消耗序列相同 |
| **仅每手一个 seed**、手内沿用同一实例 | **不能**满足 `74ai`。这正是 `74k` §7.1 对启发式类的只读冲突，也是 `74l` 手级协议与 K2-P-i 分叉的原因。现行 L-3 v1 的手级 seed 属于这一栏 |
| **为注入 κ 而修改** `HeuristicStrategy` 的随机消费 | 落入已不采用的 K2-P-iii；**不得**作为本候选的授权路线 |

因此：`heuristic@1` **具备**「包外逐决策新实例 + 注册表整数 seed」这一注入面；它**不具备**「手级单次 seed 即等价于逐决策同值」这一性质。若未来 K-1 裁定确认该成员，L-3 材料单元的本轮预期是**每个 κ 一条整数 seed**，映射进注册表 `seed`，而不是把现行 L-3 的 `(campaign, block, hand, seat)` 手级 seed 原样视为 `M(κ)`。`samples` 与 `bluff_freq` 属于实例化口径，不属于这条随机材料本身。

### 6.1 唯一可进入候选：`K1-C-heuristic-1`（`heuristic@1`）

当前 L-2 v1 与 K-1「已冻结单一基线成员」条件之下，**只有**本项可进入本次 K-1 裁定。本文**不选择**它。

| 维度 | 关系 |
|---|---|
| **身份** | 规范标识 `heuristic@1`，即 L-2 v1 §5.2 的基线标识，也是当前默认策略。角色仅限迁移／比较基线，不构成强度上界或质量基准（`74l` §4.2、`74r` L-2 §5.2）。该角色限定**不**等于本提案已经作出 K-1 裁定 |

## 7. 五项关系（只针对 §6.1）

下列关系由 `74k`、`74ai` 与 L-2 v1 的 `heuristic@1` 注入面共同固定。它们**不**延伸到 §6.2。

1. **逐决策新实例**：实例寿命短到单次决策；两臂在同一 κ 上各建各的 `heuristic@1` 实例，但注入同一 `M(κ)`。
2. **κ 材料注入**：材料是 κ 的函数，运行前落盘；臂内推进随机源不得改写已发布的 `M(κ)`。注入参数是该次实例的整数 `seed`。
3. **L-3 材料单元**：类型是逐 κ 的有限域整数，映射到上述 `seed`。键空间须覆盖完整 κ，包括已写死的 `σ_public` 字节。禁止另造一套公开状态编码，也禁止把单元类型改成其他策略的根键或主键。
4. **K-4**：运行器、随机化协议、实例化口径、输入映射进入验证 `code_identity`／执行身份。标识保持 `heuristic@1` **不**豁免这项审查。
5. **参考／评估版本化**：只在 K-4 审查中判断。本提案对「会升版」和「不会升版」都不作陈述。

架构边界同时有效：`verification/` 可配置且不可执行，不推进牌局；配对推进只在包外；`poker/` 不依赖 `api/`、`llm/`；`strategy/` 只经 `GameState` 与 `poker/` 交互。L-2 规定该基线不依赖公开摘要；本轮不得为了换用 §6.2 的策略而把混合运行态引进基线路径。
