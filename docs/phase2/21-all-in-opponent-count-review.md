# 21 训练前置核验：all-in 对手人数与争池资格

> 日期：2026-09-16。代码基线：`843a897934d3419a94195863b92a629c470aaa13`。状态：**已完成只读诊断，并经用户确认实施方案 B；生产策略人数口径和对应测试已更新。**
>
> 本文只处理「全下玩家的行动资格与争池资格不能混用」这一前置核验。它不启动 CFR 训练，不实现风格、位置、DeepSeek 或其他多人估值修复，也不改 UI、`BOT_DELAY`、既有保守复盘保护或真实手牌库。

## 1. 本轮目标、基线与边界

问题是：`HeuristicStrategy` 在翻后估值时把已全下但未弃牌的玩家排除，是否会把「不能继续行动」误判为「不再竞争底池」。

开始时分支为 `master...origin/master`，工作区干净；`HEAD` 为上述提交。诊断前后真实库 `backend/data/holdem.db` 的 SHA-256 均为：

```text
41843936879180ca15dbf00c55200a3e2d4eb55334e7b648f5e340432fe3c4cb
```

诊断阶段没有运行应用、没有调用会推进 Bot 的 `GET /games/{id}`、没有写入 SQLite，也没有改动 `backend/tools/inspect_hand.py`。候选口径先在独立 Python 进程中临时替换策略模块的私有计数函数，用真实 `action_distribution` 对同一快照重新计算；在用户确认后，才将该最小口径修复写入策略源码并补测试。真实手牌库始终未被写入。

长期路线仍保持：运行时对手和教学复盘分目标；2–9 人使用统一契约；位置、公开行动历史、全下人数、多人平局与短码价格是训练前置。本文不把单项人数修复说成完整多人 EV 或 GTO 修复。

## 2. 代码事实与合法最小复现

### 2.1 两种资格已经在引擎中分开

当前规则引擎的行动推进使用「可行动」口径：

- `legal_actions()` 对已弃牌或已全下的当前座位返回空动作集；
- `_first_active_from()`、`_num_can_bet()`、`_betting_round_complete()` 都跳过 `folded` 或 `all_in`；
- 若只剩一名有筹码玩家，引擎仍保留其面对全下下注的跟注/弃牌机会；若无人可行动，则直接发完公共牌并摊牌。

这是正确的**行动资格**定义：

```text
can_act = not folded and not all_in
```

结算采用不同的**争池资格**定义。`_settle_showdown()` 按每座位 `total_committed` 切分层级；每层的 `eligible` 是「对该层有投入且未弃牌」的座位。全下玩家仍在他有投入的主池/边池中竞争，弃牌玩家的已投入筹码是死钱但不具争池资格：

```text
eligible_for_layer = contributed_to_layer and not folded
```

`GameState` 已公开每座位 `folded`、`all_in`、`stack`、`street_bet` 和 `total_committed`，但当前没有决策时可直接消费的逐池资格/边池金额投影。

### 2.2 策略把行动资格错误复用于翻后竞争人数

`backend/app/strategy/heuristic.py::_num_opponents` 当前计数为：除自己外，既未弃牌且未全下的座位。`_postflop_distribution()` 将该数传给 `equity()`。

因此它统计的是「仍可行动的其他座位」，不是「仍会在至少一个底池中与当前座位竞争的座位」。当其他未弃牌对手全部全下时，传入 `0`；`backend/app/poker/equity.py::equity()` 对 `num_opponents <= 0` 直接返回 `1.0`。

`equity(0) == 1.0` 作为泛用函数的「没有竞争者」结果本身不必改变；问题是合法决策点不应把仍有未弃牌全下对手的情况传成 `0`。

复盘层已部分使用争池口径：`hand_review._analyze_decision()` 的展示 `equity`、`call_ev` 和 mistakes 输入按「自己以外、未弃牌」计数，包含全下玩家。但复盘的基线分布仍调用 `HeuristicStrategy.action_distribution()`，所以 `bot_action` / `bot_distribution` 仍受本问题影响。保守收窄和错误检测本身不因基线分布改变而改写其既有赔率、弱踢脚、被压制对子或强听牌判据。

### 2.3 合法最小复现 A：唯一对手已全下，仍须弃/跟

使用 `PokerEngine.start_hand_with()` 产生，不直接伪造快照：

1. 两人桌，按钮兼小盲 seat 0；初始筹码分别为 seat 0 `110`、seat 1 `100`，盲注 `5/10`。
2. 翻前：seat 0 补齐，seat 1 过牌；翻牌 `As Kd 9s`。
3. 翻牌：seat 1 过牌，seat 0 下注剩余 `100` 并全下。

此时 seat 1 是合法决策者：底池 `120`、`to_call=100`，可弃/跟、不可再加注；seat 0 `all_in=True`、未弃牌、总投入 `110`。现行计数为 `0`，未弃牌争池对手数为 `1`。

以固定种子 `17` 独立估值（10,000 样本）时，当前口径为 `1.0000`，包含全下对手为 `0.2023`。对同一合法快照调用真实策略分布：

| 口径 | 分布 |
|---|---|
| 当前：仅可行动对手 | `CALL 100%` |
| 候选：全部未弃牌对手 | `FOLD 100%` |

策略没有读取对手暗牌或未来公共牌；构造中给牌仅用于让引擎能完成合法手牌，策略输入仍是当前公开牌面和自己的底牌。

### 2.4 合法最小复现 B：全下与可行动对手共存

三人桌，seat 0 初始 `110`，seat 1、seat 2 各 `1000`；三人翻前均入池，翻牌 `As Kd 9s` 后 seat 1、seat 2 均过牌，seat 0 下注剩余 `100` 全下。轮到 seat 1：

| 项 | 值 |
|---|---|
| 底池 / 跟注额 | `130 / 100` |
| 合法动作 | 弃牌、跟注、加注 |
| seat 0 | 未弃牌、全下、总投入 `110` |
| seat 2 | 未弃牌、可行动、总投入 `10` |
| 当前人数 / 未弃牌人数 | `1 / 2` |

给 seat 1 `Qh Jc` 后，固定种子 `23`、10,000 样本的随机范围胜率为单个可行动对手 `0.5565`、两个未弃牌对手 `0.3578`；此处跟注赔率约为 `0.4348`。真实策略在相同快照、相同种子下从当前口径的 `CALL 100%` 变为候选口径的 `FOLD 100%`。

这说明「只保留可行动对手」不仅会产生零对手确定胜率，也会在仍有可行动对手时低估主池竞争人数。

### 2.5 合法最小复现 C：弃牌、全下与边池资格并存

四人桌由引擎完整执行：初始筹码 `[100, 100, 30, 100]`，seat 1 下小盲 `5`、seat 2 下大盲 `10`；随后 seat 3 加注全下至 `100`、seat 0 全下跟注、seat 1 弃牌、seat 2 短码跟注。引擎结算前状态为：

```text
投入       [100, 5, 30, 100]
已弃牌     [否, 是, 否, 否]
已全下     [是, 否, 是, 是]
```

结算产生金额 `20`、`75`、`140` 三层。seat 1 的 `5` 是死钱；seat 0、seat 2、seat 3 才是各层的候选争夺者，seat 2 仅参与前两层。此手由 seat 0 获胜只是牌面结果，不改变资格结论。

所以：弃牌者绝不能作为 equity 对手；全下者又不能一概算进当前玩家新投入形成的每个边池。后者是「简单人数修复」的明确边界。

## 4. 修复候选、最小推荐、取舍及涉及层

### 4.1 候选

| 方案 | 内容 | 解决的问题 | 仍未解决 / 代价 |
|---|---|---|---|
| A. 维持现状 | 继续按可行动人数估值 | 无 | 合法全下竞争会得到 `equity=1.0`，并遗漏主池竞争者；不推荐 |
| B. 最小人数修复 | 策略翻后估值人数改为「自己以外未弃牌座位」，全下纳入、弃牌排除 | 修复零对手确定胜率；修复主池中全下与可行动对手共存时的少算 | 仍是对所有底池的单一随机范围胜率；无法计算边池的逐层 EV、短码实际价格或多人平局份额 |
| C. 逐池收益估值 | 从每座位投入、可跟注上限和各层资格构造主池/边池，联合抽样并按各池赢家份额累计收益 | 能表达各层资格、短码和多人平局的实际支付 | 涉及策略输入、估值返回语义、抽样与性能；需要单独设计和确认，不是本轮最小改动 |

### 4.2 已实施的最小范围：方案 B

本轮仅在 `strategy/heuristic.py` 将翻后 MC 的人数语义改为「仍争夺任一底池的未弃牌对手」，并用能表达目的的内部函数名替代原先含混的 `_num_opponents`。未改：

- `poker/equity.py::equity()` 的 `0 -> 1.0` 泛用边界；
- 引擎的行动顺序、合法动作、全下推进、边池结算；
- `hand_review._analyze_decision()` 的独立 equity、`call_ev`、保守收窄和 mistakes 判据；
- 短码跟注金额、多人人平局份额、范围建模或真实底牌隔离。

这只承诺修正「把仍争池的全下对手漏出随机竞争集合」；它不应被表述成完整 EV 修复。存在边池时，已全下座位可能只竞争旧主池，而当前行动者的新增筹码只与仍可行动座位形成边池；简单地将所有未弃牌座位都放进一个 equity 的做法仍可能高估或低估某个动作的真实货币价值。

候选 B 也会使每个受影响节点多抽样一个或数个随机对手，实时开销可能上升。当前没有把旧的性能样本外推为修复后结果；若实施，须按 2–9 人、尤其 6/7/9 人实际复测 `<100ms` 约束。

### 4.3 涉及层与兼容影响

| 层 | 方案 B 的影响 |
|---|---|
| 实盘 `HeuristicStrategy` | 翻后受影响节点的 equity 和动作分布可能变化；翻前不受影响。历史动作不会被改写，之后新牌局会使用新口径。 |
| `equity` | 函数本身不改；调用方不再应在「仍有未弃牌对手」的合法策略节点传入零。 |
| 引擎 / 结算 | 不改。现有行动资格和逐池争池资格已正确分开。 |
| 复盘展示 | 展示的独立 equity、`call_ev` 和 mistakes 口径不变；但参考基线分布、保守收窄后的 `bot_distribution` 与 `bot_action` 可随当前代码重评而变化。 |
| 保守保护与 mistakes | 不删除、不放宽。`bad_call`、`bad_fold`、弱踢脚、被压制对子、limp 豁免、强听牌余量等既有判据不因本项自动重开。 |
| 旧历史 | 原始 `history_json` 不变；动态重评同一历史可能得到新的参考动作，须明确这是评估版本变化，不是恢复原 Bot RNG。 |

### 6.4 版本影响

当前没有单独的评估版本字段；旧历史会以同一 `heuristic-conservative` 标识动态得到新参考分布。该变化是已确认的数值语义修正，不表示能恢复原始 Bot RNG，也没有迁移或改写历史数据。

未在本轮重新测量修复后的 2–9 人决策延迟，因此不以先前性能数据证明新实现仍满足 `<100ms`；后续涉及新策略或 CFR 接入时再按人数实测。

## 7. 遗留与下一小步

1. **边池/短码**：`legal.call_amount` 仍是下注差额，实际 `CALL` 会按余额截断；需要逐池收益模型后才能正确评价所有边池决策。
2. **多人平局份额**：当前 `equity()` 的平局一律折半，不能表达三人及以上平分主池或各边池。
3. **范围而非随机底牌**：方案 B 仍是 vs 随机范围，不能根据下注线反映对手范围；不能读取真实底牌作为替代。
4. **信息集和训练**：位置、公开行动历史、每座位投入及逐池资格仍需在后续通用契约中明确；本轮不开始 trainer 或 CFR。
