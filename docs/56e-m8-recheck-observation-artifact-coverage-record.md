## 3. 缺口与规格出处

- `docs/56a` §4.8 要求：补算须「先核对行为指标（含逐节点行），再逐手核对净筹码（**含观测工件的自洽性**）」；任何差异**立即中止且不写报告**。
- `docs/56d` §9 如实披露：当时实现**只**核对行为指标（含逐节点行）与逐手净筹码，**无法验证观测工件**，并声明「不得在补算通过后声称观测工件已被确定性核对」。
- 该缺口与阶段 A 的「缺登记」同属**实现相对规格不完整**，且同样落在**新增的 opt-in 路径**上。

## 6. F4 的残余边界（必须记账）

1. 工件**缺失**时静默跳过：补算通过**不蕴含**观测工件已被核对；「已核对」成立的前提是**工件存在**。
2. 补算报告**不带**「观测已核对」标记——本轮**未**给 `mixed-recheck.v1` 加字段、**未**改 `note` 文本，以保持既有字段语义与既有落盘工件完全可比。
3. **未**核对观测工件的 `output_bytes` 与文件大小的自洽性；该写入路径的自洽由落盘函数自身保证，**不构成补算结论**。
4. 观测工件的**动作序列、各街底池、牌力档**未逐项比对；F4 覆盖的是手数、顺序、分组键与逐手净筹码。
