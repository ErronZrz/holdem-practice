## 6. 改造机械明细

### 6.1 B2：逐节点行（拟议字段闭集）

每行 = 一个（节点 × 风格 × 手模式 × **种子块**）：

| 字段 | 说明 |
|---|---|
| `node_id` / `category` / `player_count` | 标识与结构 |
| `style` / `hand_mode` / `seed_block` | 风格、内部手模式、种子块 |
| `action_units` | 五类动作的 `units`（`fold` / `check` / `call` / `bet` / `raise`） |
| `scale_units` | **同额合并后**的 `金额 → units`（额度多样性的直接依据） |
| `action_entropy` / `scale_entropy` | 条件熵（口径与既有实现一致） |
| `effective_scale_count` / `structural_single_size` | 有效档位数 / 结构性单档 |
| `has_active_candidate` | 该分布是否存在 `units>0` 的 BET/RAISE 候选 |

**字段闭集（禁止出现）**：底牌、公共牌、牌堆、种子派生细节、座位随机键、任意元数据。

**行数**：`125` 节点 × `3` 风格 × `3` 手模式 × `S` 个种子块（`S` 见 §7.2）。

### 6.2 为什么逐节点行还不够——「种子块」维度必须加（本次新发现的实现层事实）

现有实现的行为矩阵在构造风格策略时**只取清单的第一个种子**（`focus_seat_key(int(manifest.seeds[0]), …)`），即**分布矩阵只是单一种子下的读数**。因此：

- L3 第 5 项「**风格稳定性**：不同 seed 仍体现倾向」在**当前计算方式下结构性不可判定**——即使补上逐节点行，只要仍只算 `seeds[0]`，该项依旧无读数；
- 故 B2 **必须**把「种子块」纳入维度（行为矩阵按每个种子块各算一次）。

**代价**：分布矩阵的计算量按种子数线性增长（`1,125` → `1,125 × S` 行）；据现有实现，单次分布矩阵构建成本很低，但须在 C2 中**实测**，不得预先承诺。

### 6.3 B3：逐手观测工件（拟议字段闭集）

每手、每落子记录：

| 字段 | 说明 |
|---|---|
| `hand_index` / `player_count` / `style` / `opponent` / `arm` / `seed_block` / `rotation` | 与既有逐手行同构的定位字段 |
| `street` / `seat` / `action` / `amount` | 落子序列（可重建整手动作流） |
| `pot_after_street` | 每街结束时的底池 |
| `net_chips` | 焦点座位净筹码（与既有逐手行自洽） |
| `focus_strength_bucket` | **派生标签**：焦点座位自身牌力的分档（**只落标签，不落牌面**） |

**字段闭集（禁止出现）**：任何底牌、公共牌、牌堆内容、对手私有信息。

**由此外部可算**（L4 机制层归因）：负差按街道 / 动作类型 / 下注尺度的分解；极端手（`docs/55h` §5 的 `5.81%`）内部发生了什么。

### 6.4 B4：L5 针对性诊断

按 `docs/55a` §7.8 第 2 项实现「前 20 手 vs 更长样本后的增益对比」，按 **尺度 / 牌力 / 街道** 分桶**分别报告**；牌力使用 §6.3 的**派生标签**。结论边界不变（D3 第 4 条）：只能表述为「本次样本集与本次探针池下未观察到 X」。
