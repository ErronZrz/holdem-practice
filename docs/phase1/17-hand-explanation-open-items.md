| `15` 疑点 | `16` 落地 |

| 参考动作带随机性（固定 seed 下的硬币结果） | 参考动作升级为概率分布，`bot_action` 取收窄后分布的众数 |

本轮（第 2 轮）以同样的逐手核对方式复核新一批真实对局，检验上述口径在**实际牌局**中的表现，并记录新暴露的疑点。

### 解释时使用的当前口径（来自 `16`）

- 参考动作 = 「启发式基线分布」经保守收窄后的**众数**；`DecisionReview.bot_distribution` 给出完整分布（按概率降序，权重和为 1）。
- 基线分布唯一来源是 `HeuristicStrategy.action_distribution`；只有「无人下注 + 胜率 < 0.25」的空气诈唬支是混合分布（`bet = bluff_freq`、`check = 1 - bluff_freq`），其余分支为单一动作（权重 `1.0`）。
- 收窄规则：
  - 翻牌后面对下注 → 赔率无余量或无可继续牌力时，把跟注质量转移到弃牌（小注例外：跟注额 ≤ 底池 1/3）；
  - 翻牌后无人下注 → 弱踢脚顶对把下注质量转移到过牌。
- `_detect_mistakes` 现签名 `(action, equity, pot_odds, to_call, pot, can_raise, hole_cards, board, big_blind)`；`bad_call` 对「翻牌前且跟注额 ≤ 一个大盲」豁免；`value_missed` 与参考价值下注共用弱踢脚门槛。
- 实盘 Bot 行为未变（`choose_action` 只是改为从分布采样）。

**关于玩家 4（Bot）为何「高牌也下注」**

- 翻牌 `equity ≈ 0.58`（vs 2 对手）、转牌 `equity ≈ 0.57`（vs 1 对手）均低于价值阈值；但 `outs = 12` **恰好踩线** → 走**半诈唬**，额度 = 一个底池（60 / 180）。河牌补牌归零、`equity ≈ 0.33 > 0.25` → 三条理由均不成立 → 过牌。
- 结论：Bot 是**用听牌下注的半诈唬**（兼有弃牌权益），不是拿 A 高做价值下注；触发条件是**补牌数**而非胜率。边界提示：`12` 恰好等于阈值，若公共牌红桃少一张（11 补牌）则不会下注。

> 每条疑点沿用 `15 §3` 的结构：**现象** → **机制**（回到代码确认） → **分析**（是否误报 / 漏报 / 口径不自洽） → **候选修正**（含取舍与代价）。
>

### 3.1 参考「弃牌」与「+EV 跟注且无标记」并存（参考与检测不对称）

**现象**：手牌 `6379cb408948464194914ce1fa9cc70c` 决策点 #4（转牌），真人 `2h 2d` 在 `Jh 8h Kh 7c` 面对 180（半池）下注：`equity = 0.4570`、`pot_odds = 0.3333`、`call_ev = +67`、`_has_playable_strength = True`、`draw_outs = 9`；**参考分布 100% 弃牌**，且**未命中任何 mistake**。

**机制**：`_conservative_distribution` 面对下注时只做两件事——`has_margin = eq > pot_odds + _fold_margin(to_call, pot)` 与 `playable = _has_playable_strength(...)`，二者**同时为真**才保留基线跟注，否则把**全部**跟注质量转移到弃牌。本手 `to_call / pot = 0.5` → `margin = 0.15 + 0.10 × 0.5 = 0.20` → 阈值 `0.5333`；`0.4570 < 0.5333`，故即使 `playable` 为真也被整体转为弃牌。而 `_detect_mistakes` 侧判 `bad_call` 只用 `equity < pot_odds - 0.03`，`0.4570` 远高于该线，故无标记。

**分析**：这是 `13` 刻意设计的保守取向（`equity` 为「vs 随机」，对下注范围系统性乐观），但出现了三方张力：**参考弃牌 + 实际 `call_ev` 为正 + 无错误标记**。对用户而言「参考：弃牌」会被读作「你打错了」，而系统并不标错，同一决策点的两个输出方向相反。属**参考与检测不对称**（`13 §6` / `16 §5` 已记录过同类形态，但均发生在翻牌前）。注意：`margin` 随 `to_call / pot` 线性放大，在「强听牌 + 半池」这一常见组合下阈值被推到 0.53，是本手触发点。

**候选修正**（含取舍）：

| 方案 | 内容 | 取舍 / 代价 |
|---|---|---|
| a | 参考侧对「强听牌（`draw_outs ≥ _STRONG_DRAW_OUTS`）」降低或豁免 `margin` | 会部分回退 `13` 的收紧取向；需重跑批量计数确认「参考=跟注」面不反弹 |
| b | 让 `bad_fold` 与参考共用同一「余量」阈值（参考弃牌 ⇒ 检测也认为该弃） | 会把 `bad_fold` 判定面收窄（更多该跟却弃不再标 warning），改动面最大 |
| c | 维持现状，仅在前端/文档说明「参考偏紧、以 `call_ev` 为准」 | 零风险，但「参考」与「标记」两套口径长期并存，用户仍需自行分辨 |

### 3.2 `bad_call` 对「有可继续牌力」的跟注仍判 error（跟注侧缺牌力门槛）

**现象**：同一手决策点 #2（翻牌），真人 `2h 2d` 在 `Jh 8h Kh` 面对底池下注 60：`equity = 0.2880`、`pot_odds = 0.3333`、`call_ev = -8`、`draw_outs = 9`、`_has_playable_strength = True`，命中 `bad_call`（error）。

**机制**：`bad_call` 判据为 `action == CALL and equity < pot_odds - _BAD_CALL_EQ_MARGIN`，**完全不看牌力 / 听牌**。而同一决策点的保守参考会先算 `playable = True`（9 补牌强听牌），再因 `has_margin = False` 转弃牌——即「牌力可继续」为真、「跟注赔率不足」也为真，两个判据同时输出。

**分析**：`13 §6` 已把 `bad_call 未同步（跟注侧仍只有 0.03 容差）` 列为遗留，本手是该遗留的**具体实例**。是否算误报需分情况：本手 `call_ev = -8`，判据与自身 metric 自洽，且真人 9 张补牌成的是 `2h` 带队的**小同花**（对手 `Ah/Qh/Th/9h` 任意高红桃听牌都有 RIO），因此本处**不宜简单判为误报**。真正的口径问题在于：`bad_call` 无法区分「高张/弱听牌硬跟」与「干净强听牌跟注」，后者在胜率略低于赔率时同样会被标 error，与 `bad_fold` / 保守参考的「牌力门槛」形成不对称。

**候选修正**（含取舍）：

| 方案 | 内容 | 取舍 / 代价 |
|---|---|---|
| a | `bad_call` 在 `playable` 为真（真实成手牌或 `draw_outs ≥ 8`）时放宽容差或豁免 | 与 `bad_fold` 的牌力门槛对称；但会漏报「弱同花听牌（RIO 高）硬跟」的 error，需专门用例 |
| b | 保持 `bad_call` 不变，仅在工具输出中并列展示 `playable`，由用户自行判断 | 零风险；`13 §6` 的遗留继续挂着 |
| c | 引入「听牌质量」区分（如是否坚果听牌 / 是否可能被压制）再决定是否豁免 | 最贴近真实牌理；但会引入新的判据维度，超出「不引范围建模」的当前边界 |

### 3.3 工具展示：翻牌前也打印「赔率余量」判据，但翻前不参与收窄

**现象**：`inspect_hand.py` 对决策点 #0（翻牌前）也打印 `判据·赔率余量：equity(0.2915) > pot_odds(0.1667) + margin(0.1700) = 0.3367 -> False`，以及 `小注例外=True`。

**机制**：`_print_decisions` 只要 `pot_odds is not None`（即 `to_call > 0`）就打印余量行；而 `_conservative_distribution` 第一句即 `if snapshot.street == Street.PREFLOP: return baseline`——翻牌前的 `margin` / 小注例外**根本不参与**参考分布计算。

**分析**：属**工具展示误导**，非引擎口径问题。逐手核对时容易把翻前那一行 `-> False` 误读为「该弃未弃」。

**候选修正**：翻牌前把该行改为「翻牌前不适用（收窄不介入）」，或只在翻牌后打印。代价：几乎为零，但需同步工具的输出说明。

### 3.4 下注额度固定为一个底池（坚果牌也无法超池）

**现象**：手牌 `a23deff5c8fd446495473df701f6f8e7` 河牌，真人 `Th Ac` 在 `Kd 3s 9s Js Qd` 上成 Broadway（`equity = 0.8950`，vs 2 对手），**参考动作 `bet 60`——恰好等于底池 60**。用户疑问：顺子成牌后超池下注也合理，为何参考只用一池。

**机制**：`_bet_amount` 的实现是 `min(legal.max_bet, max(legal.min_bet, state.pot))`，即目标额度**恒为「当前底池」**，只做合法区间夹取。价值下注、半诈唬、空气诈唬**共用同一函数**，因此额度不随牌力、牌面、街道、对手数变化；`bot_distribution` 里的 `amount` 也取自该函数，分布本身**没有额度维度**。河牌底池 60、`min_bet` 20、`max_bet` 远超 60 → 取 60。

**分析**：一池下注是启发式的固定档，实现简单且稳健；但它把「下注与否」与「下多少」解耦不彻底——坚果牌与边缘薄价值牌用同一个池量。`13` / `16` 的保守口径只收窄「是否下注」（跟注质量转移、弱踢脚顶对转过牌），**未触及额度**，因此本处不是误报，而是**口径能力缺失**：用户提出的「顺子超池」在当前实现里无法表达。另需注意复盘自身并不惩罚「只用一池」——`underbet` 仅在 `bet < pot / 2` 且 `equity ≥ 0.80` 时给 info 提示，`value_missed` 只看是否过牌，所以系统内部对额度的一致性判据是「不低于半池」。

**候选修正**（含取舍）：

| 方案 | 内容 | 取舍 / 代价 |
|---|---|---|
| a | 按牌力分档设额度（如成顺/成花或 `equity ≥ 0.90` 时 1.5 池） | 需定义档位与夹取规则；**实盘 Bot 行为会变**，与「实盘未变」的既有取舍冲突，需新增用例 + 批量计数 |
| b | 只在复盘层对强成牌提高参考额度 | 实盘不变，但「参考 ≠ 实盘」的差距再扩大一档；`underbet` 阈值需同步，否则出现「参考建议超池、检测只要求半池」 |
| c | 保持一池，文档/前端说明「额度为固定档，不代表最优 sizing」 | 零风险；但用户看到「参考：bet 60」仍会误以为这是最优额度 |

### 3.5 `bad_fold` 对「被公共牌高张压制的成手牌」误报

**现象**：手牌 `92713201d1a04c01940e009e2d14874d` 决策点 #2（翻牌），真人 `Jc Js` 在 `9d Kd 2h` 面对 **满池 120**（底池 240、`pot_odds 0.3333`）弃牌：`equity = 0.5510`（vs 2 随机）、`_is_made_hand = True`（口袋对）、`draw_outs = 0`、`_has_playable_strength = True`、`call_ev = +78`，命中 `bad_fold`（warning）。真人给出的理由是「对手有 K 的概率很大」。

**机制**：`bad_fold` 判据为 `equity > pot_odds + _fold_margin(to_call, pot)`，且翻牌后还要求 `_has_playable_strength`。本手 `margin = 0.15 + 0.10 × (120 / 240) = 0.20` → 阈值 `0.5333`；`0.5510` **仅高出 0.0177** 即命中。而 `_has_playable_strength` 对口袋对（`ranks[0] == ranks[1]`）无条件返回 `True`——它只问「底牌是否参与成牌」，**不问这张成手牌是否被公共牌压制**。

**分析**：属**误报（判据过宽）**，根因仍是 `equity` 的「vs 随机」口径（`10 §4`、`15 §3.3` 已记录），本手是该口径**最极端的一次暴露**。实测（本轮离线计算，公共牌 `9d Kd 2h`、JJ）：

| 对照 | JJ 胜率 |
|---|---|
| 复盘口径（vs 2 随机） | **0.5510** |
| vs `As Kh` + 1 随机（本手实际对手） | **0.0911** |
| vs `Kc Qs` + 1 随机 | 0.0823 |
| vs `9c 9h` + 1 随机 | 0.0914 |
| vs `Qd Jd`（对子+同花听牌）+ 1 随机 | 0.3482 |
| vs `8d 7d`（同花听牌）+ 1 随机 | 0.4654 |
| 构造的「跟注翻前 + 满池下注」范围（14 手，单挑） | 平均 **0.318** |

即：**面对下注时，vs 随机高估约 20~45 个百分点**，而 `margin`（`+0.20`）只补偿了其中一小部分。本手真人的弃牌在范围口径下明显正确（对 `Kx`/三条只有 ~10%），复盘却因踩线 0.0177 判 `bad_fold`。注意这**不是内部自相矛盾**——参考动作与 `bad_fold` 共用同一 `margin`，两者同时给出「跟注」；问题在于该门槛对「有牌力但被高张压制」的牌整体偏松。

**候选修正**（含取舍）：

| 方案 | 内容 | 取舍 / 代价 |
|---|---|---|
| a | 新增「公共牌压制」牌力门槛：成手牌为**一对且该对低于公共牌最高点数**（含低于公共牌高张的口袋对）时，面对下注不保留参考跟注、也不判 `bad_fold` | 与 `_weak_kicker_top_pair` 对称（那边管顶对弱踢脚，这边管被高张压制的对子），且**参考与检测共用**，符合 `16 §4.2` 的自洽原则；代价：会漏掉「对手在诈唬、JJ 其实是最好牌」的漏报，需用例覆盖「同花面/连张面」等例外 |
| b | 提高 `margin` 的注额系数（`0.10`）或加一个下限 | 改动最小；但会**无差别**收紧所有牌力（含强听牌、成手牌），把 `13` 已验证的「A 组顶对保留跟注」面也一起压掉 |
| c | 维持现状，在工具/前端标注「`equity` 为 vs 随机，面对下注偏乐观」 | 零风险；但用户的实际读牌与复盘结论长期相反时，复盘的教练价值被削弱 |

**数据校验**：本地 243 手可重放样本中 `bad_fold` 仅 2 处（另一处为翻前 `Kc 9d`，同属 vs 随机口径），详见 §3.7。方案 (a) 的改动面因此**很小且可控**。

### 3.6 工具展示：翻牌前的「参考依据」文案按胜率口径生成（实际走 Chen 分档）

**现象**：手牌 `92713201d1a04c01940e009e2d14874d` 决策点 #0（翻前，`JJ`）打印 `参考依据：胜率≥0.90，加注`，但该点 `equity = 0.6040`，与文案自相矛盾。

**机制**：`_bot_rationale` 只按 `pot_odds is not None`（即「面对下注」）分支，对 `RAISE` 直接返回 `胜率≥{_RAISE_EQ:.2f}，加注`。而**翻牌前的动作来自 `_preflop_action` 的 Chen 分档**（`JJ` 得分 12 ≥ `_STRONG_CHEN` → 激进档加注），与 `_RAISE_EQ` / `_AIR_EQ` 无关。同理翻前的「跟注 / 弃牌」文案（`胜率≥0.25 且不低于底池赔率`）也是胜率口径，与 Chen 分档无关。

**分析**：属**工具展示误导**，与 §3.3 同源（翻前分支被翻牌后的文案模板套用）。逐手核对翻前决策点时，依据文案会给出错误的因果解释。

**候选修正**：`_bot_rationale` 增加街道判断，翻牌前改为说明 Chen 分档结果（如「Chen 分档：强牌（12 分）→ 加注」）；代价：需把分档逻辑在工具侧复述或从策略层暴露分档结果，注意**不得在分析层重复实现判据**（`11 §3.1` 的「复用规则、杜绝漂移」）。

1. 口袋对一律算「真实成手牌」，不问是否被公共牌压制；
2. 公共牌三条被算作「底牌参与成牌」（其实双方共享）；
3. 小注例外（`to_call × 3 ≤ pot`）直接返回 `True`，使多数小额跟注天然「可继续」。

因此 **§3.2 候选修正 (a)（`playable` 时豁免 / 放宽 `bad_call`）会掩盖真报，不建议按原样实施**。若仍要动跟注侧，须先收紧 `_has_playable_strength` 本身（与 §3.5 的「公共牌压制」门槛同向），再谈是否豁免。

## 4. 修复优先级建议与状态

> 排序依据：**教练结论的正确性 > 工具可读性 > 能力扩展**；并考虑「`equity` 为 vs 随机」这一共同病根下各条目的相互牵制。

| 条目 | 状态 |
|---|---|
| §3.3 + §3.6 工具展示 | **已修复**（§5.1） |
| §3.1 + §3.5 跟注侧门槛分层 | **已修复**（§5.2） |
| §3.2 `bad_call` 门槛 | 挂起（数据反对；待 §5.2 落地后按新数据复评） |
| §3.4 超池额度 | 挂起（需求未确认，且会触及实盘 Bot 行为） |

以下 4.1 ~ 4.4 保留为当时的决策依据。

### 4.1 建议修：§3.3 + §3.6（工具展示，零风险）

- 二者都是**纯展示问题**，不改任何判据、不动实盘、不影响既有测试语义。
- 收益直接：本轮工作模式（逐手解释）完全依赖工具输出的判据文案，§3.6 的错误文案会给出**错误的因果解释**（本轮已实际误导一次）。
- 最小实现：翻前不套用胜率文案（改为「翻牌前按 Chen 分档，不适用胜率口径」），翻前不打印「赔率余量」判据行。**无需新增策略层 API**。

### 4.2 建议合并修：§3.1 + §3.5（跟注侧「赔率余量 + 牌力质量」的牌力分层）

- 二者**同源但方向相反**，必须一起设计，否则按下葫芦浮起瓢：
  - §3.1：强听牌（9 补牌）`equity 0.4570`、`call_ev +67`，参考却弃牌 → `margin` **过大**；
  - §3.5：被公共牌高张压制的口袋对 `equity 0.5510`（实际 ~0.09），参考却跟注且判 `bad_fold` → `margin` **过小**。
- 可行的落点（两处都作用在既有的 `has_margin and playable` 上，不引范围建模）：
  - 质量侧：`_has_playable_strength` 排除「一对且该对低于公共牌最高点数」（与 `_weak_kicker_top_pair` 对称）→ 直接修掉 §3.5 的误报，且参考与检测**共用**该门槛；
  - 余量侧：对「强听牌（`draw_outs ≥ _STRONG_DRAW_OUTS`）」降低或豁免 `margin` → 修掉 §3.1 的「参考弃牌 vs +EV 跟注」。
- 代价：会同时改变参考动作与 `bad_fold` 判定面，**必须**跑批量前后计数（沿用 `16 §7` 的形式）并补 pytest；`13` 已验证的「顶对保留跟注」面需回归确认不反弹。

### 4.3 建议暂不修：§3.2（`bad_call` 门槛）

- 数据反对（§3.7）：豁免 `playable` 会掩盖 7/9 的命中，含 2 处 `equity 9.55%` 的真报。
- 真正要做的是**先收紧 `_has_playable_strength`**（见 4.2），这本身就会连带影响跟注侧口径；`bad_call` 是否随之放宽，应在 4.2 落地后按新数据再评估。

### 4.4 建议挂起：§3.4（超池额度）

- 需求未确认（本轮只是提出「超池也合理」），且改动会触及**实盘 Bot 行为**，与 `13` 起确立的「实盘不变、只动复盘」取舍冲突。
- 若要推进，建议先做**只读评估**：统计多少决策点因「固定一池」而明显欠额，再决定是否只改复盘层。
