## 1. 牌桌操作只能鼠标点击，缺少键盘快捷键

### 1.1 现象

牌桌页（`frontend/src/components/GameTable.vue`）轮到真人行动时，只能通过鼠标点击按钮（弃牌 / 过牌 / 跟注 / 下注 / 加注）完成操作；连续多手练习时操作效率低，且下注/加注需「点按钮 → 点输入框 → 输入 → 点确认」多步鼠标动作。

期望：轮到真人时支持键盘快捷键。

| 键 | 期望行为 |
|---|---|
| `C` | call / check |
| `B` | bet / raise，按下后进入等待输入金额的状态 |
| `Enter` | 金额输入后回车发送 bet / raise |
| `B`（金额态再按） | 自动填充底池金额到输入框，仍需回车发送 |
| `F` | fold |

### 1.2 机制（回到代码确认）

- 全量检索 `frontend/src` 内的 `keydown` / `keyup` / `keypress` / `addEventListener` / `autofocus` / `onKey`，**零命中**：前端当前没有任何键盘事件处理，交互全部由按钮 `@click` 承担。
- 动作入口为 `GameTable.vue` 的 `act(action, amount)`，并以 `busy` 做防重入。
- 下注/加注流程：`openBet()` / `openRaise()` 设置 `pendingAction` 与初始金额 → `setPot()` 填底池（已对 `min/max` 做夹取）→ `confirmAmount()` 发送 → `cancelAmount()` 取消。
- 可用动作由 `legal`（后端下发的 `legal_actions`）与 `game.is_human_turn` 决定，前端不自行判断规则合法性。
- `App.vue` 用 `<KeepAlive>` 包裹牌桌组件：切到「历史 / 统计」页时组件**仍处于挂载状态**，若把键盘监听挂在 `window` 上而不随页签启停，会在其它页面误触发牌桌动作。

### 1.3 分析

- 属**纯前端交互能力缺失**，与牌局正确性、策略与复盘判据无关；不涉及后端。
- 唯一需要小心的是**监听生命周期**：`KeepAlive` 缓存下必须随 `activated` / `deactivated` 启停监听，否则历史/统计页的按键会穿透到牌桌；同时组件卸载需解绑，避免重复绑定与泄漏。
- 另一处需要明确的是**焦点归属**：金额输入框内应允许快捷键（否则无法「按 B 填底池」），而创建表单等其它输入控件内必须屏蔽快捷键，避免打字时误触发。

### 1.4 候选修正（含取舍与代价）

| 方案 | 内容 | 取舍 / 代价 |
|---|---|---|
| a | `window` 级 `keydown` + 金额面板态区分 + 按钮字母提示（**本轮采用**） | 纯前端、无既有行为改动；代价是要正确处理 `KeepAlive` 下的监听启停与输入框焦点判定 |
| b | 只在牌桌容器上监听（`tabindex` + 手动聚焦） | 需容器可聚焦并持续维持焦点，焦点易被按钮/输入框夺走，行为不稳定 |
| c | 不做快捷键，仅优化鼠标操作（大按钮、快捷下注） | 零风险，但不满足需求 |

确认口径（与用户逐项确认后锁定）：

1. **金额面板打开时**：只响应 `B`（填底池）/ `M`（最小值）/ `A`（全下）/ `Enter`（发送）/ `Esc`（取消）；`C` / `F` 一律忽略（避免误弃牌）。
2. **焦点**：金额输入框内快捷键生效；创建表单等其它输入控件内一律不触发。
3. **按钮提示**：在动作按钮上标注快捷键字母，沿用现有按钮样式。
4. **无效金额**：拒绝发送，并在金额面板内与顶部横幅同时提示原因，面板保持打开。

## 2. 动作条位置随「本手动作」记录不断下移

### 2.1 现象

牌桌页的纵向版块顺序为：牌桌信息 → 牌桌 → **本手动作（记录）** → 本手复盘 → **动作条（按钮）**。由于「本手动作」在本手进行中会随每次动作不断追加内容、高度持续增长，而动作条排在它**下方**，导致**每次轮到玩家时按钮都被往下推**，需要重新定位鼠标。

期望：把「本手动作」记录放到动作条**下方**，使按钮位置在本手内保持稳定。

### 2.2 机制（回到代码确认）

`GameTable.vue` 模板中三块的先后顺序（改动前）：

```
panel.hand-actions   ← 本手动作记录，数据源 handActionGroups，随动作累积增长
panel.review-panel   ← 本手复盘（v-if="game.hand_over && showReview"）
controls.panel       ← 动作条：动作按钮 / 金额面板 / 结果与「下一手」
```

而动作条上方的两块高度是**稳定**的：

- `.table-meta` 为单行文本；
- `.felt` 有固定 `min-height: 460px`，且座位用绝对定位（`seatStyle`）渲染，不随动作数变化。

即：按钮被下推的唯一来源就是排在其上方的「本手动作」面板，属**纯 DOM 顺序问题**。

### 2.3 分析

- 与牌局正确性、策略、复盘判据无关；纯前端版块顺序问题，不涉及后端与接口。
- 修法是**整块移动动作条**（`controls.panel`）到「本手动作」之前，即顺序调整为：牌桌信息 → 牌桌 → 动作条 → 本手动作 → 本手复盘。
- 由于 `table-meta` / `felt` 高度稳定，移动后按钮位置在本手内固定，不再随记录增长而下移。
- 本手结束时动作条内含「结果 + 下一手」，按确认口径顺序为 **按钮 → 记录 → 复盘**。

### 2.4 候选修正（含取舍与代价）

| 方案 | 内容 | 取舍 / 代价 |
|---|---|---|
| a | 把 `controls.panel` 整块上移到 `hand-actions` 之前（**本轮采用**） | 纯 DOM 顺序调整，无逻辑/接口/状态变更；代价为零，但记录仍会向下增长（不影响按钮位置） |
| b | 动作条改 `position: sticky; bottom: 0` 常驻视口底部 | 滚动时按钮始终可见，体验更彻底；但需处理粘性定位的层叠、背景与圆角，改动面更大，可能与现有视觉风格不一致 |
| c | 「本手动作」面板改为固定高度 + 内部滚动 | 按钮位置稳定，但小屏下可读性变差，且引入滚动容器 |

本轮取 a：满足「记录在按钮下方」的诉求且零风险；若后续仍需滚动时按钮可见，再单独评估 b。

## 3. 有限手数 + 无参数持久化：刷新页面后回到首页

### 3.1 现象

浏览器标签页休眠（被浏览器丢弃后重载）或手动刷新时，牌桌页会回到「开始新对局」表单，进行中的对局无法继续；「目标手数 20」还会在打到一半时把对局判为结束，进一步放大该问题。

期望：

- 首次进入设置 **玩家人数 / 大盲（偶数，小盲自动为大盲的一半）/ 初始筹码**，设置后持久保存；
- 之后刷新页面**直接回到牌桌**，不回到首页；
- 取消「目标手数」，可无限继续；
- 取消 Bot 策略选择（当前只使用一套策略）；
- 游戏页仍可「退出对局」回到首页重新设置。

### 3.2 机制（回到代码确认）

- 前端 `game` / `sessionId` 仅存在于 `GameTable.vue` 的 `ref`，**无任何持久化**（全量检索 `frontend/src`，`localStorage` / `sessionStorage` 零命中）；`App.vue` 的 `<KeepAlive>` 只保证切换页签不丢，覆盖不了「页面重载」。
- 后端 `_finalize_hand()` 在 `hands_played >= target_hands` 时把 `session.status` 置 `finished`；`next_hand()` 对 `finished` 直接返回 400。
- 进行中的对局仅驻留进程内存（`docs/14`），所以即便前端记住了 `session_id`，也必须处理「后端已丢失该局」的情况。
- `SessionModel.target_hands` / `bot_strategy` 是**非空列**，且 `storage/db.py` 只用 `Base.metadata.create_all`（无迁移工具）——**给已有库加列不会生效**，只能复用既有列表达新语义。

### 3.3 分析

- 属**平台层可用性问题**：一次页面重载即丢失全部进行中状态，且「目标手数」把练习硬切成若干段。
- 关键约束是**数据库兼容**：必须在不改表结构、不改旧行语义的前提下表达「不限手数」。
- 「刷新后直接回到牌桌」有两种取向：恢复进行中的这一手（不丢进度），或每次都新开一手（实现更简单）。已与用户确认取前者。

### 3.4 候选修正（含取舍与代价）

「刷新后回到牌桌」的实现方式：

| 方案 | 内容 | 取舍 / 代价 |
|---|---|---|
| a | 前端 `localStorage` 保存设置参数 + 对局标识；刷新时优先 `GET /games/{id}` 恢复，404 时按参数新建（**本轮采用**） | 仅前端持久化、零后端存储改动；局限是同浏览器/设备有效 |
| b | 后端新增「最近一次设置」存储与接口 | 换浏览器/设备也生效；但需新增表/接口与用例，改动更大 |
| c | 后端把进行中对局整体落库以便恢复 | 能真正续玩任意对局；但需引擎快照序列化，与「只存已完成手牌」的既有取舍冲突，成本最高 |

「不限手数」的落地方式（复用既有列）：

| 方案 | 内容 | 取舍 / 代价 |
|---|---|---|
| a | 复用 `target_hands`，**0 表示不限手数**；入参省略（`None`）时落库 0（**本轮采用**） | 不改表结构、旧行（`target_hands = 20/50`）语义不变；代价是「0 = 不限」需在代码与文档中说明 |
| b | 新增 `unlimited` 列 | 语义最清晰；但 `create_all` 不会给已有库加列，需要迁移，成本高 |

### 3.5 确认口径（与用户逐项确认后锁定）

1. **刷新**：优先恢复进行中的对局（同一 `session_id`、同一手继续）；仅当后端内存已丢（404）时才按保存的参数新建一局。
2. **持久化位置**：仅前端 `localStorage`（同浏览器/设备有效）。
3. **退出对局**：只清空本地保存的参数与对局标识；数据库里那一局**保持 `active` 不动**（不新增接口）。
4. **退出后表单**：预填上一次用过的参数，便于直接重开。

## 4. 修复落地（实现快照）

### 4.1 改动文件

| 文件 | 改动 |
|---|---|
| `frontend/src/components/GameTable.vue` | ① 键盘快捷键、金额校验、金额框自动聚焦、按钮快捷键提示与相关样式；② 把动作条移到「本手动作」之前；③ 设置表单改为人数/大盲/初始筹码，`localStorage` 持久化与刷新恢复 |
| `frontend/src/components/HistoryView.vue` / `StatsView.vue` | 不限手数（`target_hands = 0`）时只显示已打手数 |
| `frontend/src/api.js` | 请求失败时在错误对象上附带 HTTP 状态码，供恢复逻辑区分 404 |
| `backend/app/api/schemas.py` | 创建请求改为「大盲必填偶数 + 小盲推导」，`small_blind` / `target_hands` / `bot_strategy` 降级为兼容字段 |
| `backend/app/api/games.py` | 校验大盲偶数并推导小盲；`target_hands = 0` 时对局不自动结束 |
| `backend/app/storage/repository.py` / `models.py` | `target_hands` 支持 `None`（落库 0），并标注「0 表示不限手数」 |
| `backend/tests/test_games_api.py` | 新增大盲偶数校验、小盲推导、不限手数对局三组用例 |

`poker/` / `strategy/` / `analysis/` **未改动**。

### 4.2 键盘语义（对应 §1）

**无金额面板时**（需 `game && !hand_over && is_human_turn && !busy`）：

| 键 | 行为 |
|---|---|
| `F` | `can_fold` → 弃牌 |
| `C` | `can_check` → 过牌；否则 `can_call` → 跟注 |
| `B` | `can_bet` → 打开下注面板；否则 `can_raise` → 打开加注面板 |

**金额面板打开时**：

| 键 | 行为 |
|---|---|
| `Enter` | 校验金额后发送 |
| `Escape` | 取消（等同「取消」按钮） |
| `B` | 填充底池金额（复用 `setPot()`，仍夹取合法区间） |
| `M` | 填充最小金额（复用 `setMin()`） |
| `A` | 填充全下金额（复用 `setMax()`） |
| 其它 | 忽略 |

**本手已结束时**（需 `game.hand_over && !session_finished && !busy`）：

| 键 | 行为 |
|---|---|
| `空格` | 开始下一手（等同「下一手」按钮） |

焦点落在按钮上时不做拦截，交给浏览器原生激活（Tab 到「下一手」后按空格同样生效）；本局已结束时（仅剩「再开一局 / 查看统计 / 查看历史」）空格不接管。

其它约束：

- 忽略带 `Ctrl` / `Meta` / `Alt` 的组合键。
- 金额输入框内允许上述按键；其它可编辑元素（`INPUT` / `TEXTAREA` / `SELECT` / `contenteditable`）内一律不响应。

### 4.3 金额校验（对应 §1）

`confirmAmount()` 发送前先做客户端校验，仅接受**合法区间内的整数**：

- 非整数（含空值）：`请输入整数下注额` / `请输入整数加注额`；
- 小于最小值：`下注额不能小于最小值 {min}`（加注同理）；
- 大于最大值：`下注额不能大于最大值 {max}`（加注同理）。

校验失败时**不发送**，在金额面板内与顶部 `error-banner` 同时展示原因，面板保持打开；用户修改金额后提示自动清除。区间取自既有 `amountMin` / `amountMax`（即后端下发的 `min_bet`/`max_bet` 或 `min_raise_to`/`max_raise_to`）。

### 4.4 监听生命周期（对应 §1）

- `onMounted` / `onActivated` 注册 `window` 的 `keydown`；`onDeactivated` / `onUnmounted` 解绑（同一函数引用，重复注册会被浏览器去重）。
- 这样在 `KeepAlive` 缓存下，切到「历史 / 统计」页时键盘监听被摘除，不会误触发牌桌动作。

### 4.5 版块顺序（对应 §2）

改动后模板顺序：

```
table-meta → felt → controls.panel（动作条）→ panel.hand-actions（本手动作）→ panel.review-panel（本手复盘）
```

- 动作条上方的两块（`table-meta` 单行、`felt` 固定 `min-height` + 座位绝对定位）高度稳定，因此按钮位置在本手内固定。
- 本手结束时同样为「按钮（结果 + 下一手）→ 记录 → 复盘」。
- 无 `script` 逻辑改动、无接口与状态变更。

### 4.6 交互细节（对应 §1）

- 金额面板打开后自动聚焦输入框并全选，便于直接键入金额。
- 动作按钮文案追加 `<kbd>` 字母提示（弃牌 `F` / 过牌 `C` / 跟注 `C` / 下注 `B` / 加注 `B`）；金额面板内「最小 `M`」「底池 `B`」「全下 `A`」「确认 `Enter`」「取消 `Esc`」与结果区的「下一手 `空格`」同样标注。
- 焦点在「确认」按钮上按 `Enter` 时，`preventDefault()` 会阻止按钮自身的默认激活，因此不会重复发送。

### 4.7 无限对局与参数持久化（对应 §3）

**后端**

- `CreateGameRequest`：`big_blind`（默认 10）是唯一盲注入参；`small_blind` / `target_hands` / `bot_strategy` 保留为兼容字段（界面不再发送）。
- `POST /games` 校验：大盲必须为偶数，否则 400「大盲必须是偶数」；`small_blind` 显式传入时必须等于 `big_blind // 2`，否则 400「小盲必须等于大盲的一半」。
- `target_hands` 省略（`None`）→ 落库 `0`；`_finalize_hand()` 仅在 `target_hands > 0` 且打满时才把对局置 `finished`。
- **表结构不变**：旧对局行（`target_hands = 20/50`，`status = finished/active`）的语义与展示完全不受影响。

**前端**

| 点 | 实现 |
|---|---|
| 设置表单 | 仅 玩家人数（2 / 5 / 自定义）/ 大盲（偶数）/ 初始筹码；小盲以只读预览展示「大盲的一半」；移除「目标手数」「Bot 策略」 |
| 持久化 | 创建成功后写入 `localStorage`：`holdem.table.config`（设置参数）、`holdem.table.session`（对局标识） |
| 首次进入 | `onMounted` → `restoreOrCreate()`：有保存参数则先 `GET /games/{id}` 恢复；404 时按参数新建；其它错误留在设置页并提示 |
| 恢复中 | 有保存参数时先显示「正在恢复对局…」，避免闪一下设置表单 |
| 退出对局 | 清空两个 key 并回到设置表单（表单保留上次参数） |
| 再开一局 | 只清 `holdem.table.session`，保留设置参数 |
| 手数展示 | `target_hands > 0` 显示「第 N / M 手」，否则「第 N 手」；历史 / 统计页同理 |

**兼容性**

- 不新增、不删除数据库列，旧对局行原样可读；`docs/06` §2.1 的模型描述仍然成立，仅新增「0 = 不限手数」这一取值约定。
- 旧 API 调用方（传 `small_blind` / `target_hands` / `bot_strategy`）行为不变，既有用例全部保持通过。
